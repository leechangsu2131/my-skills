# 개인정보·비밀값 체크리스트 (작업자용, 1쪽)

> 커밋하기 **전에** 위에서부터 훑어보세요. 저장소는 **공개**라서, 한 번 올라가면 몇 분 안에 자동 수집 봇이 가져갑니다.
> 규칙의 원본: [WORKER_GUIDE.md](WORKER_GUIDE.md) §3 (교사 결정 2026-11-25). 사고 기록: [SECURITY_LESSONS_LEARNED.md](SECURITY_LESSONS_LEARNED.md).

## 1. 올리기 전 30초 점검 — 하나라도 "예"면 멈추기

- [ ] **학생·학부모 정보**가 있나? (이름·학번·평가 글·사진·녹음·보호자 연락처) → `학생A` 처럼 바꾸기. 진짜 기록은 `data_dir()`(교사 PC 의 `내 문서\my-skills-data`)에만.
- [ ] **전화번호·집 주소**가 있나? (누구 것이든) → `000-0000` 으로.
- [ ] **비밀값**이 있나? (API 키·토큰·비밀번호·웹후크 주소·로그인 쿠키) → 지우고, 코드는 `skills/_shared/skill_env.py` 로 읽기.
- [ ] **저작물**이 있나? (지도서·교과서 PDF 등) → 올리지 않기.
- [ ] **바깥에 실제로 영향**을 주는 실행을 했나? (NEIS·에듀파인 제출, 문자 발송, 결제·구매, 삭제) → 작업자는 하지 않음. 교사 PC 에서 교사 확인 뒤에만.

## 2. 만드는 순간 조심할 파일

과거 사고에서 실제로 올라갔던 종류입니다(근거: SECURITY_LESSONS_LEARNED §2·§5).

- 브라우저 프로필·로그인 세션: `chrome_profile`, `playwright_profile`, `*_storage_state.json` → 폴더를 만들기 전에 `.gitignore` 부터 확인. 쿠키가 있으면 비밀번호 없이도 로그인됩니다.
- 화면 자동화 디버깅 결과: `*.html` 덤프, `*.png`, `*.log` → 숨은 입력칸·토큰·개인정보가 그대로 들어 있습니다.
- 결과물: `result/`, `output/`, `data/` 의 엑셀·CSV·PDF → 학생 기록이 섞이기 쉽습니다.
- `.env` → 올리지 않기. `.env.example` 에는 `YOUR_API_KEY_HERE` 같은 **눈에 띄는 가짜 값**만.
- 코드 기본값(fallback)에 진짜 값 넣지 않기: 나쁜 예 `os.getenv("PW", "진짜")`, 좋은 예 `os.getenv("PW", "")` 후 비었으면 오류로 멈추기.

## 3. 커밋 직전 순서

1. `git status` — 내가 고친 파일만 있나? 자동으로 생긴 프로필·덤프·결과 파일이 없나?
2. `git add <파일>` 로 **고른 파일만** (`git add -A` 금지).
3. `git diff --staged` — 눈으로 읽기. 도구는 **이름을 못 찾습니다**.
4. `python tools/check_privacy.py` — 새로 추가된 줄에서 전화번호·주민번호 모양·키 모양·사용자 폴더 경로를 찾아 줍니다. 찾은 값은 앞 2글자만 보여 줍니다.
   - 예시·가짜 값이라면 그 줄 끝에 `privacy-ok` 를 적으면 건너뜁니다.
   - 이 도구는 **이메일 주소도 경고**하고 끝내는 값을 1 로 하지만, 교사 결정상 이메일은 막지 않습니다. 이메일 경고만 뜬 것이면 통과로 봅니다(PR 에서는 `--warn-only` 로 돌아 실패시키지 않음).
5. `python tools/build_catalog.py --check`

## 4. 괜찮은 것 (막지 않음)

작업자 이름(실명·별명), 교사·교직원 이름, 이메일 주소, 학교 업무 정보. 위 §1 의 다섯 가지가 아니면 막지 않는 것이 교사 결정입니다.
기술 습관 하나: 절대 경로(`C:\Users\<이름>\…`) 대신 `%OneDrive%`·`%USERPROFILE%`·`data_dir()` — 다른 PC 에서도 돌게.

## 5. 실수로 올렸다면

1. **지우고 끝내지 마세요.** 이미 올라간 키·비밀번호는 이력에 남아 있으므로 **새어 나간 것으로 보고 폐기·재발급**하는 것이 원칙입니다(SECURITY_LESSONS_LEARNED §6 교훈).
2. 바로 교사에게 알리기: 무엇이, 어느 파일·어느 브랜치에, 언제 올라갔는지. 값 자체는 대화·PR 에 다시 적지 않기.
3. **작업자는 이력 지우기(강제 푸시·브랜치 삭제)를 하지 않습니다**(WORKER_INSTRUCTIONS.md). 이력 정리와 키 재발급은 교사 PC 에서 교사가 합니다(지난 정리도 그랬습니다 — SECURITY_LESSONS_LEARNED §6).
4. 일지(`docs/worklog/<내 이름>.md`)에 "무엇이 올라갔다 / 교사에게 알림" 한 줄. 일지에도 값을 쓰지 않기.
