## 1. 보완이 필요한 스킬

### admin-buying-product

**현재 있는 내용**
- 서점 엑셀을 이미지보다 우선하도록 안내한다.
- 이미지에서 읽은 목록은 엑셀에 바로 쓰지 않고 사용자 확인을 받도록 한다.
- 상품명·저자·출판사·수량·판매가를 추출하고 파일 잠금 때 다른 이름으로 저장하는 절차가 있다.

**보완할 내용**
1. 대상 엑셀의 실제 양식(시트 이름, 열 이름, 시작 행, 필수 열)을 확인하는 절차가 없다. 예시 코드의 대상 파일 기록 부분도 생략되어 있어 그대로 실행할 수 없다.
2. 대상 파일을 찾는 방법, 결과 파일명·저장 위치, 원본 보존 여부가 정해져 있지 않다.
3. 기록 후 상품 수, 수량, 금액 합계, 빈 칸, 중복 행을 대조하는 마지막 검산 단계가 필요하다.
4. 엑셀 입력 경로 예시에서 사용자 PC의 절대 경로를 쓰지 않도록 바꾸는 편이 좋다.
5. 엑셀 입력을 정확도 100%로 단정하지 말고, 원본 셀을 읽더라도 열 위치·금액 형식·대상 양식은 검증한다고 표현하는 것이 안전하다.

**권장 절차**
- 입력 파일 확인 → 원본 열 이름·샘플 행 확인 → 대상 양식 확인 → 열 매핑표 작성 → 기록 전 목록 미리보기 → 사용자 확인(이미지 입력일 때 필수) → 새 결과 파일 저장 → 건수·수량·금액 검산 → 결과 위치 보고.

### personal-attach-files

**현재 있는 내용**
- PowerShell 스크립트와 BAT 실행 방법, 탐색기에서 파일을 선택해 AI 입력창으로 끌어 놓는 방법이 있다.
- 스크립트가 순서가 있는 파일 이름으로 복사한다는 설명이 있다.

**보완할 내용**
1. 설명은 여러 프로젝트에 쓸 수 있는 도구처럼 되어 있지만, 기본 수집 목록은 특정 앱의 파일 다섯 개로 고정되어 있다. 다른 프로젝트를 고르는 방법이 없다.
2. 프로젝트 루트와 파일 목록을 어디서 바꾸는지, 파일이 없을 때 어떻게 처리하는지 설명이 없다.
3. 이전 `snapshot_to_ai/` 결과를 덮어쓰거나 지우는지, 실패했을 때 원본 파일에 영향이 없는지 안내가 필요하다.
4. `.env`, 토큰, 비밀번호, 학생 기록, 대용량 산출물을 수집 대상에서 제외하는 규칙이 없다.
5. 실제 사용자 PC의 절대 경로가 문서에 들어 있다. 경로는 프로젝트 기준 상대 경로나 환경변수로 바꾸고, 예시는 일반화해야 한다.

**권장 절차**
- 프로젝트 폴더 선택 → 수집 목록 확인·수정 → 비밀값·개인정보·생성물 제외 → 누락 파일 검사 → 임시 폴더 새로 만들기 → 복사 결과 목록 표시 → 탐색기 열기 → 사용 후 임시 폴더 정리.

### personal-free-parents-app

**현재 있는 내용**
- SKILL.md에는 제품 원칙, 디자인 기준, 지도 렌더링 주의점, Supabase 데이터 계약과 검증 명령이 상세하다.
- 별도 README.md에 `flutter pub get`, 에뮬레이터 실행, 분석·시험·APK 빌드 명령이 있다.
- ISSUE 로그에는 원격 마이그레이션 적용 순서와 적용 전 확인 사항이 기록되어 있다.

**보완할 내용**
1. SKILL.md가 README.md의 실행 절차로 바로 연결되지 않는다. 시작할 때 README의 설치·실행·검증 절차를 먼저 읽도록 링크를 추가하면 좋다.
2. 신규 PC에서 필요한 Flutter·Android SDK·에뮬레이터 준비 여부와 확인 방법은 별도 안내가 필요하다.
3. Supabase 원격 마이그레이션은 기존 번호 중복과 적용 이력을 확인해야 한다는 경고가 있으나, 실제 적용 전 확인 순서와 중단 기준을 별도 절차로 정리하면 더 안전하다. 이번 점검에서는 원격 DB에 접속하거나 변경하지 않았다.
4. ISSUES.md의 Android 지도 키 XML 예시에 키 형태의 문자열이 포함되어 있다. 공개용 NCP 키 ID인지 비밀값인지 소유자가 확인해야 한다. 실제 비밀값이면 공개 문서에서 제거하고 교체해야 한다. 이 보고서에는 해당 값을 복사하지 않았다.
5. README.md의 실행 예시에도 컴퓨터 사용자 폴더가 포함된 절대 경로가 있다. 다른 PC에서 그대로 복사해 쓸 수 있도록 환경변수 또는 기본 SDK 경로 탐색을 안내하는 편이 좋다.

**권장 절차**
- README 설치 확인 → 로컬 설정·환경값 확인 → Flutter 의존성 설치 → 에뮬레이터 실행 → analyze/test/build → 로컬 화면 확인 → 원격 DB 변경은 별도 확인·승인 후 진행.

## 2. 현재 절차가 대체로 충분한 스킬

### teacherlesson-aiep-courseware

- 학년·교과·주제·차시 등 필수 입력과 선택 정보를 구분한다.
- 성취기준 확인, 수업 흐름 설계, 자료 분류, 패키지 구성, 사이트 입력표 작성, 검토, 미리보기, 임시저장·최종 등록을 순서대로 설명한다.
- 공개 범위, 저작권, 학생 개인정보, 실제 사이트에서 확인되지 않은 기능을 추측하지 않는 기준이 있다.
- 결과 폴더 구조와 체크리스트가 있어 실무 절차로 사용할 수 있다.
- **추가 권장**: 실제 화면의 세부 입력 위치는 `references/site-capabilities.md`와 템플릿을 함께 읽도록 시작 절차에 한 줄 더 강조하면 좋다. 사이트 화면이 바뀔 때는 해당 문서를 먼저 갱신한다.

### teacherlesson-classtool-courseware

- 시작 정보, 제작 순서, 자료 공개와 학생 클래스 배포의 차이, 실시간 응답과 지속 보관 제출의 차이를 구분한다.
- 사용자가 지정한 클래스·공개 범위·비밀번호를 확인하고, 학생 명단이나 클래스 설정은 임의 변경하지 않도록 한다.
- 현재 화면과 기능 확인 기록을 대조하고, 실제 사이트 등록은 요청받았을 때만 하도록 정한다.
- **추가 권장**: 새 작업을 시작할 때 `references/site-capabilities.md`의 마지막 확인 날짜와 현재 화면이 일치하는지 확인한다.

### teacherlesson-courseware-builder

- 공통 수업 패키지와 플랫폼별 어댑터의 역할을 분리한다.
- 플랫폼 선택, 성취기준, 수업 흐름, 자료 출처, 학생 응답 방식, 저장 위치, 게시 전 확인 절차가 있다.
- 지원 여부가 불명확한 파일 형식·학생 제출 기능을 추측하지 않도록 기준을 둔다.
- **판단**: 공통 절차 문서로 충분하다. 새 플랫폼을 추가할 때 실제 화면/공식 문서 확인과 어댑터 분리 원칙을 유지하면 된다.

## 3. 권장 작업 순서

1. `admin-buying-product`: 대상 엑셀 양식 확인과 저장 후 검산 단계 추가.
2. `personal-attach-files`: 프로젝트 선택·파일 목록 설정·민감 파일 제외·임시 폴더 정리 절차 추가.
3. `personal-free-parents-app`: SKILL에서 README 실행 절차로 연결하고, 키 형태 문자열 및 절대 경로를 소유자가 확인.
4. AIEP·ClassTool: 지금은 큰 수정 없이 사이트 기능 확인 문서의 갱신 날짜만 꾸준히 관리.

## 점검 한계

- 이 보고서는 SKILL.md와 연결된 README·ISSUES 일부를 읽고 절차가 실제 시작부터 결과 확인까지 이어지는지 검토한 것이다.
- 실제 앱 실행, 사이트 로그인, 구매, 원격 Supabase 변경은 하지 않았다.
- 실제 키 ID가 비밀값인지, 사용자 PC의 환경 설정이 무엇인지는 확인하지 못했다.
- 이번 작업에서는 대상 SKILL.md나 코드를 직접 수정하지 않았다.
