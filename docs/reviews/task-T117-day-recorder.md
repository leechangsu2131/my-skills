## 🟡

1. **PC 를 끈 뒤 남은 `recorder.pid` (가짜로 재현)**: 켜짐 판단이 '그 번호의 프로세스가 있나'뿐임. 끄지 않고 PC 를 끄면 파일이 남고, 다음에 윈도우가 같은 번호를 다른 프로그램에 주면
   - `start` → "이미 녹음 중이에요" (**실제로는 녹음 안 됨**), `status` → 녹음 중
   - `stop` → 답이 없다며 그 **다른 프로그램을 `taskkill /T /F`** 로 끔(저장 안 한 문서를 잃을 수 있음)
   - 자주 생기지는 않음. `run` 이 오류로 끝날 때(반환 1·2·3)도 파일을 지우지 않아 남기 쉬움.
   - 고치는 법: 본체가 몇 초마다 파일에 '살아 있음 시각'을 적고 오래되면 꺼진 것으로 보기, 또는 프로세스 시작 시각·명령줄을 대조. 확인 못 하면 강제로 끄지 않기. `speaker_level.py`(#209)도 같은 방식이라 함께 고치면 좋음.
2. **메모장 BOM 이 있는 `config.json` (재현)**: `load_config` 가 `utf-8` 로 읽어 실패하면 `{}`. 설정한 마이크 대신 **목록 첫 마이크로 녹음**하고 알림이 없음(`ffmpeg_path` 설정도 무시). `assistant_server.py` 처럼 `utf-8-sig` 로.
3. **`start` 의 "녹음을 시작했어요"는 확인 전 말 (코드 읽음)**: 본체가 바로 끝나도(마이크를 다른 프로그램이 씀, 저장 실패 등) 성공으로 보임. ffmpeg 오류 글은 버려서(`stderr=DEVNULL`) 기록에는 종료 코드만 남음. 몇 초 뒤 첫 조각 파일이 생겼는지 확인하고, ffmpeg 오류 마지막 몇 줄을 `recorder.log` 에 남기길 권함. 하루가 지나서야 빈 것을 알면 되돌릴 수 없음.
4. **윈도우에서 까만 창이 뜰 수 있음 (추정, 교사 PC 확인)**: 본체는 `DETACHED_PROCESS`(콘솔 없음)인데 ffmpeg 를 `CREATE_NO_WINDOW` 없이 띄움 → 콘솔 창이 새로 생길 수 있고, 그 창을 닫으면 녹음이 끊김(10분 안에 거듭되면 멈춤). `audio_export.py` 처럼 `CREATE_NO_WINDOW` 를.
5. **PC 가 잠든 채 날짜가 바뀌면 (추정)**: 날짜 폴더는 ffmpeg 가 `-t`(자정까지 초)로 끝나야 바뀜. `_wait` 는 날짜를 보지 않음(가짜 시계로 며칠이 지나도 계속 기다리는 것 확인). 잠자는 시간이 `-t` 에 안 세어지면 다음 날 녹음이 전날 폴더에 들어감 → `_wait` 에서 날짜가 바뀌면 `q` 를 보내기. 잠자기를 지난 조각은 파일 안 시각과 실제 시각이 어긋날 수 있어 나누기 표(T116)에 영향(추정).
