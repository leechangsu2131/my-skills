### 1. 띄어쓰기만 다를 때, 앞에 있는 더 긴 이름이 골라짐

| | 사이트 목록(순서대로) | 찾는 이름 | main | PR |
|---|---|---|---|---|
| E 차시(번호 없음) | `우리 지역의 문화유산` / `우리 지역의 문화` | `우리지역의 문화` | 못 찾음 | **첫째 ❌** |
| H 단원(번호 없음) | 단원 `우리 지역의 문화유산` / `우리 지역의 문화` (차시 이름은 같음) | 단원 `우리지역의 문화` | 못 찾음 | **첫째 단원 ❌** |

- 원인: `resolve_references` 는 맞는 이름(둘째)으로 잘 바꾸지만, 그 뒤 반복문의 기존 엄격한 규칙이 '포함'도 맞다고 보아 **앞의 긴 이름**을 먼저 잡음.
- 차시 번호가 양쪽에 있으면(`[1차시] …` / `[2차시] …`) 바르게 고름. 실제 사이트에 번호 없는 이름이 있는지는 **확인 필요**.
- 권하는 고침: 고르는 반복문에서 **이름이 완전히 같은 항목을 먼저** 봄. 사회 `find_lesson_item` 예:

```python
for item in sorted(lessons, key=lambda i: (i["unit_title"] != unit_text, i["title"] != lesson_text)):
```

  음악 `find_lesson_position` 에도 같은 순서를 (원래 순번 `index` 는 유지하며) 임시로 적용해 보니 E·H 가 바른 결과였음(파일은 올리지 않음).
  음악의 나머지 고르는 곳(`click_ppt_for_lesson`·`find_lesson_position_from_candidates`·`find_adjacent_lesson`)도 같은 처리가 필요해 보임(**추정**, 불러 보지 않음).
- 시험에 E·H 를 더하기를 권함.

### 2. 찾는 차시가 없으면 한 글자 다른 차시를 엶 (교사 결정)

| 사이트 목록 | 찾는 이름 | main | PR |
|---|---|---|---|
| `[1차시] 우리 지역의 자연환경 알아보기` 만 | `우리 지역의 인문환경 알아보기` | 못 찾음 | **자연환경 차시를 엶** |

- '엄격하게 맞는 것이 없으면 가장 비슷한 하나' 방식이라 의도된 동작이지만, 사이트에 그 차시가 없을 때는 **다른 차시**가 열림.
- **교사 결정 (2026-11-27): (나)** — 띄어쓰기·기호만 다른 것만 자동으로 열고, '포함'·'비슷함'은 자동으로 열지 말고 확인받음.
- 고칠 때 볼 것:
  - 지금의 '같음(same)'은 띄어쓰기·기호보다 넓음. `normalize_title` 이 숫자 든 괄호도 빼서 `노래 부르기(1)` 와 `노래 부르기(2)` 가 `same` 임(`match_level` 로 확인). 자동으로 여는 기준에서는 이 숫자를 남겨야 함.
  - 도우미는 새 콘솔 창에서 실행되므로(`assistant_server.py`), 후보 이름을 보여 주고 `prompt_input` 으로 묻는 방식이 가능해 보임(**추정**, 실행해 보지 않음).
