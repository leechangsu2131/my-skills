## 🔴 비슷한 이름의 다른 차시가 골라짐 (새로 생기는 문제)

### 원인

- 음악·사회 도우미는 사이트의 차시 목록을 위에서부터 보고 **처음 맞는 것**을 고릅니다(`find_lesson_position`, `find_lesson_position_from_candidates`, `click_ppt_for_lesson`, `find_adjacent_lesson`, `open_resource_for_lesson`).
- 새 `lesson_matches` 는 차시 하나를 볼 때 옛 규칙이 아니면 곧바로 '포함·비슷함'까지 봅니다. 그래서 **앞에 있는 비슷한 차시가, 뒤에 있는 정확한 차시보다 먼저** 잡힙니다.
- 수업 비서는 도우미에 `run <단원> <차시 제목>` 을 넘깁니다(`assistant_server.py` `open_lesson`). 제목에 차시 번호가 없으면 `numbers_can_decide` 보호가 걸리지 않습니다.

PR 설명의 "기존에 맞던 것은 그대로 맞습니다(앞 규칙을 먼저 봄)"는 차시 **하나**를 볼 때만 맞고, **목록에서 고를 때**는 맞지 않습니다.

### 재현

가짜 차시 목록으로 음악 `find_lesson_position` 과 사회 `open_resource_for_lesson` 을 실제로 불러 비교했습니다(selenium·PyMuPDF 는 가짜 모듈, 브라우저 조작 함수는 mock). 두 도우미의 결과가 같았습니다.

| | 사이트 차시 목록(순서대로) | 찾는 제목 | 합치기 전 | T82 |
|---|---|---|---|---|
| A | `[1차시] 우리 지역의 문화` / `[2차시] 우리 지역의 문화유산` | 우리 지역의 문화유산 | 2차시 ✅ | **1차시 ❌** (포함) |
| B | `[1차시] …자연환경 알아보기` / `[2차시] …인문환경 알아보기` | 우리 지역의 인문환경 알아보기 | 2차시 ✅ | **1차시 ❌** (비슷함) |
| C | `[1차시] …자연환경 알아보기` 만 있음 | 우리 지역의 인문환경 알아보기 | 못 찾음 ✅ | **1차시를 엶 ❌** |
| D | `[1차시] 위치 알아보기` | 위치알아보기 | 못 찾음 | 1차시 ✅ (새 기능) |

(B·C 의 `…` 는 "우리 지역의")

다시 해 보기(도우미 폴더에서, 라이브러리가 있는 PC):

```python
import music_helper as m
titles = ["[1차시] 우리 지역의 문화", "[2차시] 우리 지역의 문화유산"]
print(next(t for t in titles if m.lesson_matches(t, "우리 지역의 문화유산")))  # 1차시가 나옴
```

단원 고르기도 같습니다: `unit_matches("우리 지역의 문화", "우리 지역의 문화유산")` 가 음악·사회 모두 합치기 전 `False` → T82 `True` (번호 없는 단원 이름일 때).

실제 사이트·진도표 이름에서 이런 짝이 얼마나 있는지는 **확인 필요**(교사 PC).

### 권하는 고침

1. **간단한 쪽**: 두 도우미의 `lesson_matches`·`unit_matches` 새 부분에서 `titles_match` 대신 `match_level(...) == title_match.SAME` 만 씁니다. 시험 삼아 바꿔 불러 보니(파일은 안 고침) A~D 가 모두 바른 결과였고, PR 의 도우미 시험 12개 중 11개 통과, 1개 실패(`"우리지역 모습"` ↔ `"1. 우리 지역의 모습"` — '비슷함'이 필요한 사례).
2. **'비슷함'을 살리려면**: 목록 전체에서 ① 옛 규칙 → ② '같음' → ③ `best_match` 순으로 고르고, ③은 자동으로 열지 말고 교사에게 확인받습니다. ③만으로는 C(찾는 차시가 없을 때 비슷한 것을 여는 문제)가 남습니다.
3. 어느 쪽이든 **'목록에서 고르기' 시험**(A·B·C)을 더합니다. 지금 시험은 한 쌍씩만 비교해서 이 문제를 잡지 못합니다.
