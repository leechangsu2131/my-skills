# 작업자 일지 (docs/worklog/)

작업자마다 **자기 파일 하나**에 어디까지 했는지 적는다. 다른 작업자 파일은 고치지 않는다(그래서 서로 부딪히지 않음).

- 파일 이름: `<작업자 이름>.md` — 교사가 정해 준 이름(예: `claude-web-a.md`, `bizcoder-2.md`, `gemini-3.md`). 실명·별명·이메일 모두 괜찮다(2026-11-25 교사 결정). 한 작업자는 한 이름만 계속 쓴다(바뀌면 일지가 둘로 갈라짐). 영문 이름이 git 도구에서 조금 더 편하다.
- 작업 브랜치에서 이 파일도 같이 고쳐 커밋한다 → 교사 PC 의 현황표(`python tools/work_status.py`)가 브랜치에서 마지막 줄을 읽는다.
- 새 기록은 **맨 아래에 한 줄씩** 붙인다. 지우지 않는다.

```
# claude-web-1 일지

- 2026-11-25 09:10 T05 시작 (브랜치 task/T05-tests-supabase-export)
- 2026-11-25 10:02 T05 PR 올림 — 시험 12개 통과, 버그 1개 ISSUES 기록
- 2026-11-25 10:05 T06 시작 (브랜치 task/T06-tests-library-search)
- 2026-11-25 11:30 T06 막힘 — 검색 결과 파싱이 사이트 HTML 에 묶여 있어 가짜 자료가 필요함, 교사 확인 대기
- 2026-11-27 14:00 T98 시작 (브랜치 task/T98-work)
- 2026-11-27 14:25 T98 진행 — 체크리스트 1·2 끝(시험 8개 통과) / 다음: 3 메모 저장 오류 재현
- 2026-11-27 16:40 T98 이어받음 (브랜치 task/T98-work, 앞 — claude-web-1: T98 진행 — 체크리스트 1·2 끝 …)
```

쓸 말(줄 앞쪽, `—` 앞에): `시작` · `진행`(한 것 / 다음: 할 것 — **단계마다**, 토큰이 끊겨도 이어받을 수 있게) · `합칠 준비`(쓸 만한 중간 단계, 같은 브랜치에서 계속) · `PR 올림`(일 전체 끝 — 무엇을 했고 어떻게 확인했나) · `막힘`(이유·필요한 것) · `그만둠`(어디까지, 다음에 할 것) · `이어받음`(`claim_task.py` 가 적음).

**이어받기(2026-11-27)**: `tools/claim_task.py` 는 브랜치의 마지막 일지 줄이 `그만둠` 이면 바로, `시작`·`진행`·`합칠 준비`·`이어받음` 인데 2시간 넘게 새 커밋이 없으면 다른 작업자가 그 브랜치를 이어받게 한다. `PR 올림`·`막힘` 은 이어받지 않는다. 그래서 마지막 줄은 늘 "다음에 무엇을 할지"가 보이게 쓴다.
