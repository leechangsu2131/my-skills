# admin-class-buy 문제해결 기록

이 파일은 실제 실행 중 발생한 문제와 해결 방법을 계속 누적한다.

## 2026-06-18 실제 실행 프로브

### 문제: 원격 디버깅 Chrome에 연결되지 않음

- 증상: `edufine_class_settlement.py` 실제 실행 시 `BrowserType.connect_over_cdp: connect ECONNREFUSED ::1:9222` 오류가 발생했다.
- 원인:
  - 자동화 대상 Chrome이 `--remote-debugging-port=9222`로 실행되어 있지 않았다.
  - 기존 기본 CDP URL `http://localhost:9222`가 Windows 환경에서 IPv6 `::1`로 해석될 수 있어, Chrome이 IPv4에만 떠 있으면 연결이 실패할 수 있다.
- 해결:
  - `edufine_class_settlement.py` 기본 CDP URL을 `http://127.0.0.1:9222`로 변경했다.
  - `--cdp-url` 옵션을 추가해 필요 시 다른 CDP 주소를 지정할 수 있게 했다.
  - 연결 실패 시 `scripts/launch_edufine_chrome.bat` 실행, 업무포털/NEIS 로그인, K-에듀파인 열기 순서가 나오도록 오류 메시지를 개선했다.
  - `scripts/launch_edufine_chrome.bat`을 추가해 원격 디버깅 Chrome을 쉽게 열 수 있게 했다.
  - RuntimeError는 긴 traceback 대신 `[오류]` 한 줄 안내로 출력되도록 정리했다.
  - Playwright 실행 중 나오는 Node deprecation warning은 `NODE_OPTIONS=--no-deprecation`으로 숨겼다.

### 확인한 실제 지급 데이터

- 파일: `C:\Users\user\Desktop\3학년 2반\개산급\(화천초등학교-2279 (첨부)) (붙임2) 학급 자율 운영비 임시출납원 개산급 지급내역.xlsx`
- 3학년 2반: 학생수 17명, 단가 20,000원, 금액 340,000원, 임시출납원 이창수.

### 다음 실행 전 체크리스트

1. `scripts/launch_edufine_chrome.bat` 실행.
2. 열린 Chrome에서 업무포털/NEIS 로그인.
3. K-에듀파인 창 열기.
4. `http://127.0.0.1:9222/json/version` 접속 또는 PowerShell `Invoke-WebRequest`로 CDP 응답 확인.
5. 실제 영수증별 정산 행 JSON/CSV를 준비한 뒤 먼저 `--dry-run` 실행.

### 문제: CDP는 열렸지만 K-에듀파인 페이지가 없음

- 증상: Chrome remote debugging은 응답하지만 `No K-에듀파인 page found` 오류가 발생했다.
- 원인: 원격 디버깅 Chrome 창은 열렸지만 업무포털 로그인 또는 K-에듀파인 메뉴 열기가 아직 완료되지 않았다.
- 해결:
  - `edufine_class_settlement.py`가 업무포털 탭을 찾으면 `K-에듀파인` 클릭을 시도하도록 보강했다.
  - 여전히 K-에듀파인 창을 찾지 못하면 열린 탭 제목과 URL 목록을 오류 메시지에 출력하도록 했다.
  - 실제 사용자는 열린 Chrome에서 로그인 후 K-에듀파인을 연 다음 같은 명령을 다시 실행하면 된다.
- 재확인 결과:
  - 원격 디버깅 Chrome은 정상 응답했다.
  - 열린 탭은 `업무포털 로그인 | https://gbe.eduptl.kr/bpm_lgn_lg00_001.do`로 확인됐다.
  - 따라서 다음 차단 지점은 코드 오류가 아니라 사용자의 수동 로그인 및 K-에듀파인 창 열기이다.

### 문제: K-에듀파인이 설치 안내 페이지에서 멈춤

- 증상: 로그인 후 K-에듀파인 탭은 열렸지만 URL이 `https://klef.gbe.kr/html/install.html?url=...main.do`이고 본문에 `사용자 PC 보안 서비스 프로그램 설치`가 표시됐다.
- 원인: 자동화용 Chrome 프로필에서 K-에듀파인 보안 프로그램 설치 상태 확인 페이지가 먼저 열렸다.
- 확인:
  - DOM에서 `메인페이지로 이동` 버튼은 `button.mian_btn`으로 확인됐다.
  - `button.mian_btn` 클릭 후 `https://klef.gbe.kr/keris_ui/main.do`로 이동하는 것을 확인했다.
- 해결:
  - `navigate()` 시작 시 `install.html`이면 `button.mian_btn` 클릭을 먼저 시도하도록 했다.
  - 클릭 후에도 `install.html`이면 쿼리스트링의 `url` 값을 직접 열도록 보강했다.

### 문제: 공지 팝업이 메뉴 클릭을 막음

- 증상: `업무메뉴` 클릭 시 `nexamodaloverlay intercepts pointer events`로 실패했다.
- 원인: `noticePopup0`, `noticePopup1`, `noticePopup2`처럼 여러 공지 팝업이 순차적으로 떠서 화면 전체 오버레이가 남았다.
- 해결:
  - DOM에서 `[id*=noticePopup]` 중 `noticePopup숫자` 패턴을 모두 찾는다.
  - 각 팝업의 `divPopupBottom.form.chkDay`, `divPopupBottom.form.btnClose`, `btnClose00`을 순서대로 강제 클릭한다.
  - 팝업이 새로 생기는 경우를 대비해 최대 8회 반복한다.

### 문제: 학교회계 시스템 전환 콤보가 화면 밖에 펼쳐짐

- 증상: `cboJobList` 드롭다운 클릭 후 목록은 생성되지만 `x=-5000`, `visibility=hidden` 상태로 있어 마우스 클릭이 불가능했다.
- 확인한 목록 순서: `업무관리`, `지식관리`, `학교회계`, `재정분석`, `서비스공통`.
- 해결:
  - `cboJobList.comboedit`에 포커스를 준 뒤 `Home`, `ArrowDown`, `ArrowDown`, `Enter` 키 입력으로 `학교회계`를 선택한다.
  - 선택 후 왼쪽 메뉴에 `사업관리`, `계약관리`, `사업담당`이 표시되는 것을 확인했다.

### 문제: 안내 문서와 실제 메뉴명이 다름

- 증상: 안내 문서에는 `개산금정산등록`으로 표현되어 있으나 실제 K-에듀파인 메뉴에는 `개산급정산등록`으로 표시됐다.
- 실제 메뉴 경로:
  - `학교회계` 전환
  - `사업담당`
  - `품의/정산`
  - `개산급정산등록`
- 확인 결과:
  - `개산급정산등록` 화면에 진입했다.
  - 화면에서 `* 일자`, `조회`, `행추가`, `* 사용일자`, `* 사용업체명`, `* 사용금액`, `* 증빙구분`, `사용내역`, `정산서제출` 항목을 확인했다.

### 문제: 조회 버튼이 브라우저 화면 밖에 있어 클릭 실패

- 증상: `btnAuthS01` 조회 버튼 클릭 시 `Element is outside of the viewport` 오류가 발생했다.
- 원인: 현재 Chrome 창/뷰포트 폭이 좁아 `조회` 버튼의 x 좌표가 1384 근처로 잡혔고, Playwright의 물리 클릭이 불가능했다.
- 해결:
  - 조회 버튼은 정확한 ID suffix `form.divWork.form.divAuth.form.btnAuthS01`로 찾는다.
  - 일반 클릭 실패 시 `mousedown`, `mouseup`, `click` MouseEvent를 DOM에 직접 dispatch한다.
  - 예상 밖 예외도 긴 traceback 대신 `[오류] {예외종류}: ...` 형식으로 출력하도록 했다.

### 문제: 시작일자를 잘못된 입력칸에 입력함

- 증상: 이전 스크립트가 첫 번째 보이는 날짜형 input을 임의 선택하여 상단 알림/기관 관련 입력칸에 `2026-03-01`을 넣었다.
- 원인: 화면 전체 input을 순회하는 범용 로직이 너무 넓었다.
- 해결:
  - 시작일자 입력은 `form.divWork.form.divSearch.form.calRecptDteFrom.calendaredit:input` suffix를 가진 필드만 사용하도록 고정했다.
  - 이후 조회는 `btnAuthS01` 버튼만 사용한다.

### 문제: 화면 본문 텍스트 판별이 좌측 메뉴/공지와 섞임

- 증상: 실제 `개산급정산등록` 작업 프레임의 시작일자 필드는 정상적으로 `2026-03-01`로 변경됐지만, `document.body.innerText` 확인값에는 좌측 메뉴와 공지 목록 텍스트가 많이 섞였다.
- 원인: K-에듀파인 Nexacro 화면은 여러 접근성/메뉴/작업 영역 노드가 한 DOM 안에 공존해 본문 전체 텍스트만으로 현재 작업 화면을 안정적으로 판별하기 어렵다.
- 해결:
  - 화면 판별은 `개산급정산등록`의 정확한 시작일자 필드 ID suffix `form.divWork.form.divSearch.form.calRecptDteFrom.calendaredit:input` 존재 여부를 우선 사용하도록 변경했다.
  - 문서에 남아 있던 안내자료식 오타 `개산금정산등록` 표현을 실제 메뉴명 `개산급정산등록` 기준으로 정리했다.
  - `scripts/quick_validate.py`를 추가해 스킬 필수 파일, 핵심 용어, 파이썬 스크립트 컴파일을 빠르게 점검하도록 했다.

### 재확인 결과

- `python scripts/edufine_class_settlement.py --navigate-only`가 정상 종료됐다.
- 실제 작업 프레임의 시작일자 필드 값이 `2026-03-01`로 확인됐다.
- 종료 메시지: `Navigation check complete. No settlement rows were entered.`

### 문제: 병렬 py_compile과 quick_validate가 __pycache__ 파일 잠금을 일으킴

- 증상: `python -m py_compile ...`와 `python scripts/quick_validate.py`를 동시에 실행하자 Windows에서 `WinError 5 액세스가 거부되었습니다`가 발생했다.
- 원인: 두 프로세스가 같은 `scripts/__pycache__/edufine_class_settlement...pyc` 파일을 동시에 생성/교체하려고 했다.
- 해결:
  - 파이썬 컴파일 검증은 병렬 실행하지 않고 순차 실행한다.
  - 재실행 결과 단독 `py_compile`과 `quick_validate.py` 모두 통과했다.

### 문제: 증빙구분 콤보에 `전산자료`가 바로 입력되지 않음

- 증상: 영수증 행 입력 후 `사용일자`, `사용업체명`, `사용금액`, `사용내역`은 입력됐지만 `증빙구분`은 처음에 `선택`으로 남았다.
- 원인: `증빙구분` 칸은 일반 텍스트 입력칸이 아니라 Nexacro 그리드 콤보박스라서 키보드로 문자열을 입력하는 방식이 실제 선택값으로 확정되지 않았다.
- 확인한 옵션:
  - `선택`, `세금계산서`, `계산서`, `전산자료`, `무증빙`, `지로납부`, `현금영수증`, `기타`.
- 해결:
  - 현재 화면의 `증빙구분` 콤보를 열고 `전산자료` 항목을 직접 클릭해 값이 반영되는 것을 확인했다.
  - `edufine_class_settlement.py`에 `select_evidence_type()`을 추가해 앞으로는 증빙구분을 콤보 항목 클릭 방식으로 선택하도록 변경했다.
