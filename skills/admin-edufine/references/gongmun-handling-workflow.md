# 공문 확인 → 업무 처리 → 기록 워크플로우

> 공문을 받고 처리하는 일을 AI가 이어받을 수 있게 정리한 절차. 학교·학생 정보는 이 문서(공개 저장소)에 쓰지 않는다.
> 실제 처리 기록은 사용자의 업무 폴더(OneDrive 업무 폴더 안 `_업무기록\`)에 둔다.

## 기록 위치 원칙 (두 갈래)

| 무엇 | 어디에 | 예 |
|---|---|---|
| **어떻게 하는가**(반복 절차, 화면 조작, 함정) | 이 저장소의 스킬 문서 (`SKILL.md`, `references/`, `ISSUES.md`) | NEIS 조작 → `admin-neis-bot`, 공문 찾기·읽기 → 이 문서 |
| **우리 학교에서 무엇을 했는가**(공문번호, 학생·교사 이름, 결재 상태, 남은 일) | 업무 폴더 `_업무기록\<연도> <업무> 처리기록.md` | PAPS 결재 중, 출장 상신 번호, 대회 인솔 일정 |

새 AI 세션은 **스킬 문서로 방법을, 처리기록으로 현재 상황을** 파악하고 이어서 일한다.

## 처리 순서

1. **공문 찾기**
   - 사용자의 공문 저장 폴더(다운로드\공문, 업무 폴더)를 먼저 검색한다.
   - 없으면 K-에듀파인 문서관리 > 문서함 > **문서등록대장**에서 제목으로 검색한다(통합검색은 타 학교 문서가 섞임).
   - 본문은 제목 클릭 시 WXSClient 네이티브 뷰어로 열려 자동화로 읽을 수 없다. 문서를 체크하고 **디스크(저장) 아이콘**으로 직접 내려받는다(사용자에게 저장을 부탁하지 않음). 자세한 내용은 `admin-neis-bot/ISSUES.md` ISSUE-008.
   - 확장자가 .xlsx/.hwpx인데 실제로는 텍스트 덤프인 파일이 있다. 압축 해제 오류가 나면 UTF-8 텍스트로 읽는다.
2. **요구사항 뽑기**: 무엇을 / 언제까지 / 누구에게(제출처·연락처) / 우리 학교 해당 여부(붙임 명단에서 학교명 검색)를 정리해 사용자에게 보여준다.
3. **처리**
   - NEIS 작업은 `admin-neis-bot`의 해당 절차를 따른다.
   - 서식(엑셀·한글)은 원본 양식을 복사해 채우고, 수식·예시 행은 그대로 둔 뒤 사용자에게 확인을 받는다.
   - 제출·상신·발송·회수처럼 **바깥에 영향을 주는 동작은 사용자에게 먼저 묻는다.**
4. **기록**: 처리기록 파일에 공문 하나당 항목 하나를 남긴다(아래 양식). 맨 위 "남은 일" 표도 함께 고친다.
5. **반복 절차 반영**: 새로 알게 된 방법·함정은 해당 스킬의 `references/`나 `ISSUES.md`에 일반화해서 적는다(이름·번호 없이).

## 처리기록 항목 양식

```markdown
## [접수번호] 공문 제목 (발신기관, 접수 MM.DD)
- 원본: 저장 경로
- 요구사항: 무엇을 / 마감
- 우리 학교 해당: 대상 학생·교사, 수량 등
- 처리: 날짜 – 한 일 (NEIS 메뉴, 상신 번호, 결재선, 작성 파일 경로)
- 상태: 완료 / 결재 중 / 사용자 확인 필요
- 남은 일: 무엇을 언제까지
```
