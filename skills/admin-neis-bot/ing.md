# 교외체험학습신청서 접수 및 결재선 상신 자동화 개발 일지 (ing.md)

## 2026-07-10: 개발 실패 극복 및 최종 완결 일지

### 목표
- 나이스 교외체험학습신청서관리 화면에서 접수대기 건을 자동 접수하고, 결재선(교무/교감)을 지정하여 상신까지 완료하는 자동화 스크립트 개발.

---

### 1단계 시도 (v1) - 실패 및 분석
- **문제점**: 
  - `grid.getColumnCount()` 호출 시 `is not a function` 구문 에러 발생. eXBuilder6의 Grid 컴포넌트는 minified 코드가 다른 프로토타입을 가짐.
  - selenium의 창 포커싱에서 SSL VPN Client 창이 타겟으로 잡혀 cpr 정의를 읽지 못하는 현상 발생.

### 2단계 시도 (v2) - 반성공 및 문제 봉착
- **개선점**: 
  - `appId` 매핑 방식으로 교외체험학습 앱(`edu/sa/eds/eaa/ae/eds_eaaae01_m01`)을 명확히 필터링.
  - 데이터셋 API(`ds.getValue`, `ds.getColumnNames`)를 사용하여 직접 신청 데이터를 수집.
  - 김주안 학생의 접수(상세 팝업 진입 -> 저장 -> 접수) 처리가 완벽히 성공.
- **오류 발생**: 
  - 결재를 올리기 위해 미상신 신청서 2건을 체크하고 승인요청을 눌렀으나, **"선택된 학생이 없습니다"** 알림창이 뜸.
  - **원인**: 데이터셋 `ds.setValue(r, "chk", "1")`만 수행하면 체크박스는 물리적으로 켜지지만, eXBuilder6 Grid 컨트롤 내부의 실제 `CheckedRow` 수집 버퍼에 등록되지 않음.
  - **오류 2**: 결재자지정 팝업에서 강동휘, 김경영을 추가하려 하였으나 그리드 선택(`selectRows`) 후 추가 버튼(`btnAdd.click()`)이 먹히지 않아 우측 결재자 목록으로 이전되지 않음. 이 상태에서 상신을 진행하자 **"1번째 결재자고유번호 유효하지 않은 매개변수 [CM-SYE-0307]"** 에러 발생.

### 3단계 시도 - 100% 자동 완결 성공 🏆
- **해결책 1: 체크박스 DOM 직접 클릭**
  - 그리드 DOM ID(`uuid-` prefix + `grid.uuid`)를 구한 뒤, 해당 행(`data-rowindex`)의 체크박스 요소를 직접 찾아 마우스 `.click()`을 보냄. 이로써 나이스 엔진이 체크 상태를 완벽히 인지하여 승인요청 단계로 진입 성공.
- **해결책 2: span 더블클릭(dblclick) 이벤트 전송**
  - 그리드에서 행 선택이 씹히는 문제를 해결하기 위해, 그리드 행 내부에서 사용자명(예: `"강동휘"`, `"김경영"`)이 들어간 `span` 요소를 직접 찾아 **`dblclick` (더블클릭) 마우스 이벤트**를 시뮬레이션 전송함.
  - 나이스 전체 메뉴 결재선 관리에서 더블클릭 이벤트가 완벽히 먹히며 우측 결재자 그리드로 즉시 연동됨.
- **해결책 3: 기본 목록 활용으로 검색 딜레이 제거**
  - 매번 이름 검색창에 텍스트를 입력하고 조회 버튼을 누르는 대신, 결재자 팝업이 로드될 때 기본 제공되는 전체 임직원 목록(Total 43명)에서 강동휘(Index 3)와 김경영(Index 1)의 위치를 찾아 더블클릭 추가를 실행함. 비동기 검색창 딜레이가 없어 인덱스 꼬임이 100% 예방됨.

## 2026-07-16: 다중 스킬 간 크롬 디버깅 포트(9222) 락, 보안 프로필 종속성 및 세션 격리(Session 0/1) 원천 해결 🛠️

### 1. 현상 및 근본 원인 분석
- **문제**: 나이스 자동화 기동 시 `ECONNREFUSED 127.0.0.1:9222` 또는 `from chrome not reachable` 연결 오류가 반복되며 자동화 진입이 차단됨.
- **분석 및 진단**:
  1. **보안 프로그램의 프로필 종속성**:
     - 에듀파인 및 나이스의 필수 보안 프로그램(공동인증서, 키보드 보안 등)은 크롬의 **실제 사용자 프로필(`%LOCALAPPDATA%\Google\Chrome\User Data`)**의 설치 경로와 긴밀하게 결합되어 구동됨.
     - 임시 프로필(`--user-data-dir=%TEMP%\...`)로 디버그 크롬을 띄울 경우, 보안 프로그램이 인식되지 않아 **"보안 프로그램을 새로 설치하라"는 경고 페이지로 무한히 튕기는 현상**이 발생함. ➡️ 따라서 무조건 실제 사용자 프로필(`User Data`)을 타겟으로 실행해야 함.
  2. **실제 프로필 중복 실행 제한 (Singleton Lock)**:
     - 이미 사용자가 평소 쓰던 일반 크롬 창들이 켜진 상태에서 실제 프로필(`User Data`)로 원격 디버깅 크롬을 새로 실행하면, 크롬 고유의 Singleton 정책에 의해 디버깅 옵션이 씹히고 기존 일반 프로세스의 탭으로 합쳐짐.
     - 이로 인해 겉보기에는 새 탭으로 나이스 창이 떠서 로그인을 마쳤으나, 실제로는 **원격 디버깅 포트 9222 자체가 활성화되지 않은 일반 모드**가 되어 연결 오류가 났던 것임.
  3. **윈도우 세션 격리 (Session 0 vs Session 1) 및 EVPN 프록시 차단**:
     - 에이전트(백그라운드 세션 0)가 직접 실행하는 파이썬 CLI 스크립트는 윈도우 보안 가상망(EVPN) 상태에서 크로스 세션 방화벽 장벽에 막혀 사용자의 실물 화면 세션(Session 1)에 켜진 크롬 포트 9222와 TCP 소켓 매핑이 드롭되는 현상이 발생함.
     - 또한 IPv6 주소 해석 꼬임(`::1`)으로 인해 `localhost` 해석 실패가 누적됨.

### 2. 향후 오류 방지를 위한 3대 개발 철칙 (Golden Rules) 🏆

이후 에듀파인/나이스/아이스크림 등 어떠한 웹 자동화 스킬을 개발하더라도 다음 3대 철칙을 반드시 준수하여 설계해야 장애를 방지할 수 있음.

#### 📌 철칙 1: 공공/교육망 시스템은 반드시 실제 사용자 프로필(`User Data`)을 타겟으로 구동한다
- 보안 모듈 튕김 현상을 원천 방지하기 위해 임시 프로필을 쓰지 않고, 무조건 `%LOCALAPPDATA%\Google\Chrome\User Data`를 사용한다.

#### 📌 철칙 2: 배치 파일(Launcher) 기동 시 락 제거 전처리를 강제화한다
- 크롬이 9222 포트를 정상적으로 활성화할 수 있도록, 배치 파일 시작부에 **(1) 해당 프로필을 점유 중인 백그라운드 크롬 좀비 프로세스를 색출하여 강제 종료**하고, **(2) SingletonLock 파일을 강제 제거**하는 파워쉘 스크립트를 상시 탑재한다.
- **표준 배치 전처리 템플릿**:
  ```bat
  powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'name = ''chrome.exe''' | Where-Object { $_.CommandLine -like '*User Data*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force -ErrorAction SilentlyContinue }"
  powershell -NoProfile -Command "Remove-Item -Path '$env:LOCALAPPDATA\Google\Chrome\User Data\SingletonLock' -Force -ErrorAction SilentlyContinue"
  start "" "%CHROME_EXE%" --remote-debugging-port=9222 --user-data-dir="%LOCALAPPDATA%\Google\Chrome\User Data" --new-window %URLS%
  ```

#### 📌 철칙 3: EVPN 인터넷 차단망 내에서는 Playwright + no_proxy + IPv4 고정을 사용한다
- 셀레늄(Selenium)은 기동 시 드라이버 자동 업데이트/버튼 체크 등을 위해 구글 아웃바운드 인터넷을 강제 호출하므로, EVPN이 연결된 인터넷 차단 상황에서 무조건 에러가 발생함.
- 따라서 드라이버 업데이트 통신을 타지 않는 **Playwright 연결 방식**을 사용하며, 아래와 같이 로컬 프록시 우회 및 IPv4 명시 고정 처리를 스크립트 최상단에 구현한다.
- **표준 파이썬 접속 구성**:
  ```python
  import os
  # 프록시 우회 강제 적용 (EVPN 가상 어댑터 필터 통과)
  os.environ["no_proxy"] = "127.0.0.1,localhost"
  
  # IPv6 루프백 오류(::1) 회피를 위해 명시적 IPv4 주소 사용
  browser = await p.chromium.connect_over_cdp("http://127.0.0.1:9222")
  ```
