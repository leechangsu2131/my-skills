## 코드에서 확인한 동작

- Manifest V3 확장 프로그램이며, `https://*.neis.go.kr/*`에 MAIN world `injected.js`와 일반 content script `content.js`를 주입합니다. 권한은 `storage`이고 호스트 권한은 나이스 도메인입니다.
- `injected.js`는 `fetch`와 `XMLHttpRequest`를 감싸 `srv_mym_mm01_001.do` 통신을 관찰합니다. 원래 요청을 먼저 실행하며, fetch 응답은 clone을 통해 읽습니다.
- 관찰된 본문과 응답 텍스트는 `window.postMessage`로 content script에 전달됩니다. 단, `saveCapturedTemplate()`은 본문만 JSON으로 파싱하고 `data.dmSearch.workYmd`가 있는 경우에 템플릿으로 저장합니다. 전달된 `responseText`는 그 저장 함수에서 사용하지 않습니다.
- 템플릿·정규화된 endpoint·origin·캡처 시각은 `chrome.storage.local`에 저장됩니다. 월별 결과도 `rowsByDate` 형태로 로컬 캐시에 저장되며 캐시 유효시간은 10분입니다.
- `fetchDay()`는 저장된 템플릿을 복제해 `data.dmSearch.workYmd`만 날짜별로 바꾼 뒤 같은 endpoint에 POST합니다. `credentials: "include"`로 현재 브라우저 로그인 세션을 사용하며, 한 달 날짜 조회는 동시 4건까지 실행합니다.
- 응답에서는 `dsMain` 배열을 사용합니다. 화면에서는 `invlFlnm`, `jbpsNm`, `rksNm`, `jbgdNm`, `workSittnNm`, `workSittnPrd`, `destiNm`, `atrzStsNm` 등을 필터링·표시에 사용합니다. 승인완료만 기본 표시하고 결재중 표시는 사용자가 켤 수 있습니다.
- 확장 프로그램은 복무 데이터를 나이스에 입력하거나 수정하는 기능을 코드에서 확인할 수 없습니다. 핵심 기능은 조회 결과를 월간 달력에 표시하는 것입니다.

## NEIS 자동화 스킬에 적용할 구조

확장 프로그램의 가치는 복무 달력 기능 자체에 그치지 않습니다. 로그인된 업무포털에서 업무별 요청과 응답을 관찰하고, 필요한 데이터를 화면 표시나 자동화에 활용하는 방법을 보여줍니다. 이를 다음 구성으로 확장할 수 있습니다.

1. **세션 연결 계층**: 사용자가 직접 로그인한 브라우저 세션에 연결합니다. 자격 증명·쿠키·토큰은 읽거나 별도로 보관하지 않습니다.
2. **업무별 어댑터**: 복무, 시간표, 주간학습 등 각 화면의 조회·입력 흐름과 자체 요청·응답 스키마를 개별 분석합니다. 한 업무의 endpoint나 필드명을 다른 업무에 추정 적용하지 않습니다.
3. **정규화 계층**: 화면별 응답을 날짜, 교시, 과목, 학습내용, 복무 종류·상태처럼 업무에 맞는 공통 구조로 변환하고, 원본 화면과 값의 출처를 추적할 수 있게 합니다.
4. **교사 화면**: 시간표와 주간학습내용을 날짜·교시 기준으로 결합해 **오늘의 수업**에 과목과 수업할 내용을 표시할 수 있습니다. 복무 현황은 별도 영역으로 표시할 수 있습니다.
5. **입력 액션**: 읽기 어댑터와 분리합니다. 실제 UI 입력 흐름에서 필수 필드, 검증, 저장 응답을 확인하고, 미리보기·사용자 승인 후 저장한 뒤 재조회로 반영 여부를 확인합니다.

## 분석 및 구현 원칙

1. 새 업무는 사용자가 정상적으로 화면에서 수행하는 조회·입력 과정을 먼저 관찰하고 화면 데이터셋, 요청, 응답, 저장 후 검증의 대응을 확인합니다.
2. 확장 프로그램처럼 캡처한 요청 본문을 재사용해 검색 조건을 바꾸는 방식은 브라우저 세션에서 추가 요청을 발생시킵니다. 복무 사례의 유효한 구현 패턴으로 기록하되, 다른 화면에 적용하기 전 해당 업무의 권한·운영 정책·요청량·응답 범위를 확인합니다.
3. 개인정보가 든 원본 본문, 응답, 캐시, 화면 캡처를 테스트 로그나 스킬 저장소에 남기지 않습니다. 스키마 예시는 식별 정보를 제거하고 필요한 필드만 사용합니다.
4. 조회와 쓰기는 별개 흐름으로 유지합니다. 조회 endpoint만으로 쓰기 형식이나 권한을 추정하지 않으며, 기존 승인 및 검증 절차를 우회하지 않습니다.
5. 저장소의 `neis_collect_semester_timetable.py`와 시간표 탐색 기록은 학급시간표관리 데이터 수집·편성 최적화의 기반입니다. 이것만으로 오늘 수업 내용을 구성할 수 있다고 보지 않으며, 주간학습내용 조회를 별도로 조사해 날짜·교시 단위로 결합합니다.

## 검증되지 않은 점

- 실제 나이스 서버가 해당 요청을 어떻게 인가·감사하는지, 허용 요청량이 얼마인지 확인하지 않았습니다.
- 여러 시도교육청에서 endpoint와 응답 스키마가 같은지 확인하지 않았습니다.
- `dsMain` 필드의 의미와 개인정보 범위는 확장 프로그램 코드에서 사용되는 방식으로만 파악했으며, 공식 스키마로 검증하지 않았습니다.
- 시간표·주간학습내용의 요청 주소와 응답 필드는 이 확장 프로그램으로 확인할 수 없습니다. 실제 각 업무 화면에서 별도 관찰해야 합니다.
