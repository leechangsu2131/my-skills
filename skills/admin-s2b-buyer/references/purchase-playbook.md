# 학교 물품 구입 안내서 — 예산 확인부터 S2B 견적서, 에듀파인 품의까지

> "○○ 예산이 남았으니 S2B에서 제일 싼 거 골라 품의까지 올려 줘" 같은 요청을 처리하는 순서와, 실제로 해 보며 알게 된 점.
> 학교마다 다른 값(공문번호·예산명·잔액·품의번호·판매처)은 여기 적지 않는다. 그런 기록은 업무 폴더 `_업무기록\<연도> <업무> 처리기록.md` 에 남긴다.
> 도구: `admin-s2b-buyer/s2b_cdp.py`, `admin-edufine/edufine_poomui_cdp.py`, 공통 `_shared/cdp_tab.py` (모두 사용자 Chrome 9222 에 내 탭 하나만 열어 쓴다).

---

## 1. 전체 순서

| 단계 | 할 일 | 도구 |
|---|---|---|
| 1 | 예산 잔액 확인 (산출내역 이름 그대로) | `edufine_poomui_cdp.py budgets` |
| 2 | 관련 문서번호 찾기 — 같은 예산으로 했던 지난 품의 개요의 "1. 관련:" | `edufine_poomui_cdp.py list --kw <키워드>` |
| 3 | 모르면 사용자에게 묻기 (예산별로 맞는 문서번호여야 함) | — |
| 4 | S2B 검색: 전국·낮은 금액순, 검색어 2~4개 | `s2b_cdp.py search "<이름1>" "<이름2>"` |
| 5 | 후보를 **형태별로** 묶어 사용자에게 고르게 함 | — |
| 6 | 상세 확인: 배송비·납품기간·견적 유효기간·신뢰도 | `s2b_cdp.py detail <물품번호>` |
| 7 | 견적서 담기 → 실제 금액(배송비 포함) 확인 | `s2b_cdp.py add <번호>:<수량>` → `cart` |
| 8 | 관리자(교장) 보고용 안내문 — 품목·판매처·가격·주소 | 클립보드 + 업무폴더 txt |
| 9 | 에듀파인 연계 엑셀 받기(보관용) | `s2b_cdp.py edufine-xls <rc>,<rc>` |
| 10 | 품의 작성·저장 (결재요청은 사용자가 누름) | `edufine_poomui_cdp.py fill plan.json --save` |
| 11 | 기록: 업무폴더 처리기록(학교 값) + 이 문서/ISSUES(방법) | — |

요청은 중간에 자주 바뀐다(품목 추가·교체·삭제, 예산 배분 변경). 각 단계 결과를 표로 짧게 보여 주고 다음으로 넘어간다. 바뀌면 S2B 견적서·품의·안내문·처리기록을 **함께** 고친다.

## 2. 사용자와 정해야 하는 것 (임의로 정하지 말 것)

- **형태** — 같은 "거치대"도 벽부착형(수만 원)과 이동식 스탠드(수십만 원)가 10배 차이 난다. 형태별 최저가를 나란히 보여 준다.
- **최저가 vs 오래가는 제품** — 매일 옮겨 쓰는 체육관 기구는 국내 제조 철제(쇼트 처리 후 분체도장, 무게중량판 등)를 고를 수 있다. 두 안을 가격 차이와 함께 제시한다.
- **이동식 여부** — 보관대·걸이대는 바퀴가 있는지가 중요할 수 있다. 오픈마켓 상품은 옵션마다 바퀴 포함 여부와 가격이 다르다.
- **수량** — 예산을 다 채울지, 품목당 1개인지.
- **예산 배분** — 예산이 여러 개일 때 어느 예산으로 할지. 한 예산 잔액 안에 들어가면 하나로 몰기도 한다.
- **관련 문서번호** — 예산마다 맞는 번호. 지난 품의에서 찾은 번호를 보여 주고 확인받는다.
- **S2B 에 없는 물품의 구입처** — 오픈마켓 중 어디서 살 수 있는지(아래 4절).

## 3. S2B 에서 알게 된 것

- **검색어 인코딩**: S2B 페이지는 EUC-KR. URL `searchQuery=` 에 UTF-8 한글을 넣으면 0건 → 검색창 폼에 값을 넣고 submit.
- **"우리지역" 기본 필터**: 로그인 계정의 지역으로 걸러진다. 전국 검색은 hidden `areaCode`·`localAreaCode` 를 비워야 한다(`search` 기본값이 전국).
- **같은 모델, 다른 판매처**: 같은 모델번호가 수십 곳에 있다. 제조사 직판은 대체로 비싸고 납품 30~45영업일. 모델번호로 다시 검색하면 더 싸고 빠른 판매처가 나온다.
- **견적서 유효기간**: 판매처마다 1주~1달로 다르다. 짧은 것은 사용자에게 날짜를 알리고 처리기록 "남은 일"에 적는다.
- **조건부 무료배송**: "5만원 미만 배송비" 기준이 **공급가(부가세 제외)** 였다. 판매가 합계가 5만원을 넘어도 배송비가 붙을 수 있으니 담은 뒤 `cart` 의 제시금액·배송비를 본다.
- **에듀파인 연계 엑셀에는 배송비가 없다** → 품의에 배송비 행(단위 "식")을 따로 넣는다.
- **견적서 삭제**는 견적접수코드(`cart` 첫 칸)로 한다. 수의시담 중이거나 에듀파인 연계된 물품은 사이트가 거부한다.
- **Chrome 재시작**: 사용자 Chrome 이 작업 중 재시작되면 탭 id 가 바뀐다. 복원된 탭은 로드 전이라 응답이 없을 수 있으니 새 탭을 연다(도구가 자동 처리). S2B 로그인 세션은 남아 있었다.

## 4. 오픈마켓 (S2B 에 없을 때)

- **G마켓**: 학교 구입 가능(사용자 확인). 상세 페이지의 옵션 목록(`select option`)에 옵션별 가격이 그대로 나온다. 국내배송·원산지 표시를 확인한다.
- **네이버 스마트스토어**: 학교에서 구입이 안 된다(사용자 확인). 자동으로 여러 번 열면 로그인 화면으로 막힌다.
- 같은 중국산 구매대행 상품이 여러 오픈마켓에 같은 옵션 구성으로 올라와 있는 경우가 많다. 옵션 이름으로 같은 상품인지 확인할 수 있다.
- 품의에는 S2B 물품과 함께 넣을 수 있다(품명·규격에 쇼핑몰 상품번호와 옵션, 비고에 판매처). 결제 방법은 행정실과 맞춘다.

## 5. 에듀파인 품의

### plan.json 예시 (값은 가짜)
```json
{
  "title": "2026학년도 ○○ 동아리 운영 체육교구 보관대 구입",
  "summary": "1. 관련: ○○학교-1234(2026. 3. 13.)\n2. 2026학년도 ○○ 운영에 필요한 체육교구 보관대를 다음과 같이 구입하고자 합니다.\n  가. 산출내역: ○○ 보관대 외 1종(품의명세서 참조)\n  나. 용도: ○○ 보관 및 이동\n  다. 구매방법: S2B(학교장터) 1인 수의계약\n  라. 소요예산: 금920,000원(금구십이만원)\n  마. 선정 사유: 내구성과 보관 수량을 고려하여 국내 제조 제품 중 S2B 최저가 판매처를 선정함\n\n붙임  지출(지급)품의서 1부.  끝.",
  "budgets": ["[추가]공모동아리(○○)"],
  "items": [
    {"budget": 0, "name": "○○ 이동식 보관대", "spec": "모델/규격", "qty": 1, "unit": "대", "price": 540000, "s2b": "<S2B 물품번호>", "rm": "S2B <판매처>"},
    {"budget": 0, "name": "배송비(○○)", "spec": "", "qty": 1, "unit": "식", "price": 4000, "rm": "S2B <판매처>"}
  ]
}
```
- `budgets` 는 `budgets` 명령 출력의 산출내역 이름 그대로. 예산이 둘 이상이면 `items[].budget` 으로 나눈다. 재원이 둘이면 개요에 "재원별 내역"을 넣는다.
- 금액 한글 표기: 920,000 → 금구십이만원, 1,155,840 → 금일백일십오만오천팔백사십원.
- 개요는 2000바이트 제한(위 예시 수준이면 약 1,000바이트).

### 에듀파인 화면에서 알게 된 것
- 품목은 **선택한 예산 행으로 걸러져** 보인다. 예산 행을 고른 뒤 [행추가]를 하면 그 예산 코드가 든 행이 생긴다.
- 저장하면 **"결재요청 하시겠습니까?" 확인창**이 뜬다. 자동화는 [취소]로 닫는다. 결재요청은 사용자가 화면을 보고 누른다.
- 저장한 품의를 고칠 때(같은 창에 품의가 열려 있는 상태):
  - 품목·예산 행을 지우면 바로 사라지지 않고 **삭제 표시(RowType 8)** 로 남았다가 저장할 때 반영된다.
  - 화면의 합계 함수 `fnExpectAmtCreat`·[행삭제]는 **삭제 표시된 행까지 더해** 예산 요구액이 줄지 않는다. 남은 행 합계로 `dmndAmt` 를 직접 맞춘 뒤 저장해야 한다(`fill` 은 자동으로 다시 계산).
  - 품목을 다시 넣을 때도 같은 창에서 예산 행 선택 → [행추가] → 값 입력 → 요구액 맞춤 → 저장하면 된다(새 행은 RowType 2).
  - 다시 저장해도 품의번호는 그대로다. 저장 뒤 품의목록 금액으로 확인한다.
- 품의저장 단계에서는 예산 잔액이 줄지 않는다(결재 뒤 반영).
- 품의목록 창(같은 메뉴 id)의 내용이 품의등록 화면으로 바뀌어 있는 일이 있었다 → 도구는 화면 내용(grdMain/divMain)으로 창을 확인하고, 다르면 닫고 다시 연다.

## 6. 관리자(교장) 보고 안내문 양식

```
교장선생님께,

○○ 예산 잔액으로 ○○를 구입하려고 합니다. 제품과 가격을 아래와 같이 알려 드립니다.

■ 예산
 - <예산 이름> 잔액: <금액>원 (관련: <학교>-<번호>, YYYY. M. D.)

■ 구입 예정 물품 (배송비 포함)
1. <품목> - <제조사> <모델> (<핵심 사양>)
   <단가>원 × <수량> = <금액>원 / 학교장터(S2B), 판매처 <판매처>, S2B물품번호 <번호>
   https://www.s2b.kr/S2BNCustomer/rema100.do?forwardName=detail&f_re_estimate_code=<번호>
   제조사 사양: <제조사 제품 페이지>

■ 합계: <합계>원 / 예산 <잔액>원 이내

■ 선정 이유
 - <내구성·보관 수량·납품기간·최저가 판매처 등>
```
메신저에 바로 붙여 넣을 수 있게 클립보드에 복사하고, 업무 폴더에 txt 로도 저장한다.
