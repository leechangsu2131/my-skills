# 설계 메모 (왜 이렇게 만들었는지)

## 시트 구조와 연결
| 시트 | 역할 | 입력 여부 |
|---|---|---|
| 설정 | 공간·교시·분류·상태·이동구분·보관 장소 목록 (모든 드롭다운의 원천) | 관리자 |
| 사용신청 | 사용일·교시·공간·신청자·용도. H열 중복체크, I열 키(`공간|날짜|교시`), J열 표시 문구는 수식 | 신청자 |
| 기물대장 | 기물 1줄 1개. I열 '현재 위치'는 이동수리이력의 마지막 '이동 후 장소'를 찾는 수식, M열은 장소별 목록용 보조 열 | 관리자 |
| 이동수리이력 | 일자·관리번호·구분·이동 후 장소·내용. 아래쪽(최신) 이동이 현재 위치가 됨 | 관리자 |
| 주간표 / 전체현황 / 기물위치 | 보기 전용. `INDEX/MATCH`로 사용신청·기물대장을 조회 | 없음 |
| 배치 | 3D 웹앱용 블록 위치·크기 (공간, 시작층, 끝층, X, Y, 가로, 세로, 높이(선택)). 건물의 모든 방을 넣을 수 있음 | 관리자 |

- 조회는 `공간|날짜|교시` 키 하나로 `MATCH`한다. 배열 수식(TEXTJOIN/FILTER)을 쓰지 않는 이유는 엑셀·구글 시트·LibreOffice 어디서든 같은 결과가 나오게 하기 위해서다. 단점은 한 칸에 첫 신청 1건만 보인다는 것이고, 중복은 사용신청 시트에서 빨갛게 표시해 해결한다.
- 수식은 사용신청 500행, 기물대장·이동수리이력 1000행까지 미리 채워 둔다. 더 필요하면 마지막 행을 아래로 복사한다.
- 파란 글씨=입력, 회색 칸=자동, 노란 칸=보기 조건 선택. 이 색 규칙을 안내 시트에 적어 두면 비전문가도 실수가 줄어든다.

## 기물 대여·승인·본인 확인·관리자 (교사용 입력 기능)
- **사람 구분**: 접근 코드 + 신청자 명단 + **개인 PIN(숫자 4~8자리)**. PIN은 `교직원PIN` 시트(숨김)에 salt + SHA-256 해시로만 저장하고, 같은 이름으로 10분에 5번 틀리면 잠근다(CacheService). PIN이 필요한 일: 기물 대여 신청·반납·취소, 내 신청 조회, 공간 신청 취소. 공간 신청 자체는 PIN 없이 가능하다(기존 흐름 유지). 이름을 먼저 정한 사람이 PIN을 가지므로, 처음 쓰기 전에 관리자가 명단과 PIN 정하기를 안내하고, 잊으면 관리자가 초기화한다.
- **기물 대여**(`대여신청` 시트, 서버가 한 줄씩 기록): 상태가 '양호'이고 분류가 대여 가능 분류(설정 J열)인 물품만. 대여 가능 수량 = 전체 수량 − (같은 기간과 겹치는 '승인대기·승인' 대여 수량). 수량이 남으면 **자동 승인**. 대여일은 오늘 이후, 한 번에 30일까지. 반납은 본인이 처리(또는 관리자), 시작 전이거나 대기 중인 대여만 취소 가능. 반납예정일이 지나도 '승인' 그대로면 연체로 본다(시트에서 빨강, 관리자 화면에 표시).
- **공간 승인**: 설정 K열 '승인 필요 공간'(예: 강당·운동장)은 신청하면 사용신청 K열 상태가 '승인대기'가 되어 그 시간을 막고, 관리자가 '확정'/'반려'로 처리한다. 반려·취소된 행은 키 수식(I열)이 비어 시간이 다시 열린다. 표시에는 ⏳가 붙는다.
- **내 신청**: 이름 + PIN으로 확인한 뒤 내 대여(반납·취소)와 앞으로의 공간 신청(취소)을 본다.
- **관리자**: 스크립트 속성 `ADMIN_CODE`가 있어야 열린다(없으면 기능 자체가 거절). 화면에서 승인 대기(공간·대여), 오늘 반납 예정, 연체, 대여 중, 대여 예정, PIN 초기화를 처리한다. 시트에서 상태 칸을 직접 고쳐도 같다. 관리자 코드는 접근 코드와 별개로 둔다.
- 한계: 개인 구글 계정 환경이라 구글 계정으로 사람을 확인하지 못한다. PIN은 '이름을 사칭하는 실수'를 막는 정도이고, 코드와 PIN이 새면 뚫린다. 자원이 커지거나 동시 신청이 많아지면 Supabase 같은 DB로 옮긴다.
- 시험: `scripts/test_server.js`(저장소 루트에서 `node scripts/test_server.js`)가 PIN·대여·승인·관리자 규칙 49가지를 가짜 시트로 확인한다.

## 통합 검색 (방 + 물품)
- 웹앱 위쪽 검색칸 하나로 **방 이름과 물품**을 함께 찾는다(`/` 키로 포커스, ↑↓ Enter Esc). 입력하는 대로 드롭다운에 '방'과 '물품(품명별 묶음)'이 나오고, 비어 있으면 최근 검색 6개를 보여 준다.
- 일치 규칙(`searchAll`): 띄어쓰기·괄호·기호 무시, 앞부분 일치 > 포함 > **초성**(예: ㅂㅍㄹㅈㅌ → 빔프로젝터). 물품은 품명(가중 3), 관리번호(3), 분류(2), 규격·담당자·비고(1) 순으로 점수를 주고 품명별로 묶어 총 수량·위치별 개수·⚠(수리필요·수리중·분실)를 보여 준다. 방 이름은 물품 위치(loc)로는 찾지 않는다(방은 방 목록으로 찾음).
- 물품을 고르면 물품 모드로 바뀌어 그 물건이 있는 방이 3D에 표시되고, 한 방에만 있으면 그 방으로, 한 층에만 있으면 그 층으로 이동한다. 여러 층이면 건물 외관의 층 배지에 '3층 물품 12개 · 2곳'이 나오고 눌러 들어간다. 패널에는 품명별로 위치 칩(`공간 ×개수`)이 묶여 나오고, 칩을 누르면 그 방으로 간다. 3D 배치에 없는 장소(창고 등)는 눌리지 않는 칩으로 보여 준다.
- 학생 화면에서는 방(학생 개방 공간)만 검색한다.
- 시트의 '기물위치'에도 같은 검색이 있다: M1에 단어를 쓰면 품명·관리번호·분류·규격·담당자·비고에서 일치하는 물건을 20건까지 표로 보여 준다(기물대장 O열 보조번호 + `INDEX/MATCH`, 대소문자 무시).

## 기물 관리 보기 (입력은 시트, 웹앱은 보기 전용)
- 사용자가 '시트 방식으로 충분하고 보기만 좋게'를 택했다. 그래서 물건 등록·이동·상태 변경은 기물대장·이동수리이력 시트에서만 하고, 웹앱은 읽기만 한다(편집 기능은 요청이 있을 때 추가).
- 시트: `기물요약`(분류 × 상태 수량표 + '점검이 필요한 물건' 40건 — 기물대장 N열 보조번호로 `INDEX/MATCH`), 기물대장 상태 색(수리필요·수리중=노랑, 분실=빨강, 폐기=회색).
- 웹앱 물품 모드: 분류·상태 선택과 품명·관리번호 검색(필터), 필터에 맞는 수량으로 방 색을 칠함(상태가 수리필요·수리중·분실이면 주황 계열), 라벨에 ⚠(점검 필요 물건 수). 방을 선택하지 않았을 때의 패널 = 요약(종·개수, 분류별 막대, 상태 칩 — 누르면 상태 필터) + 점검이 필요한 물건 + 검색 결과 + 물품이 있는 장소 목록. 방 상세 = 분류별 묶음, 물건을 누르면 관리번호·규격·취득일·담당자·최초/현재 위치·비고와 이동·수리 이력(`getItemHistory`, 한 번 불러오면 캐시). 위치가 3D 배치에 없는 물건(창고 등)은 방 이동 없이 보여 준다.
- 취득가는 웹앱으로 보내지 않는다(필요 없고 민감하다). 담당자 이름은 교사용 화면에만 있고 학생 화면에는 물품 정보 자체를 보내지 않는다.

## 정규 수업(고정시간표)
- 학교 교육과정 문서(시정표, 특별실 사용표, 전담 시간표)가 있으면 `고정시간표` 시트로 옮긴다: `[공간, 요일, 교시, 내용(예: 6-1 과학)]`. 매주 반복되는 칸이며, ① 교사 신청은 서버(`submitRequest`)와 시트(`⚠정규수업과 겹침`)에서 막고 ② 전체현황·주간표·교사 3D 사용 현황에 '정규 …'로 보이고 ③ 학생 화면에서는 선생님 수업 시간(파랑)으로 보이며 학생 사용 시작도 거절·시간 단축 대상이다.
- PDF 표는 텍스트로 뽑으면 요일 칸이 뭉개진다. 해당 쪽을 이미지로 변환해(`pdftoppm`) 눈으로 읽고, 반별 시수(전담 시간표)와 합이 맞는지 교차 검증한다(이번에는 학급별 주당 시수가 모두 일치).
- 읽을 때 주의: **색칠된 칸만 실제 사용**이다(흰 칸의 '61실'은 '실과 시간이라 이 방을 안 쓴다'는 표기). 강당 표와 운동장 표가 같은 시간대로 겹치면(우천 시 대체 등) 두 곳 모두 '체육 수업 중'으로 둔다. 5교시 칸의 '1~2학년/3~6학년'처럼 요일이 불분명한 표기는 넣지 말고 사용자에게 알린다.
- 교사 이름은 시간표에 있어도 옮기지 않는다(학급·교과만). 시정표(교시별 시각)는 `periods`에 반영한다. 방과후 시각처럼 문서에 없는 값은 예시라고 알린다.

## 방과후·돌봄 프로그램 시간표 (hwpx)
- 방과후·돌봄 시간표(예: 맞춤형·선택형 프로그램)도 `fixed_schedule`에 같은 형식으로 넣는다. 내용 앞에 '정규' 또는 '방과후'를 붙여 구분한다(예: `방과후 선택형 아이돌댄스 2부`). 서버·시트·학생 화면은 내용을 그대로 보여 준다.
- 한글 파일(.hwpx)은 ZIP 안의 XML이다. `scripts/hwpx_tables.py`로 표를 격자로 뽑고, **요일 머리글 칸의 시작 열 → 다음 요일 시작 열 전까지**를 그 요일의 열 범위로 삼아 '장소' 행과 바로 아래 '프로그램' 행을 짝지어 읽는다(한 요일에 같은 시간대 프로그램이 여러 개면 하위 열이 여러 개다). '정규수업' 칸은 프로그램이 없다는 뜻이므로 넣지 않는다.
- 프로그램은 시간 칸(예: 13:50~14:30)으로 적혀 있으므로 `periods`에 같은 시각의 교시를 둔다(5교시·6교시·방과후1·방과후2). 문서의 방 이름이 배치에 없으면(예: 도담마루) 임의로 짝짓지 말고 사용자에게 어느 방인지 묻는다. 방과후는 기수마다 바뀌므로 새 기수가 시작되면 표를 갱신하도록 알린다.

## 3D에서 수업을 한눈에 (교사용 사용 현황)
- **종류별 색**: 정규 수업 = 파랑, 방과후·돌봄 = 보라, 교사 신청 = 초록, 비어 있음 = 회색. 종류는 서버가 주는 `fixed` 표시와 내용 앞 글자('방과후…')로 가른다(`useKind`). 방 이름표에는 접두어를 뗀 짧은 내용(`6-1 과학`, `놀이스포츠 1부`)을 쓴다.
- **시간 이동**: 교시 ◀ ▶ 버튼과 `,` `.` 키, '지금'(오늘 날짜 + 현재 시각의 교시로 이동), '하루 재생'(1.6초마다 교시를 넘기며 건물 전체의 변화를 보여 줌). 교시 시각은 설정 시트에서 온다.
- **요약과 표**: 방을 고르지 않았을 때 패널 위에 '정규 수업 n · 방과후 n · 교사 신청 n · 비어 있음 n' 칩과 층별 목록(종류 색 점 + 내용), 표로 보기는 같은 색, 방 상세에는 '이번 주 시간표'(월~금 × 교시, `getRoomTimetable`: 정규 + 방과후 + 그 주 신청, 신청이 같은 칸의 고정 일정보다 우선).
- 학생 화면에는 이 종류별 색을 쓰지 않는다(수업·프로그램을 '선생님 수업·프로그램' 하나로 보여 준다).

## 신청 규칙 (겹침 방지)
- **신청할 수 없는 방이 처음부터 있다**: 교무실, 교장실, 행정실, 방송실, 보건실, 창고, 학급 교실 등. 기준은 설정 시트 '공간'(A열)이다 — 여기에 있는 방만 신청 대상이고, 나머지는 3D에는 보이되 신청할 수 없다. 화면(드롭다운·버튼)만 막지 말고 **서버(`submitRequest`)도 `bookable_()`로 거절**한다(요청을 직접 만들어 보내는 경우를 막기 위해). 신청 불가 방을 누르면 이유를 말해 준다(행정·지원실/학급 교실/기타). 행정·지원실 라벨에는 🔒를 붙인다. `build_sheet.py`는 `spaces`에 행정·지원실로 보이는 이름이 들어 있으면 경고한다.
- 어느 방을 신청 대상으로 둘지는 학교가 정한다. 돌봄·늘봄교실, 게더링스테어 같은 곳은 학교마다 달라서 임의로 정했다면 알리고 확인한다.
- **같은 공간·날짜·교시**는 누가 신청했든 막는다(`공간|날짜|교시` 키).
- **같은 사람이 같은 날짜·교시에 다른 공간**도 막는다(본인 시간 겹침). 서버(`submitRequest`)가 신청 직전에 시트의 기존 기록과 대조하며, 화면은 그날 불러온 기록으로 먼저 안내만 한다(최종 판정은 항상 서버). 동시에 두 명이 눌러도 LockService로 한 줄씩 처리한다.
- 사람 식별은 이름 문자열이다. 오타와 띄어쓰기로 우회되지 않도록 ① 공백을 제거해 비교하고 ② 설정 시트 H열 '신청자 명단'을 채우면 신청 화면에서 목록 선택으로 바꾸고 명단 밖 이름은 거절한다. 명단이 비어 있으면 직접 입력을 허용한다(대신 우회 가능성이 남는다고 알린다).
- 시트에서 직접 입력한 기록도 사용신청 H열이 '⚠중복'(같은 공간) 또는 '⚠본인중복'(같은 사람·같은 시간)으로 빨갛게 표시한다.
- 같은 이름의 교사가 둘이면 구분되지 않는다. 명단에 '김교사(3학년)'처럼 구분되는 이름으로 적게 안내한다.
- 필요하면 지난 날짜 신청 금지, 하루 신청 횟수 제한 같은 규칙도 같은 자리(`submitRequest`)에 추가한다. 사용자가 요청하기 전에는 임의로 넣지 않는다.

## 학생용 빈 교실 찾기 · QR 사용 시작
- 같은 웹앱을 `?mode=student`로 열면 학생 화면이 된다(교사 이름·신청·물품 정보 없음). 교실 문 앞 QR = `웹앱주소?mode=student&room=방이름[&c=학생코드]`. 서버 `doGet(e)`가 주소 매개변수를 `Index.html`의 `/*__PARAMS__*/{}/*__END__*/` 자리에 넣어 준다(화면은 iframe 안이라 주소를 직접 읽을 수 없다).
- 시트: 설정 I열 = 학생 개방 공간, `학생사용` = 학생 활동 기록(시작, 공간, 학급·별명, 활동, 종료예정, 종료(실제)). 앱이 `appendRow`로 쌓으므로 미리 수식을 넣지 않는다. 기록은 학기말에 보관하고 비운다.
- 상태 판정(서버): 지금 시각이 선생님 신청 교시(설정 시트의 교시 시간 'HH:MM-HH:MM') 안이면 `teacher`, 진행 중인 학생 기록(종료 안 함 + 종료예정 이전)이 있으면 `student`, 아니면 `free`. 다음 선생님 신청 시작 시각을 `next`로 알려 준다.
- 사용 시작 규칙: ① 선생님 신청 시간 중이면 거절 ② 같은 방에 진행 중인 기록이 있으면 거절 ③ 같은 학급·별명이 다른 방을 쓰는 중이면 거절(먼저 '다 썼어요') ④ 요청한 시간이 다음 선생님 신청과 겹치면 그 시작 시각까지로 줄이고 안내 ⑤ 이름은 12글자 이하(실명 방지 안내) ⑥ LockService로 동시 요청을 한 줄씩 처리.
- 요일별 패턴(`getRoomWeek`): 이번 주 월~금 선생님 신청(파랑) + 최근 4주 학생 활동 횟수(초록 농도). 활동도 신청도 없던 칸은 '대체로 비어 있는 시간'으로 모아 보여 준다.
- 화면: 비어 있는 방은 초록 + 반짝임(체크박스로 끔), 학생 활동 중은 주황, 선생님 신청은 파랑. 층 배지는 '빈 교실 n/m'. 30초마다 자동 갱신하되 입력 중에는 패널을 다시 그리지 않는다. 학생이 방에서 QR을 찍어 들어오면 그 방이 선택되고 사용 시작 양식이 열린다.
- 개인정보: 학생 화면에는 선생님 이름과 학생 활동 기록의 학급·별명을 보내지 않는다(상태와 활동 종류만). 실명을 받지 않고, IP나 위치는 수집하지 않는다. 접근 코드(`STUDENT_CODE`)는 QR에 함께 인쇄되는 '아는 사람만' 수준의 보호다.
- 한계: 학생이 QR을 사진으로 공유하면 교실 밖에서도 시작할 수 있다. 위치를 정확히 확인하려면 현장 확인형 문제(교실 안 숫자 입력 등)를 더해야 한다. 한꺼번에 접속하는 학생이 많으면 Apps Script 동시 실행 한도에 걸릴 수 있어 반별로 나눠 시작한다.

## 3D 웹앱 (Apps Script)
- 시트에 **연결된(container-bound) 스크립트**여야 `SpreadsheetApp.getActiveSpreadsheet()`로 시트를 읽는다. 시트에서 확장 프로그램 → Apps Script로 열어야 한다.
- 시트 이름(설정, 배치, 사용신청, 기물대장)과 열 위치를 Code.gs가 그대로 가정한다. 열 순서를 바꾸면 Code.gs도 고친다.
- 서버 함수: `getData(code, dateStr)`는 배치·교시·그날 사용 신청·기물 목록을 한 번에 반환, `submitRequest(code, p)`는 LockService로 잠근 뒤 중복을 검사하고 사용신청의 첫 빈 행에 쓴다. 사용신청에는 수식이 미리 들어 있으므로 `appendRow`를 쓰지 말고 A, B, D~G열만 개별로 쓴다(C·H·I·J 수식을 지우지 않기 위해).
- 층은 `(시작층-1)*6`(FH=6) 높이에서 시작하고, 블록 높이는 `(끝층-시작층)*6+3`(또는 직접 적은 높이)이다. 층 사이를 넉넉히 띄워 '전체' 보기에서도 층이 구분되게 한다. 같은 X·Y를 쓰면 위층에 겹친다. 층 선택 드롭다운은 그 층 범위에 걸치는 방을 모두 보여 준다(여러 층 공간은 각 층에서 보임).
- `getData`는 `bookable`(설정 시트 A열 = 신청 대상 공간)을 함께 돌려준다. 배치에는 있지만 bookable에 없는 방은 신청 버튼·일정표 없이 물품 위치만 표시한다. 표로 보기도 신청 대상 공간만 나온다.
- **가독성 원칙(방이 많을 때)**: ① 층 내부 화면은 '모든 방 보기'가 기본으로 켜져 있어 학급 교실·행정실·교장실 등 신청 대상이 아닌 방도 보인다(종류별 색: 신청 대상=사용 상태 색, 학급 교실=연한 파랑, 행정·지원실=연한 갈색, 기타=연한 회색). 끄면 신청 대상 방만 남는 '집중 보기'가 된다. 처음에 숨기는 쪽을 기본으로 했다가 '교무실·학급 교실이 안 보인다'는 지적을 받았다. 숨기는 것은 사용자가 요청할 때만 한다. ② 층마다 바닥판과 'N층' 이름표를 깐다. ③ 층 버튼을 누르면 그 층만 보이고 카메라가 그 층을 위에서 내려다보는 각도로 이동한다. ④ 3D 블록 라벨은 호수를 뺀 짧은 이름만 쓴다. ⑤ 오른쪽 패널의 기본 화면은 '선택한 교시의 층별 방 목록'(사용 중/비어 있음 색 점 + 사용자)이며, 목록을 눌러도 3D에서 고른 것과 같다. ⑥ 표로 보기도 층별로 묶는다. 3D만으로 모든 정보를 읽게 만들지 말고 목록·표를 함께 둔다.
- 방이 150개 이상이면 3D 라벨이 겹치므로, 전체 층 보기에서는 신청 대상 방(과 선택한 방, 물품 모드에서는 물품이 있는 방)만 라벨을 켜고 층을 고르면 해당 층 라벨을 모두 켠다.
- **건물 외관(`buildShell`)**: 방 블록만 늘어놓으면 '상자 모음'으로 보인다. 층마다 방들이 차지한 칸을 1칸 격자에 찍고, 팽창 2칸 → 침식 2칸(모폴로지 닫기)으로 방 사이 작은 틈을 복도로 메워 건물 영역을 구한 뒤, ① 영역 전체에 바닥 슬래브, ② 영역 경계를 따라 이어 붙인 바깥벽(창문 무늬 캔버스 텍스처를 `uv.u *= 길이/4`로 반복), ③ 지붕을 만든다. 층 높이는 FH=4(층고 3.6 + 슬래브 0.4)로 붙여 쌓는다. 영역을 칸 단위로 합치기 때문에 방 크기가 개략적이어도 건물 윤곽이 자연스럽게 나온다.
- **보기 방식**: '전체' = 외관(방은 숨기고 건물, 지붕, 층 배지 '3층 사용 7/12'만 표시, 건물이나 배지를 누르면 그 층 내부로 이동). '○층' = 그 층까지만 보여 주고 위층은 제거, 선택한 층은 지붕을 열고 바깥벽을 낮춰(scale.y 0.56) 내부 방을 본다. 운동장처럼 높이 1 미만인 바닥판은 건물에서 제외하고 항상 보인다.
- **분위기**: 하늘 그라데이션(CSS), 반구광 + 그림자 있는 직사광(PCFSoft, 2048), 땅과 나무, 시점 관성(`enableDamping`). 쓰는 재질은 건물은 `MeshStandardMaterial`, 방·나무는 `MeshLambertMaterial`.
- **걸어 다니기(미구현)**: 1인칭 이동·충돌까지 가려면 PointerLock + 벽 AABB 충돌이 필요하다. 이동 속도와 충돌을 시험하기 어려우니 요청이 있을 때 별도 모드로 추가한다.
- **방 모양**: 상자 대신 '지붕 없는 방'으로 그린다(`buildRoom`): 상태 색 바닥 + 4면 벽(앞쪽에 문 틈) + 칠판, 신청 대상이고 충분히 크면 책상 몇 개. 지붕을 없애야 위에서 내려다볼 때 안이 보인다. 여러 층 공간은 벽을 높이의 70%로, 운동장처럼 높이 0.6 미만이면 바닥만 그린다. 클릭 판정은 보이지 않는 `hit` 상자(재질 `visible:false`)로 하고, 방이 숨겨졌을 때는 목록에서 제외한다. 반투명(유령) 처리는 방이 가진 재질 전체에 건다.
- **시점 조작**: 마우스는 **왼쪽 드래그 = 이동(땅 위에서 지도처럼, `screenSpacePanning=false`), 오른쪽 드래그 = 회전, 휠 = 확대**, Shift+왼쪽 = 회전. 터치는 한 손가락 회전·두 손가락 확대/이동. 키보드는 WASD·방향키(이동), QE(회전), +−(확대), R(초기화), T(위에서 보기), 0~9(층), ?(도움말), Esc. 화면 오른쪽 아래에 같은 동작의 버튼(＋ − ⟲ ⟳ ▦ ⌂ ?)이 있어 마우스가 없는 기기에서도 쓴다. 왼쪽 클릭이 이동에 쓰이므로 방 선택은 '눌렀다 떼는 사이 움직임 6px 이하'일 때만 클릭으로 본다. 오른쪽 버튼은 선택에 쓰지 않는다.
- **터치(태블릿)**: 마우스 버튼이 없으므로 '왼쪽 드래그 = 이동, 오른쪽 드래그 = 회전'과 같은 뜻으로 **한 손가락 = 이동, 두 손가락 = 확대 + 회전**(`TOUCH.PAN` / `TOUCH.DOLLY_ROTATE`)을 기본으로 한다. 화면 버튼 '☝이동/☝회전'으로 한 손가락 동작을 회전(`ROTATE` / `DOLLY_PAN`)으로 바꿀 수 있고 설정은 기기에 저장한다. 터치 기기에서만 이 버튼을 보인다(`maxTouchPoints`). 캔버스에 `touch-action:none`을 줘서 브라우저 스크롤·확대와 겹치지 않게 하고, 더블클릭이 어려우니 방 상세 패널에 '🎯 이동' 버튼을 둔다. 손가락에는 마우스 올리기(호버)가 없어서 말풍선 대신 방을 탭해 패널로 확인한다.
- **편의 기능**: 방 찾기 입력(datalist, 부분 일치 → 그 층으로 이동 + 방으로 날아감), 더블클릭하면 그 방으로 이동, 마우스를 올리면 방 이름·상태 말풍선과 테두리 강조, 시점 이동은 0.65초 부드러운 애니메이션(사용자가 조작을 시작하면 즉시 중단), 패널 접기/펴기 버튼, 처음 한 번만 조작 안내. 카메라 보조 함수(`zoomBy/rotateBy/moveBy/topDown`)는 three.js 수학으로 단위 시험할 수 있다(거리 제한, 회전 시 높이 유지, 땅 위 이동, 위에서 보기 왕복).
- 클릭과 드래그 구분: pointerdown/up 사이 이동량이 6px 이하일 때만 선택으로 처리한다(모바일 회전과 충돌 방지).
- three.js는 jsDelivr의 `three@0.128.0`(전역 빌드) + `examples/js/controls/OrbitControls.js`를 쓴다. 버전을 올리면 OrbitControls 경로와 전역 방식이 달라진다.

## 접근 제어 (학교 도메인이 아닌 경우)
- 개인 구글 계정 환경에서 '나로 실행'으로 배포하면 `Session.getActiveUser().getEmail()`이 비어 있어 이메일 허용 목록을 쓸 수 없다. 그래서 스크립트 속성 `ACCESS_CODE`를 대조하는 간단한 접근 코드 방식을 쓴다(코드는 브라우저 localStorage에 저장).
- '사용자로 실행'으로 바꾸면 이메일 기반 제어와 시트 권한을 쓸 수 있지만, 선생님마다 시트 권한과 '확인되지 않은 앱' 승인 화면을 거쳐야 해서 비전문가에게는 부담이 크다.
- 학교 Workspace 도메인이면 배포 설정에서 '도메인 내 사용자'로 제한하는 편이 가장 안전하다.
- 시트에는 교사 이름·용도·물품 정도의 가벼운 정보만 둔다. 학생 개인정보는 넣지 않는다.

## 대화 안에서 미리보기를 보여 줄 때
- 대화 안에서 게시하는 페이지는 외부 사이트(구글 시트 포함)를 읽지 못한다(보안 정책). 그래서 미리보기는 `scripts/make_preview.py`로 가짜 `google.script.run`과 샘플 데이터를 넣은 단일 HTML을 만들어 게시한다.
- 게시 페이지 규칙: 라이브러리는 고정 버전 `<script>`로만, `viewport-fit=cover`와 안전 영역 여백, 색은 CSS 변수로 두고 다크 모드 값을 따로 정의한다(make_preview.py가 처리).

## 배포 체크리스트
1. xlsx를 드라이브에 올려 구글 시트로 열기 → 배치 시트를 실제 학교 구조로 수정
2. 확장 프로그램 → Apps Script → Code.gs, Index.html 붙여 넣기
3. 프로젝트 설정 → 스크립트 속성 `ACCESS_CODE` 추가
4. 배포 → 웹 앱 → 실행 주체 '나', 액세스 권한 선택 → 링크 공유
5. 코드 수정 후에는 '배포 관리'에서 새 버전으로 다시 배포
6. 시트 편집 권한은 관리자만. 선생님은 웹앱으로만 보고 신청

## 엑셀 배치도 읽기 메모
- 층이 시트에 세로로 이어진 도면은 층 글자(1층, 2층 …)가 구역 안쪽에 있고 구역 높이가 일정(예: 28행)한 경우가 많다. 시트를 PDF로 변환해 이미지로 보면 구역 경계를 가장 빨리 확인할 수 있다(LibreOffice `soffice --headless --convert-to pdf`, 인쇄 영역과 한 페이지 맞춤 설정 후 `pdftoppm`).
- 호수는 100 이상 숫자 칸, 이름은 글자 칸으로 읽는다. 이름-호수는 같은 줄 오른쪽 / 이름 위 / 이름 아래 숫자를 짝으로 보지만 손으로 그린 도면은 어긋나는 경우가 많다. 반드시 사용자에게 확인한다.
- '1-1', '3-2' 같은 학급 표기를 엑셀이 날짜로 바꾸는 일이 흔하다(월-일로 되돌림). '2(영양,조리실)'처럼 숫자와 괄호가 붙은 표기는 방 개수 표기일 수 있어 추정으로 다룬다.
- 같은 시트에 하자 접수 대장, 칠판장, 누수 현황 등이 함께 있는 경우가 있다. 실 이름을 '실 명(실 번호)' 형태로 적는 관행이 있으므로 방 이름을 `이름(호수)`로 만들면 나중에 하자·점검 기록과 연결하기 쉽다.

- 배치도에 없는 외부 공간(운동장, 주차장, 놀이터 등)은 하자·점검 시트 같은 다른 자료에 이름만 나오는 경우가 많다. 위치를 임의로 정했다면 임의 배치라고 알리고 방향(예: 건물 오른편)을 사용자에게 확인한다.

## 3D 프린터용 모형 (STL)
- `scripts/make_stl.py`가 layout에서 층별 STL을 만든다(1:200이면 1칸=5mm, 층고 18mm). 층마다 바닥 3mm + 바깥벽 1.2mm + 방 칸막이 1.0mm(문 틈 포함) + 층 맞춤 핀/홈 4쌍 + 밑면 층 번호 음각. 여러 층 공간은 위층 바닥에 구멍 + 낮은 난간. 지붕은 없다(들어 올려 내부를 보는 돌하우스).
- 건물 윤곽은 웹 3D와 같은 방식(방이 차지한 칸을 팽창·침식으로 메움)이다. 불리언은 `manifold3d`, 2D 도형은 `shapely`. 생성 후 반드시 닫힌 입체(watertight) 여부와 출력 크기를 점검하고 `report.json`으로 남긴다.
- 사용자가 출력 크기를 모르면 일반적인 220×220mm(`--bed 210`) 기준으로 시작한다. 안 맞으면 `--scale`을 키운다.
- 개략 배치를 굳히는 작업이므로 '개략 모형'임을 밝히고, 슬라이서 확인과 출력은 사용자가 해야 한다. 창문·책상·글자는 해상도가 안 나와 뺀다.
- 파일 시스템이 대화 도중 초기화될 수 있으니(작업 폴더가 비는 경우) 스킬 패키지와 outputs의 설정 파일로 복원할 수 있게 둔다.
