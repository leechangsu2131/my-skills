# i-scream 과목별 평가 자동화 개발 및 검증 기록 (ing.md)

이 문서는 개발자가 스킬을 작성하고 로컬에서 검증한 상세 디버깅 및 보완 내역을 기록하는 히스토리 파일입니다.

## 1. 2026-06-16: 초기 빌드 및 기동 문제 해결
- **문제 현상**: `launch_chrome_iscream.bat` 더블클릭 시 도스 창이 바로 꺼지거나 크롬이 실행되지 않는 현상 발생.
- **분역 및 진단**:
  - Unix 스타일(`LF`) 줄바꿈 문자로 저장되어 윈도우 `cmd.exe`에서 괄호 `()` 구문을 읽지 못하고 구문 오류(`The syntax of the command is incorrect`) 발생.
  - 일반 실행 중인 기존 크롬 인스턴스가 존재할 경우, 새 프로필 실행 인수가 무시되고 기존 브라우저 탭으로 위임된 뒤 디버그 인스턴스가 즉시 종료됨.
- **조치 사항**:
  - 배치 파일 인코딩 및 줄바꿈 타입을 `CRLF`로 강제 변경.
  - 배치 파일 내 괄호 내부의 특수 문자(`(64-bit)`)에서 괄호 제거.
  - 크롬 기동 명령어에 `--new-window` 플래그를 추가하여 기존 세션에 흡수되지 않고 항상 독립된 창으로 켜지도록 강제함.
  - 프로세스 락(Lock)을 방지하기 위해 배치 파일 실행 시 기존에 열린 `iscream_chrome_profile` 크롬 프로세스를 백그라운드에서 강제 종료(taskkill 대체 파워쉘 명령)하는 전처리 추가.

## 2. 2026-06-16: 올인원 통합 및 자가 진단 도구 추가
- **기능 추가**:
  - 사용자 편의를 위해 하나의 배치 파일 실행만으로 (1) 락 해제, (2) 디버그 크롬 기동, (3) 웹 브라우저 대시보드 팝업, (4) Flask 서버 구동을 모두 수행하는 **올인원 런처**로 개선.
  - 디버그 크롬 탭 감지 및 DOM 내 내부 `<iframe>` 영역까지 전부 순회하여 셀렉터 일치 여부를 검사하는 자가 진단 스크립트 `verify_selectors.py` 추가.

## 3. 2026-06-16: 자체 에이전트 구동 및 연결 검증 테스트
- **테스트 환경**: Windows 11, Chrome 헤드리스 CDP 디버깅 포트 `9222` 활성화 후 `verify_selectors.py` 구동.
- **검증 절차 및 결과**:
  1. **CDP 연결성**: 에이전트 환경에서 디버그 크롬 기동 후 `verify_selectors.py`를 호출하여 포트 `127.0.0.1:9222`을 통한 CDP 원격 디버깅 연결 성공.
  2. **페이지 및 탭 탐색**: Chrome의 열린 탭을 정상 조회하여 `'선생님과 함께하는 i-Scream'` 탭 및 메인페이지 URL(`https://www.i-scream.co.kr/user/main/MainPage.do`) 정상 식별 확인.
  3. **디버깅 보완 (AttributeError)**:
     - 검증 과정 중 `Page` 객체에 `.name` 속성이 없어 발생하는 `AttributeError: 'Page' object has no attribute 'name'` 에러 식별.
     - `getattr(frame, 'name', None)` 처리를 통해 메인 페이지 객체와 프레임 객체를 안전하게 구분하도록 `verify_selectors.py` 예외 감지 로직 보완 완료.
  4. **화면 및 DOM 수집**: `iscream_verification_screenshot.png` 캡처 및 `iscream_verification_dom.html` (232KB) HTML 파일 덤프에 모두 성공.
  5. **셀렉터 스캔**: 로그인 전 메인페이지이므로 평가 영역 셀렉터는 감지되지 않음(0/6 감지 성공, 정상 동작).
- **최종 판정**: CDP 기동, 포커싱, 캡처, DOM 수집 및 셀렉터 분석 기능이 모두 완벽하게 통합되었음을 확인하였음.

## 4. 2026-06-16: 비밀번호 입력 확인 페이지 진입 및 iframe 미인식 문제 해결
- **문제 현상**: AI평어 서비스 진입을 위해 비밀번호 'dlckdtn3'을 요구하는 페이지가 표시되었을 때, 자동 입력 및 제출 처리가 이루어지지 않고 멈추거나 건너뛰는 현상 발생.
- **원인 분석**:
  1. 비밀번호 확인 페이지(`SubjectEvaluationCheck.do`)가 메인 탭에 직접 로드되기도 하지만, 때로는 메인 탭(`SubjectEvaluation.do`) 하위의 `<iframe>` 요소 내부로 은폐되어 로드됨.
  2. 기존 Playwright 코드는 `page.locator()` 및 `page.url`만으로 감지했기 때문에, iframe 내부에 담겨 있는 비밀번호 입력란(`input#psw`)과 확인 버튼(`a:has-text('확인')`)을 식별할 수 없었음.
  3. URL 매칭 시 `SubjectEvaluation.do`로 표시되면서 내부에 확인 iframe이 있는 경우 "이미 평가 페이지에 진입 완료"된 것으로 오인하여 흐름을 우회하는 버그가 있었음.
- **조치 사항**:
  - `iscream_evaluate.py` 내 `navigate_to_evaluation` 함수를 대대적으로 리팩토링함.
  - 현재 로드된 메인 페이지와 모든 하위 프레임(`page.frames`)을 재귀적으로 순회하여, `SELECTOR_PASSWORD_INPUT` (`input#psw`)이 존재하는 프레임(`password_frame`)을 능동적으로 탐색하도록 구현.
  - 해당 입력란이 발견되면, 일반 URL 문자열 검사 결과와 무관하게 확인 창이 떠 있는 것으로 판단해 `password_frame` 내에서 직접 비밀번호를 기입하고, 확인용 앵커/버튼(`a:has-text('확인')`, `a.cbtn_rtyp1`, `a[onclick*='fnSubmit']`)을 클릭하여 정상 제출을 트리거함.
- **자가 진단 결과**:
  - `verify_selectors.py` 검증 도구도 동일한 셀렉터 및 다중 프레임 스캔 방식으로 맞춤 보완.
  - 테스트 러너(`test_pwd_entry.py`)를 통해 비밀번호 확인 프레임 발견, `dlckdtn3` 자동 입력 및 전송, 그리고 메인 평가 대시보드인 `SubjectEvaluation.do` 진입 완료(Navigation success: True)까지 완벽하게 이루어짐을 최종 실검증 완료.

## 5. 2026-06-16: 비밀번호 환경변수(.env) 분리
- **요구사항**: 소스코드 내 하드코딩되어 있던 비밀번호(`dlckdtn3`)를 보안 및 관리 편의성을 위해 외부 환경 변수 파일(`.env`)에서 로드하는 방식으로 리팩토링.
- **조치 사항**:
  - `.env` 및 `.env.example` 파일에 `ISCREAM_EVAL_PASSWORD` 환경 변수 항목 추가.
  - `iscream_evaluate.py` 모듈 내에 `.env` 파일을 동적으로 탐색하고 로드하는 `_load_password()` 유틸리티 함수 추가.
  - `iscream_evaluate.py` 내의 모든 비밀번호 자동 입력부(`password_input.fill()`)를 하드코딩된 문자열 대신 `_load_password()`에서 반환된 값을 전달하도록 수정.
- **검증 결과**:
  - `.env`에 등록된 `ISCREAM_EVAL_PASSWORD=dlckdtn3` 값을 정상적으로 읽어와 비밀번호 자동 입력을 수행함을 확인 완료.

## 6. 2026-06-16: 과목 선택 실패 문제 해결 (Nexacro 오프스크린 숨김 라디오 버튼 제어)
- **문제 현상**: 웹 UI에서 자동 입력을 시작하면 "과목 선택 실패" 로그가 발생하며 프로세스가 중단되는 문제 지속 발생.
- **원인 분석**:
  1. i-scream 페이지의 과목 선택 라디오 버튼(`input[name="searchSubject"]`)들은 시각적으로 노출되지 않고, 화면 좌표 밖(`x=-8987`)에 배치되어 있는 숨겨진(Off-screen) 접근성 노드 형식으로 구현되어 있음.
  2. Playwright의 표준 `.click()` 혹은 `force=True`를 활용한 클릭 시도는 엘리먼트가 뷰포트 영역 밖에 위치하기 때문에 `Locator.click: Element is outside of the viewport` 예외를 발생시키며 실패하게 됨.
  3. 라디오 버튼 대신 화면에 노출된 `<label>` 태그 클릭을 시도했으나, 해당 앵커/라벨 위로 헤더 영역(`header#header`)이나 상단 레이어(`div.subAreaFull`)가 가리고 있어 포인터 이벤트가 가로채어지는 등의 이유로 3000ms 시간 초과 에러가 발생했음.
- **조치 사항**:
  - `iscream_evaluate.py` 내의 `select_subject` 함수를 수정하여 모든 프레임을 돌며 대상 과목의 라디오 버튼을 찾은 뒤, Playwright의 뷰포트 물리 클릭 대신 **브라우저 내부 JavaScript 실행 방식 (`element.click()`)**을 사용하여 직접 이벤트를 주입하도록 변경함.
  - JS 클릭을 발생시킨 후, i-scream 및 JQuery 리스너가 해당 라디오 버튼의 변경을 감지하고 학생 목록 테이블을 갱신하도록 `change` 이벤트 디스패치(`dispatchEvent(new Event('change', { bubbles: true }))`) 처리를 명시적으로 추가함.
- **검증 결과**:
  - `test_js_click.py`와 실데이터 일괄 처리 테스트(`test_batch_run.py`)를 가동하여 '과학' 과목 라디오 버튼의 체크 상태가 정상적으로 `True`로 전환되는 것을 확인.
  - 과목 변경에 따른 학생 목록 갱신 및 대상 학생("강시우")의 평가 입력란 활성화, 텍스트 자동 기입 시뮬레이션(Dry Run)이 한 번에 완벽하게 통과(성공 1건)함을 최종 입증 완료.

## 7. 2026-06-16: 학생 체크박스 제어 및 평가기준 클릭 자동화 추가
- **요구사항**: 각 과목별로 한 학생당 평가기준(성취기준)을 2개 정도 클릭하는 것을 성공해야 함.
- **원인 분석 & 상세 진단**:
  1. i-scream 교과평가 입력 페이지에서는 좌측 학생 목록에서 대상 학생의 체크박스(`input#ai-student{idx}`)를 명시적으로 체크한 상태여야 우측 테이블의 평가기준 문장 버튼들(`button.al`)을 클릭했을 때 해당 학생의 평가 입력란(textarea)으로 자동 연동 및 반영이 됨.
  2. 평가기준 문장 버튼들(`button.al`)은 토글(Toggle) 방식으로 동작함: 클릭 시 부모 `tr`에 `highlight` 클래스가 추가되며 textarea에 해당 문장이 추가되고, 이미 선택된 상태(`highlight` 존재)에서 다시 클릭하면 선택 해제(highlight 제거 및 문장 제거)가 이루어짐.
- **조치 사항**:
  - `iscream_evaluate.py` 내 `fill_evaluation` 함수에 학생 체크박스 및 평가기준 2개 자동 클릭 흐름을 삽입함:
    - **학생 체크박스 단일 선택**: 학생 목록에서 대상 학생의 체크박스(`input#ai-student{idx}`)를 활성화하기 전, 다른 학생들의 체크박스들을 전부 스캔하여 루프를 돌며 체크를 강제 해제(`click()` 및 `change` 이벤트 주입)함. 그 후 대상 학생의 체크박스만 단독으로 체크 활성화함.
    - **평가기준 2개 선택**: 우측 평가기준 목록에서 부모 `tr`에 `highlight` 클래스가 없는(아직 선택되지 않은) `button.al` 요소를 검색하여 순차적으로 최대 2개 클릭하고 `change` 이벤트를 주입함. 이를 통해 학생별로 고유한 평가기준 2개가 정상적으로 선택되도록 보장함.
    - **평가내용 기입**: 평가기준이 2개 선택되어 텍스트가 자동 추가된 상태에서, Supabase/LLM을 통해 생성된 최종 평가 문장(`eval_text`)을 textarea에 강제로 `.fill`하여 덮어쓰고 갱신 처리를 마침 (이 과정 중에도 평가기준 선택 상태인 `highlight` 및 0명 -> 1명 카운트 등은 그대로 유지됨).
- **검증 결과**:
  - `test_batch_run.py` (dry-run 모드) 테스트 러너 실행 결과:
    - 대상 학생("강시우")의 체크박스가 정상 활성화되고, 우측 평가기준 버튼 2개가 성공적으로 클릭되어 `highlight` 상태가 되었으며, 최종 평가내용 입력까지 누수 없이 완료(시뮬레이션 성공)됨을 로그와 콘솔 추적으로 완벽 검증하였음.
