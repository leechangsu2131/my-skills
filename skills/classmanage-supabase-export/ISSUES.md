## 📌 백로그

### ISSUE-005: 이름 칸·시트 이름의 남은 위험 (2026-11-26)
- **상태**: 📌 백로그
- **증상** (가짜 자료로 실행해 확인): ① 이름 칸 값이 글이 아니라 목록(`['학생A']`)이면 `AttributeError` 로 멈춤. ② 이름에 `:` 등 엑셀 시트에 못 쓰는 글자가 있으면 `ValueError` 로 멈춤(지금은 `/`, `\` 만 바꿈). ③ 앞 31자가 같은 이름 둘은 시트 하나로 겹쳐 한 사람 기록이 사라지는데 '총 2명' 이라고 알림.
- **원인**: `parse_names` 는 글만 받고, 시트 이름은 일부 글자만 바꾸며 겹침을 검사하지 않음.
- **해결/조치**: 미정(T61 범위 밖). 실제 표의 이름 칸 형식은 **확인 필요**.
- **관련 파일**: `export.py` `parse_names`, `export_to_excel`

### ISSUE-004: SKILL.md의 결과 저장 위치 안내가 이전 상태임 (2026-11-25)
- **상태**: 📌 백로그
- **증상**: SKILL.md는 결과 파일이 현재 폴더에 생성된다고 설명하지만, T25 이후에는 공용 개인 데이터 폴더에 저장함.
- **원인**: T25의 작업 범위가 `export.py`와 시험 파일로 한정되어 사용 설명서는 수정하지 않았음.
- **해결/조치**: 문서 정리 작업에서 저장 위치 안내를 `data_dir()` 기준으로 바꾼다.
- **관련 파일**: `SKILL.md`, `export.py`

## 🟢 해결됨

### ISSUE-001: parse_names 가 이름 칸의 특이한 모양에서 틀리게 나눔 (2026-11-25)
- **상태**: 🟢 해결 (2026-11-26)
- **증상**: ① `[학생A 학생B]` 의 대괄호가 이름에 붙음. ② JSON 배열 안에 숫자가 있으면 `AttributeError`. ③ `학생 A, 학생 B` 가 네 개로 나뉨.
- **원인**: JSON 해석 실패 시 `[,\s]+` 로 그대로 나누고, JSON 항목이 글인지 확인하지 않음.
- **해결/조치**: 대괄호를 떼고 나눔. 숫자는 글로 바꾸고 null 은 버림. 쉼표가 있으면 쉼표로 먼저 나누고, 칸 안에 한 글자 토막이 있으면 한 이름으로, 모두 두 글자 이상이면 공백으로도 나눔.
- **남는 한계**: 쉼표 목록에서 `남궁 민수` 처럼 두 토막이 모두 두 글자 이상이면 둘로 나뉨. 쉼표 없는 `김 철수` 도 지금처럼 둘로 나뉨.
- **관련 파일**: `export.py` `parse_names`, `tests/test_export.py`

### ISSUE-002: 이름이 하나도 없으면 export_to_excel 이 멈춤 (2026-11-25)
- **상태**: 🟢 해결 (2026-11-26)
- **증상**: 모든 이름 칸이 비면 `IndexError: At least one sheet must be visible`
- **원인**: 시트 없이 엑셀 파일을 닫음
- **해결/조치**: 파일을 만들지 않고 알린 뒤 끝냄(전에 만든 파일은 그대로 남음).
- **관련 파일**: `export.py` `export_to_excel`, `tests/test_export.py`

### ISSUE-003: 결과 엑셀 저장 위치와 TLS 인증서 확인 (2026-11-25)
- **상태**: 🟢 해결 (2026-11-25)
- **증상**: `student_records.xlsx` 가 스킬 폴더(저장소 안)에 만들어지고, Supabase 요청에 `verify=False` 가 쓰였음.
- **원인**: 저장 경로가 `Path(__file__).parent`였고, 요청에서 인증서 확인을 껐음.
- **해결/조치**: `data_dir() / "student_records.xlsx"`로 저장하고 `verify=False`를 제거해 requests 기본 TLS 인증서 검증을 사용함. 시험은 `data_dir()`를 임시 폴더로 바꿔 실제 개인정보 폴더에 쓰지 않도록 수정함.
- **관련 파일**: `export.py`, `tests/test_export.py`
