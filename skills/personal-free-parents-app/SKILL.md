# 같이 놀자 스킬 가이드

이 문서는 놀이터에서 서로의 존재를 확인하는 공동 육아 앱 **'같이 놀자'** 개발 및 디자인 통합 가이드라인을 제공합니다.

---
## 최신 구현 메모 (2026-07-20)

### 지도 데이터는 데모와 실제를 섞지 않는다

- 놀이터 목록은 `GroupRepository.getPlaygrounds()`에서 읽는다.
- 실제 목록을 불러오지 못했을 때 릴리스 빌드는 데모 마커나 가상의 부모 현황을 보여 주지 않는다. 빈 상태 또는 재시도 UI를 표시한다.
- 데모 마커는 `kDebugMode`에서만 지도 동작을 점검하기 위한 용도로 허용한다.
- 상단의 놀이터 개수처럼 화면에 보이는 수치는 하드코딩하지 않고 현재 목록을 기준으로 계산한다.

### flutter_naver_map 비동기 오버레이 규칙

- `NOverlayImage.fromWidget()` 전후에는 `mounted`와 현재 렌더 토큰을 확인한다. 페이지가 닫힌 뒤 이전 `NaverMapController`에 오버레이를 추가하면 `unmounted context` 또는 `MissingPluginException`이 생길 수 있다.
- `clearOverlays()`와 `addOverlay()`는 `await`하고, 화면 전환 중 발생한 채널 예외는 지도 렌더를 중단하지 않도록 안전하게 무시한다.
- Android의 NCP 키는 `AndroidManifest.xml`에서 `@string/naver_map_sdk_ncp_key_id`를 참조한다. Dart 초기화에는 별도 client ID를 넘기지 않는다.
- Android `applicationId`, Gradle `namespace`, `MainActivity` 패키지는 모두 `com.example.one_parent_watch`로 맞춘다. NCP 콘솔의 Android 패키지명도 이 값과 일치해야 한다.

### 데이터 계약을 먼저 정리한다

- 화면에서 `playgroundId`를 생성 화면으로 넘기는 것만으로는 모임 생성이 완성되지 않는다. `groups`, `group_members`, Flutter 모델, 저장소 쿼리가 같은 컬럼 계약을 가져야 한다.
- `supabase/migrations/00003_group_contract.sql`은 기존 `user_id` 기반 테이블에 일정·상태·아동 별칭·GPS 호환 필드를 추가한다. 원격에 적용하기 전에는 중복된 기존 `00002` 마이그레이션의 적용 이력부터 확인한다.
- 데이터 계약이 정리되기 전에는 데모 상태를 실제 모임 현황처럼 표시하거나 생성 성공 토스트만 띄우지 않는다.

## 0. 이 앱이 느껴져야 하는 것

경주 여름 오후 2시. 아파트 단지 놀이터 옆 벤치. 느티나무 그늘.
벤치에 앉은 부모는 처음으로 휴대폰을 내려놓는다.
저 멀리 미끄럼틀 앞에 아는 얼굴이 보인다. 혼자가 아니다.

아이들은 또래와 어울려 놀고, 부모들은 서로의 존재를 알아차리며 자연스럽게
마음을 놓는다. 이 앱은 그 순간을 만드는 도구다. "아이를 맡기는 앱"도,
"순번을 배정하는 앱"도 아니다. **"지금 여기 누가 있는지 보여주는" 공동
돌봄 도구**다.

새 디자인 결정을 내릴 때 스스로에게 묻는다:
**"이게 느티나무 그늘 아래 앉은 부모에게 필요한 것인가?"**

### 이 앱이 배정하지 않는 것

이 앱은 **누구에게도 감독 순번이나 시간을 배정하지 않는다.** 타이머도,
강제 교대도, "지금 당신 차례입니다"도 없다. 각자 자기 아이는 항상 자기
책임이며, 다른 집 아이를 잠깐 봐주는 것은 어른들 사이의 개인적 호의일 뿐
앱이 조직하는 일이 아니다 — 이건 앱 없이 놀이터에서 일어나던 일과 똑같다.

앱이 하는 일은 딱 하나, **지금 누가 여기 있는지 보여주는 것**이다. 그
다음은 사람들이 알아서 한다.

### 핵심 프레이밍 — "모집"이 아니라 "확인"

이 앱은 **사람을 모으는 앱이 아니라, 지금 상황을 보여주는 앱이다.**

"그룹원 모집중", "매칭 대기" 같은 언어와 UI는 쓰지 않는다. 이런 프레이밍은
낯선 사람이 만든 모집 글에 "참여" 버튼을 눌러야 하는 심리적 장벽을 만든다.

대신 지도를 열면 **지금 어디서 누가 놀고 있는지가 그냥 보인다.** 사용자는
"모집에 참여"하는 게 아니라 "저기 누가 있네, 나도 가야지"라고 자연스럽게
판단한다. 둘러보는 행위 자체는 완전히 개방적이고 가볍다 — 로그인 없이도
지도는 볼 수 있고, 탭하는 데 아무 장벽이 없다.

단, **자신의 상태를 스스로 표시하는 것**은 조금 다르다. "저 지금 아이들을
보고 있어요"라고 스스로 표시하는 순간, 다른 부모들이 그걸 보고 판단에
참고한다. 강제성은 없지만 최초 1회는 이 표시의 의미(19-1번 법적 원칙)를
가볍게 안내한다. 즉:

```
둘러보기(누가 있는지 확인) → 완전히 열려있고 가볍다. 장벽 없음.
내 상태 표시(☀️보는 중 / 🌿쉬는 중) → 순전히 자율 선언. 배정도, 시간
                                     제한도, 강제 교대도 없다. 최초
                                     1회만 의미를 가볍게 안내한다.
```

이 둘을 UI에서도 명확히 분리한다. 지도와 바텀시트는 "확인"의 언어로,
최초 상태 표시 안내만 짧게 "책임"의 언어를 섞는다.

**UI 문구 원칙**

```
❌ "그룹원 모집중"        → ✅ "지금 2명 있어요"
❌ "매칭 대기"            → ✅ "아직 아무도 없어요"
❌ "그룹에 참여하기"       → ✅ "나도 갈게요"
❌ "그룹 생성"            → ✅ "여기서 시작하기" (기존 유지, 이미 적절함)
❌ "감독 그룹 상세"        → ✅ "지금 놀고 있어요"
❌ "그룹이 만들어졌어요!"   → ✅ "이제 다른 부모들이 볼 수 있어요"
❌ "감독 순번", "교대"     → ✅ (아예 없음 — 배정 개념 자체가 없다)
❌ "동의하고 시작하기"     → ✅ "알겠어요" (최초 1회 안내 확인용, 매번 아님)
```

마지막 두 항목이 이번 변경의 핵심이다: "감독 순번"이나 "교대"라는 말 자체를
쓸 일이 없다 — 앱이 배정하는 게 없기 때문이다. "동의하고 시작하기"도 매
합류 시점마다 나오는 무거운 동의 화면이 아니라, **최초 1회만** 상태 표시의
의미를 안내하는 가벼운 확인으로 바뀐다(19-1번 참고).

"그룹" 이라는 단어는 사용자 대면 문구에서 최대한 걷어낸다(내부 DB/코드에서
group_id로 부르는 것은 무방).

지도 마커 상태 표시도 같은 원칙을 따른다.

```
amber (진행중)  라벨: "지금 놀고 있어요" — 모집 완료가 아니라 현재 상황
canopy (모집중) 라벨: "○명 있어요"      — "모집중"이 아니라 현재 인원
smoke (비어있음) 라벨: "아직 없어요"     — 비어있는 사실을 담백하게
```

바텀시트의 "참여하기" 버튼(7-3, 8번 관련)도 "나도 갈게요"로 바꾸는 것을
검토한다. 최초 상태 표시 시 나오는 안내 화면의 버튼 문구("알겠어요")는
가볍게 유지한다 — 매번 나오는 무거운 동의가 아니라 처음 한 번의 안내다.

## 1. 디자인 콘셉트 — 한낮의 그늘 (Midday Shade)

## 2. 핵심 레이아웃 — 두 존, 그러나 배정이 아니라 선언

**타이머도, 강제 교대도, 순번 배정도 없다.** 대신 각자 자기 상태를 스스로
선언한다 — "☀️ 지금 보고 있어요" 또는 "🌿 잠깐 쉴게요". 이건 시스템이
정하는 게 아니라 각 사람이 원할 때 스스로 탭해서 바꾸는 토글이다.

화면은 여전히 두 존으로 나뉜다. 이건 "한낮의 그늘" 시각 정체성을 지키기
위함이지, 역할을 배정하기 위함이 아니다.

```
─────────────────────────────────────
  ☀️ 햇볕 존 (화면 상단)
  배경: amberPale → amberGlow 그라디언트
  내용: "지금 보고 있어요"를 스스로 선택한 사람들의 아바타
        (0명일 수도, 여러 명일 수도 있다 — 배정이 아니므로)
─────────────────────────────────────
  〰️ 파도 모양 구분선 (SVG path, 직선 금지)
─────────────────────────────────────
  🌿 그늘 존 (화면 하단)
  배경: forest (#192B1B)
  내용: "쉬고 있어요"를 선택한 사람들의 아바타, 긴급 버튼
  텍스트: mist (#B4D4A8)
─────────────────────────────────────
```

**타이머를 그리지 않는다.** 82px 디스플레이 타이머, 진행 바, 자동 교대
카운트다운은 전부 제거한다. 대신 각자의 아바타 옆에 "몇 분째"라는 정보
정도만 담백하게 보여줄 수 있다(강제성 없는 참고 정보로만).

**아무도 ☀️를 선택하지 않은 상태도 정상이다.** 시스템이 "지금 아무도
안 보고 있다"고 경고하거나 독촉하지 않는다. 그건 다시 배정을 하는
것이므로, 이 앱의 원칙에 어긋난다.

구분선은 CSS 직선 border가 아니라 SVG path로 그린 유기적 곡선이어야 한다.
직선이면 딱딱해서 "그늘의 경계"라는 느낌이 사라진다.

## 3. 타이포그래피 및 UI 규칙

- **서체**: Noto Sans KR (굵기: 400 Regular, 700 Bold, 900 Black만 사용).
- **화면 제목(H1)**: `24px` 굵기 900, ink, 자간 `-0.5px` 이상.
- **워드마크**: `20px` 굵기 900, forest색, 자간 `-1px`.
- **아이콘 원칙**: 별도 벡터 아이콘 라이브러리 대신 이모지를 기본 탑재 (🛝, ☀️, 🌿, 🚨, 🏢, 🏫, 🚄, 📍, 🏷).
- **버튼 텍스트**: 동사형으로 쓴다 ("나도 갈게요", "여기서 시작하기", "다음"). "확인", "OK"는 쓰지 않는다. 둘러보기/합류 단계의 정확한 문구는 0번 "UI 문구 원칙" 참고.
- **모서리**: 버튼 14px / 카드 16–18px / 칩·뱃지 99px(완전 알약형).
- **긴급 버튼 (Emergency FAB)**: `error`(#B03020) 원형 플로팅 버튼, 54px. 지도 및 놀이터 화면 내 항상 노출 — 절대 숨기거나 비활성화하지 않는다.

### 애니메이션 (아래 4가지만 사용)
- `ping` 1.8s — 활성 놀이터 마커 외부 원
- `sunRay` 3s — 햇볕 존 배경 방사, 매우 느리게
- `breathe` 4s — 화면 전체 미세 확대 (scale 1.0 ↔ 1.02)
- `slideUp` 0.32s spring — 바텀시트 등장

## 5. 법적 및 기능 원칙

- **"아이를 맡긴다"는 표현은 사용하지 않는다.** 대신 **"함께 있다 / 같이 논다"**로 기술한다.
- **앱은 누구에게도 감독 순번이나 시간을 배정하지 않는다.** 타이머도, 강제 교대도, 시스템이 지정하는 담당자도 없다. 앱은 각자가 스스로 "지금 보고 있어요"를 선언할 수 있는 표시 도구일 뿐이다.
- **각자 자기 아이는 항상 자기 책임이다.** 다른 집 아이를 잠깐 봐주는 것은 그 순간 그 어른들 사이의 개인적 호의이며, 앱이 조직하거나 배정한 역할이 아니다. 이는 앱 없이 놀이터에서 일어나던 것과 동일하다.
- **"지금 보고 있어요" 표시는 매번 무거운 동의를 요구하지 않는다.** 최초 1회, 이 표시가 법적으로 무엇을 뜻하지 않는지(=책임을 앱이 대신 지지 않는다는 것) 가볍게 안내하는 것으로 충분하다. 매번 배정이 발생하는 게 아니므로 매번 동의를 받을 이유가 없다.
- 완전히 낯선 사용자 간 매칭은 하지 않는다. 같은 어린이집·단지 등 **소속 기반**으로만 서로를 확인할 수.

**이전 설계와의 차이**: 이전에는 "감독 순번에 합류하는 순간"에 무거운 동의 절차를 매번 거치게 했다. 배정이 없어지면서 이 구조가 오히려 더 단순해졌다 — 앱이 누구의 책임을 조직하지 않으므로, "앱이 순번을 배정해놓고 책임은 안 진다"는 취약한 논리 자체가 필요 없어진다. 대신 "이 앱은 애초에 아무것도 배정하지 않았다"는 훨씬 방어하기 쉬운 사실만 남는다.

## 6. 지도 — 네이버 지도 SDK 전용

이 앱의 지도는 **네이버 지도(flutter_naver_map)만 사용한다.** Google Maps는 쓰지 않는다. 한국 놀이터·아파트 단지 데이터 품질이 네이버 쪽이 압도적으로 높고, 파일럿 지역(신경주역 권역) 데이터도 네이버 기준으로 확인했다.

```dart
dependencies:
  flutter_naver_map: ^1.2.0
```

### 커스텀 마커 구현 방법 (확인된 API)

색 점 구성 표시, 알약형 라벨 등 커스텀 디자인은 `NOverlayImage.fromWidget()`으로 구현한다. 임의의 Flutter 위젯을 렌더링해 마커 아이콘 이미지로 변환하는 공식 지원 방식이다.

```dart
final markerIcon = await NOverlayImage.fromWidget(
  widget: PlaygroundMarkerWidget(  // 7번의 구성 마커 위젯
    status: pg.status,
    affiliationColors: pg.affiliationColors,
  ),
  context: context,
);
final marker = NMarker(id: pg.id, position: pg.latLng, icon: markerIcon);
controller.addOverlay(marker);
```

마커 수가 많아질 경우(Beta 이후), 위젯 렌더링을 백그라운드에서 미리 준비하고 메인 스레드에서는 `addOverlay`만 호출해 성능을 관리한다.

### 줌 레벨별 라벨 표시 (직접 구현 필요)

네이버 SDK가 자동으로 줌에 따라 라벨을 숨겨주지 않는다. `onCameraChange`/`onCameraIdle` 콜백에서 현재 zoom 값을 읽어, 코드에서 직접 마커의 caption 유무를 전환한다.

```dart
onCameraChange: (position, reason) {
  final zoom = position.zoom;
  // zoom < 13: 놀이터 마커만, 소속 라벨 숨김
  // zoom 13~15: 놀이터 + 가까운 소속 1~2개 라벨
  // zoom > 15: 전체 라벨
}
```

### 지도 배경 톤 — 확인 필요 항목

네이버 지도는 Google Maps Style JSON과 같은 전면적인 색상 커스터마이징 API가 공식 문서에서 명확히 확인되지 않았다. 지도 배경 자체를 warmGray 톤으로 바꾸는 것은 **약속하지 않는다.** 대신 `activeLayerGroups`로 건물/대중교통 레이어만 선택적으로 노출하고, 나머지는 네이버 기본 지도색을 그대로 쓰되 **우리 마커와 라벨의 대비를 강하게 줘서** 시각적 위계를 만든다 (흰 배경 알약 + 진한 색 마커).

```dart
NaverMapViewOptions(
  mapType: NMapType.basic,
  activeLayerGroups: [NLayerGroup.building, NLayerGroup.transit],
)
```

### 라벨 표시 원칙

- **라벨은 반드시 흰 배경 알약(pill)을 가진다.** `NOverlayCaption`은 배경색·텍스트 스타일 옵션이 제한적이므로, 정교한 알약 라벨이 필요하면 `NOverlayImage.fromWidget()`으로 라벨까지 포함한 마커 위젯을 통째로 만든다.
  ```
  배경: white(#FFFDF3), opacity 0.92 / padding: 4px 10px
  radius: 99px / 그림자: 0 1px 4px rgba(0,0,0,.15)
  ```
- **폰트 크기·굵기 통일**: 놀이터 라벨 12px/700/ink, 소속 라벨 11px/400/bark
- **긴 이름은 지도에서 8자 이내로 축약**, 전체 이름은 마커 탭 시 바텀시트에서 노출
  - "해링턴플레이스 신경주역" → 지도 라벨은 "해링턴플레이스"

### 놀이터 — 소속과 1:1이 아니다

한 아파트 단지 안에 놀이터가 여러 개 있을 수 있고, 두 단지 사이 경계에 공용 놀이터가 있을 수도 있다. **놀이터를 특정 소속에 종속시키지 않는다.** 놀이터는 그냥 위치이고, 어느 소속과 가까운지는 조회 시점에 거리 계산으로 판단한다.

```
❌ 놀이터 하나 = 소속 하나 (고정 연결)
✅ 놀이터는 독립적인 위치, 소속과의 관계는 매번 거리로 계산
```

### 놀이터 이름 규칙 — 랜드마크로 구분

같은 단지 안 여러 놀이터는 반드시 랜드마크를 붙여 구분한다. 이름이 겹치면 지도에서도, 그룹 생성 흐름에서도 혼동이 생긴다.

```
❌ "해링턴 놀이터" (단지 내 3곳이 전부 이 이름이면 구분 불가)
✅ "해링턴 놀이터 (분수광장)"
✅ "해링턴 놀이터 (정문 앞)"
✅ "해링턴 놀이터 (테니스장 옆)"
```

파일럿 현장 답사 시 이 랜드마크 이름까지 확정해서 seed data에 넣는다.

### 인접 놀이터 클러스터링 — 확대 대신 스파이더파이

같은 단지 내 놀이터가 지도상 가까이 붙어 있으면(예: 30m 이내) 마커가 겹친다. 네이버 SDK는 클러스터링을 기본 제공하지 않으므로 직접 구현한다.

```
넓은 줌: 인접 놀이터 여러 개를 클러스터 마커 하나로 묶어 "🛝 3" 표시
클러스터 탭: 지도를 확대하지 않고, 그 자리에서 개별 마커가
             부채꼴로 펼쳐지며(스파이더파이) 각각 이름표를 단다
```

지도를 확대하지 않는 이유: 확대하면 지도의 현재 위치·맥락을 잃는다. 지도를
훑어보다가 클러스터 하나를 잠깐 열어보는 행위는 가벼워야 한다(0번 "확인"
원칙). 확대 후 다시 원래 줌으로 돌아오는 왕복이 생기면 그만큼 마찰이 된다.

```
탭 전                탭 후 (스파이더파이)

  🛝 3                🛝분수광장
                      ╱
                  🛝 ─┼─ 🛝정문앞
                      ╲
                       🛝테니스장옆
```

**구현 방식**

- 클러스터 중심점 기준 하위 놀이터 개수만큼 각도를 나눠(3개면 120도씩)
  일정 반경(예: 40px) 떨어진 위치에 개별 마커를 재배치한다.
- 중심점과 각 마커 사이에 얇은 연결선(bark색, 1px)을 `NPolylineOverlay`로 그어
  "원래 하나였다"는 시각적 연결을 남긴다.
- 펼침/접힘 전환은 spring 커브로 부드럽게(0.25초 내외). 지도 바깥(빈 곳)을
  탭하면 다시 접힌다.
- 펼쳐진 개별 마커를 탭하면 평소처럼 해당 놀이터 바텀시트가 열린다.
- 하위 놀이터가 5개를 넘으면 스파이더파이 대신 리스트 바텀시트로 전환한다
  (부채꼴이 촘촘해지면 오탭 위험이 커지므로).
- 클러스터 마커도 `NOverlayImage.fromWidget()`으로 만들고, `onCameraChange`의
  zoom 값에 따라 개별 마커 ↔ 클러스터 마커 전환 여부를 판단한다(줌 레벨별
  라벨 표시 로직과 같은 방식으로 통합 관리).

### 그룹 생성 시 놀이터 선택 — 지도 탭이 애매하면 목록으로

인접한 놀이터가 여러 개면 지도 탭만으로는 오탭 위험이 있다. 사용자 위치 기준 30m 이내에 놀이터가 2곳 이상이면, 지도 선택 대신 리스트 선택지를 띄운다.

```
"해링턴 아파트 안에 놀이터가 3곳 있어요"
○ 분수광장 놀이터
○ 정문 앞 놀이터
○ 테니스장 옆 놀이터
```

## 7. 소속 색상 시스템 — "누가 저기서 놀고 있는지" 한눈에

지도만 보고 **"어, 라라어린이집 애들이 저기서 놀고 있네"**를 바로 알 수 있어야 한다. 각 소속에 고유 색을 부여하고, 놀이터 마커에 현재 있는 소속들을 색 점으로 표시한다. `NOverlayImage.fromWidget()`으로 구현한다(6번 참고).

### 소속별 색상 팔레트

한낮의 그늘 톤(warm, muted) 안에서 서로 구분되는 6가지 색을 쓴다. amber와 forest는 상태색(보는 중/쉬는 중)으로 이미 쓰이므로 소속 색상에는 포함하지 않는다.

```
소속 1  clay      #B5654A  (테라코타)
소속 2  olive     #8A8B3F  (올리브)
소속 3  dustyRose #A5695E  (더스티 로즈)
소속 4  moss      #5E7A5C  (이끼 녹색 — canopy와는 다른 톤)
소속 5  sand      #C9A66B  (모래 황토)
소속 6  plum      #7A5C6E  (자두 보라 — 채도 낮게)
```

7개 이상 소속이 생기면(Growth 단계) 명도/채도를 조금씩 변주해 확장한다. 파랑 계열은 여전히 쓰지 않는다.

`affiliations` 테이블에 `color_hex` 컬럼을 추가해 소속 생성 시 팔레트에서 순서대로 자동 할당한다.

```sql
alter table affiliations add column color_hex varchar default '#B5654A';
```

### 놀이터 마커 위젯 구조 (PlaygroundMarkerWidget)

```dart
Stack(
  children: [
    // 기본 마커: 상태색 원 (amber="지금 놀고 있어요" / canopy="○명 있어요" / smoke="아직 없어요")
    Container(width: 36, height: 36, decoration: BoxDecoration(
      shape: BoxShape.circle, color: statusColor,
      border: Border.all(color: Colors.white, width: 3)),
      child: Text('🛝')),
    // 구성 점: 최대 4개, 소속 종류당 1개 (인원수 아님)
    ...affiliationColors.take(4).map((c) => Positioned(
      /* 마커 테두리를 따라 배치 */
      child: Container(width: 10, height: 10, decoration: BoxDecoration(
        shape: BoxShape.circle, color: c,
        border: Border.all(color: Colors.white, width: 1.5))),
    )),
    // 4개 초과 시 "+N" 텍스트 오버레이
  ],
)
```

예시: 천년가 앞 공원에 라라어린이집(moss) 아이 2명 + 해링턴 아파트(clay) 아이 1명이 있다면, 마커 주변에 moss 점 1개 + clay 점 1개가 붙는다. 부모는 지도를 슥 보는 것만으로 "우리 어린이집 애들이 저기 있네"를 안다.

바텀시트를 열면 소속별로 그룹화된 참여자 목록과 색 점이 함께 표시되어 더 자세히 확인 가능하다.

### 내 소속 강조

로그인한 사용자의 소속 색 점은 다른 소속 점(10px)보다 크게(13px) 하고, amber 테두리를 둘러 강조한다. 내 아이와 같은 소속 아이가 있는 놀이터를 빠르게 찾을 수 있게 하기 위함이다.

## 8. 첫 실행 화면 — 로그인 우선, 슬라이드 없음

앱을 열면 인트로 슬라이드 없이 **바로 로그인 화면**이 뜬다. "복잡함보다 단순함"이라는 원칙에 따라, 로그인 전 화면을 하나로 줄인다.

### 화면 구성 (스크롤 없이 한 화면)

```
─────────────────────────────
     🌤  (아이콘, 상단 여백)

     같이 놀자
     번갈아 돌보고, 제대로 쉬어요
     (워드마크 + 한 줄 슬로건)

     [ G  Google로 계속하기 ]
     (화면에서 가장 크고 눈에 띄는 버튼)

─────────────────────────────
```

- 워드마크: 20px, 900, forest색
- 슬로건: 14px, 400, bark색, 워드마크 바로 아래
- 구글 로그인 버튼: 화면 내 유일한 CTA. 패딩 18px 이상, Google 공식 브랜드 가이드라인 준수(흰 배경, Google 로고, "Google로 계속하기")
- 로그인 성공 후 소속 선택(어린이집/아파트) 화면으로 바로 이동. 그 외 추가 단계 없음.

### 하지 않는 것

- 기능 소개 슬라이드, 캐러셀, "다음" 버튼으로 넘기는 인트로 화면을 만들지 않는다.
- 전화번호 인증을 로그인 전 단계로 넣지 않는다. 필요하면 구글 로그인 이후 소속 인증 강화 단계(Beta)에서 선택적으로 추가한다.

## 9. 이 스킬을 적용할 때

새 화면이나 컴포넌트를 만들 때 아래 순서로 확인한다.

1. 이게 놀이터 현황/상태 화면인가? → 2번 두 존 레이아웃 적용(배정 아닌 자율 선언임에 유의)
2. 색을 쓸 일이 있는가? → 1번 색상 코드표 안에서만 선택 (소속 색은 7번 별도 팔레트)
3. 텍스트를 쓸 일이 있는가? → 5번 금지 표현 확인, 버튼은 동사형
4. 애니메이션이 필요한가? → 3번 4가지 중에서만 선택, 새로 만들지 않는다
5. 지도 화면을 만드는가? → 6번(네이버 SDK, 라벨 규칙) + 7번(소속 색 구성 표시) 적용
6. 로그인/첫 실행 화면을 만드는가? → 8번에 따라 슬라이드 없이 로그인 화면부터 시작
