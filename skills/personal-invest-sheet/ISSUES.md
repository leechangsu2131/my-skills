## 🔵 진행 중

### ISSUE-001: 예전 투자 스킬 2개와 역할 정리 (2026-11-20)
- **상태**: 🔵 진행 중
- **증상**: `personal-analyze-trade`(분석)·`personal-record-trade`(기록)가 같은 시트를 다루지만, 시트 지도가 옛 구조(📊 A4:T32)이고 `.env` 경로도 예전 위치를 가리킨다. 세 스킬이 함께 있으면 어느 것이 불릴지 헷갈린다.
- **해결/조치**: 두 스킬의 status를 `보관`으로 바꾸고 이 스킬로 안내. `record-trade`의 스크립트(`2_add_trade.py` 등)는 지우지 않았다. 다시 쓸 스크립트가 있으면 이 스킬로 옮긴다.
- **남은 것**: 보관 스킬의 쓸 만한 교훈은 SKILL.md에 옮김(2026-11-20). 옛 폴더를 지울지는 사용자 결정.
- **관련 파일**: `skills/personal-analyze-trade/SKILL.md`, `skills/personal-record-trade/SKILL.md`

## 📌 백로그

> 투자시트 쪽 미결 항목 전체는 드라이브 `invest/docs/00_총괄_투자시스템.md` §7-1 열린 목록이 기준이다. 여기에는 이 스킬·스크립트에 관한 것만 둔다(ISSUE-002 = 열린 목록 P1, 003 = P2, 004 = P9).

### ISSUE-002: 수집 스크립트마다 종목 목록이 따로 박혀 있음 (2026-11-20)
- **상태**: 📌 백로그
- **증상**: `fetch_*` 5개와 `narrative_dcf` 2개의 종목 목록이 서로 다르고, 이미 정리한 종목이 "보유"로 남아 있다(invest `README.md` §9-3).
- **후보**: 드라이브 `invest/portfolio/universe.csv`(또는 📊 포트폴리오 C열)를 한 곳의 기준으로 두고 스크립트가 그걸 읽게 바꾸기.

### ISSUE-003: 스크립트별 `.env` 읽는 방식·출력 폴더가 제각각 (2026-11-20)
- **상태**: 📌 백로그
- **증상**: 키움·DART·NAVER 키를 찾는 순서가 스크립트마다 다르고, 재무 CSV는 실행 폴더에 생긴다(invest `README.md` §4, 질문 1~3). 실행 폴더에 `.env`를 두면 드라이브로 올라갈 위험.
- **후보**: 공통 `load_env` 하나(중앙 `.env`만 읽기) + 출력은 `invest/data/` 아래로 통일 + 순서대로 돌리는 `run_all.py`.

### ISSUE-004: 큰 붙여넣기와 5행 쓰기 규칙의 충돌 (2026-11-20)
- **상태**: 📌 백로그
- **증상**: 📥 재무수집·FCF이력·raw data 갱신은 수십 행이라 `sheet_io.py`의 5행 제한에 걸린다. 지금은 사용자가 직접 붙여 넣는다.
- **후보**: 수집 탭 전용으로 "탭 전체 값 교체" 모드를 따로 두고, 교체 전 백업 TSV를 `data_dir()`에 남기기. 사용자 결정 필요.

## 🟢 해결됨

### ISSUE-008: 매매일지 소급 입력 기준 정함 (2026-11-21)
- **상태**: 🟢 해결 (2026-11-21)
- **증상**: 키움 1년치와 대조하니 매매일지에 종목·일 단위 193건이 빠져 있었다(대부분 소액 반복 매수).
- **해결/조치**: 사용자 결정으로 기간 합산 입력. 같은 종목·구분·포지션ID 안에서 10일 넘게 쉬면 끊고, 절세 매매(같은 기간 같은 수량 매도·재매수)는 제외. SKILL.md "B-2"에 절차, `journal_reconcile.py`가 매매근거의 `기간합산 시작~끝`을 읽어 기간 전체를 기록된 것으로 보게 함. 날짜 정렬은 사용자가 한다.
- **관련 파일**: `SKILL.md`, `scripts/journal_reconcile.py`

### ISSUE-007: 키움 1년치 조회에서 국내 구간이 빠짐 (2026-11-20)
- **상태**: 🟢 해결 (2026-11-20)
- **증상**: `[경고] kt00015 … 조회 실패: 429 Client Error`. 이전 실행의 1년치 결과는 0건이었다.
- **원인**: 연속조회를 쉬지 않고 보내 키움의 요청 한도(429)에 걸림.
- **해결/조치**: 드라이브 `invest/fetch/kiwoom_fetch_trades.py`에 요청 간격(0.3초)과 429 재시도(1·2·4·8초) 추가. 재실행 결과 국내 118 + 해외 255건 정상.
- **관련 파일**: `invest/fetch/kiwoom_fetch_trades.py` (드라이브, 이 저장소 밖)

### ISSUE-006: 읽기 전용 점검 스크립트 추가 (2026-11-20)
- **상태**: 🟢 해결 (2026-11-20)
- **해결/조치**: `scripts/sheet_check.py`(오류 셀, 🎯 하방 임시식, 🔬에 남은 청산 종목), `scripts/journal_reconcile.py`(키움 내역 ↔ 매매일지 대조). 둘 다 시트에 쓰지 않는다.
- **관련 파일**: `scripts/`

### ISSUE-005: 시트 ID가 코드에 직접 적혀 있음 (2026-11-20)
- **상태**: 🟢 해결 (2026-11-20)
- **증상**: `invest/tools/sheet_io.py`에 시트 ID와 키 경로가 박혀 있었다.
- **해결/조치**: 공용 .env에 `PERSONAL_INVEST_SHEET__GOOGLE_SHEET_ID`·`__GOOGLE_SHEET_URL`·`__INVEST_DIR` 추가. `sheet_io.py`가 my-skills `skill_env.py`와 같은 순서로 .env를 찾아 시트 ID와 `GOOGLE_CREDENTIALS_PATH`(상대 경로는 .env 폴더 기준)를 읽게 바꿈. 예전 스킬용 `PERSONAL_*_TRADE__GOOGLE_SHEET_ID`도 같은 시트를 가리키는 것 확인.
- **남은 것**: 이 SKILL.md 표의 `G:\내 드라이브\invest` 표기(사람용 안내), 보관 스킬의 `batch_portfolio_valuation.py`·`scratch_read_sheets.py` 하드코딩(안 쓰는 파일).
- **관련 파일**: `invest/tools/sheet_io.py`, `scripts/sheet_check.py`
