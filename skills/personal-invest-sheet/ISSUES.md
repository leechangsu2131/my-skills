### ISSUE-001: 예전 투자 스킬 2개와 역할 정리 (2026-11-20)
- **상태**: 🔵 진행 중
- **증상**: `personal-analyze-trade`(분석)·`personal-record-trade`(기록)가 같은 시트를 다루지만, 시트 지도가 옛 구조(📊 A4:T32)이고 `.env` 경로도 예전 위치를 가리킨다. 세 스킬이 함께 있으면 어느 것이 불릴지 헷갈린다.
- **해결/조치**: 두 스킬의 status를 `보관`으로 바꾸고 이 스킬로 안내. `record-trade`의 스크립트(`2_add_trade.py` 등)는 지우지 않았다. 다시 쓸 스크립트가 있으면 이 스킬로 옮긴다.
- **남은 것**: 보관 스킬의 쓸 만한 교훈은 SKILL.md에 옮김(2026-11-20). 옛 폴더를 지울지는 사용자 결정.
- **관련 파일**: `skills/personal-analyze-trade/SKILL.md`, `skills/personal-record-trade/SKILL.md`

### ISSUE-010: 드라이브 docs를 구글 문서로 전환, 스킬의 문서 이름 갱신 (2026-11-22)
- **상태**: 🟢 해결 (2026-11-22)
- **배경**: 웹·모바일 세션의 Drive 커넥터로는 `.md` 본문을 고칠 수 없어, 사용자 결정으로 `invest/docs`(하위 `변경기록_결정기록` 포함) 문서를 모두 구글 문서로 바꿨다. 옛 .md 원본은 `invest/_보관/<이름>_md원본_20261122.md`.
- **해결/조치**: SKILL.md 표·절차의 문서 이름에서 `.md`를 뺐고, `grep -n '^#'` 목차 읽기를 구글 문서 방식으로 바꿨다. 로컬 `G:`에서는 `.gdoc` 바로가기라 파일로 못 읽으므로 Docs 플러그인·커넥터로 읽는다.
- **남은 것**: Claude Code에서 Docs 플러그인으로 실제로 읽히는지 사용자가 확인. 안 읽히면 이 절차를 다시 정한다.
- **관련 파일**: `SKILL.md`

### ISSUE-009: 스크립트를 공개 저장소로 이전 (2026-11-21)
- **상태**: 🟢 해결 (2026-11-21)
- **배경**: 여러 LLM이 드라이브 폴더의 스크립트를 겹쳐 고치는 문제. 사용자 결정: 개인 데이터가 없으면 이 공개 저장소에 두고, 실행은 로컬, 결과물은 지정 폴더.
- **해결/조치**: 드라이브 `invest/fetch·sentiment·portfolio·tools`의 스크립트 11개를 `scripts/`로 옮김(드라이브 원본은 `invest/_보관/코드_20261121/`). `invest_common.py`가 종목 목록(`universe.csv`, 비공개)·결과 폴더(`OUTPUT_DIR`)·매매근거 태그(`KIWOOM_TAG`)를 공용 .env에서 읽는다. 스크립트·주석·시험 데이터에서 보유 종목·이름 제거. 자체 시험(selftest) 3개 통과, 재무·키움·시트 실제 실행 확인.
- **관련 파일**: `scripts/*`, 드라이브 `invest/README.md` 0절

### ISSUE-008: 매매일지 소급 입력 기준 정함 (2026-11-21)
- **상태**: 🟢 해결 (2026-11-21)
- **증상**: 키움 1년치와 대조하니 매매일지에 종목·일 단위 193건이 빠져 있었다(대부분 소액 반복 매수).
- **해결/조치**: 사용자 결정으로 기간 합산 입력. 같은 종목·구분·포지션ID 안에서 10일 넘게 쉬면 끊고, 절세 매매(같은 기간 같은 수량 매도·재매수)는 제외. SKILL.md "B-2"에 절차, `journal_reconcile.py`가 매매근거의 `기간합산 시작~끝`을 읽어 기간 전체를 기록된 것으로 보게 함. 날짜 정렬은 사용자가 한다.
- **관련 파일**: `SKILL.md`, `scripts/journal_reconcile.py`

### ISSUE-007: 키움 1년치 조회에서 국내 구간이 빠짐 (2026-11-20)
- **상태**: 🟢 해결 (2026-11-20)
- **증상**: `[경고] kt00015 … 조회 실패: 429 Client Error`. 이전 실행의 1년치 결과는 0건이었다.
- **원인**: 연속조회를 쉬지 않고 보내 키움의 요청 한도(429)에 걸림.
- **해결/조치**: 드라이브 `invest/fetch/kiwoom_fetch_trades.py`에 요청 간격(0.3초)과 429 재시도(1·2·4·8초) 추가. 재실행 결과 국내 118 + 해외 255건 정상.
- **관련 파일**: `invest/fetch/kiwoom_fetch_trades.py` (드라이브, 이 저장소 밖)
