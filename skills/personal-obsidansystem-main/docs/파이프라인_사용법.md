# PKM 시스템 도구 — 사용 설명서 (v14 기준)

이 문서는 옵시디언 PKM 시스템(v14 기준)을 유지보수하고 자동화하는 도구들의 사용법을 다룹니다. 핵심은 **NotebookLM을 활용한 전역 자동화 파이프라인**이며, 이를 통해 수백 개의 노트를 일관된 분류체계(domain, engine, topic, type)와 폴더 구조 안에 조직합니다.

---

## 1. 전역 자동화 파이프라인 (Orchestrator)

볼트(Vault) 내의 여러 문서들을 한 번에 묶어 NotebookLM의 강력한 문맥 분석을 거친 뒤, 도출된 속성을 기반으로 파일을 이동시키고 **링크까지 자동으로 관리해 주는 하프-오토메이션(Half-Automation) 파이프라인**입니다. 이름 변경 시 링크 깨짐을 방지하고 프론트매터를 정교하게 다룹니다.

### 1단계: 번들(Bundle) 생성
NotebookLM은 작은 문서를 수백 개씩 한 번에 처리하기 어렵기 때문에(최대 50개 소스 제한), 내용이 유사한 파일들끼리 묶어주는 과정이 필요합니다.
```powershell
python orchestrator.py merge "<볼트 경로>" --target 45
```
- `<내 문서>\my-skills-data\personal-obsidansystem-main\notebooklm_bundle` 폴더에 50개가 넘지 않도록 (기본적으로 45개 전후로 설정 권장) 텍스트 파일들이 묶입니다.
- 묶인 파일의 내부는 AI가 정확히 식별할 수 있도록 `========== [ FILE_SEPARATOR : ... ] ==========` 와 같은 가독성 높은 구분선이 적용되어 파싱 오류를 원천 차단합니다.
- 이 파일들을 NotebookLM에 소스로 일괄 업로드하고 `PKM_운용지침_v14.md`도 지시문으로 함께 업로드합니다.

### 2단계: 우선순위 기반 배치(Batch) 프롬프트 🚀
수백 개의 문서를 한 번에 분석하기 힘들기 때문에 **30개 단위**로 끊어서 분석하도록 프롬프트를 자동 생성합니다. 이때 **`00_Inbox`나 `2 AREA`, `3 Resources` 등에 방치된 레거시 노트(1순위)**부터 우선 추출합니다.

```powershell
python orchestrator.py batch-prompt "<볼트 경로>" --copy
```
- 화면에 출력된 마크다운 프롬프트가 클립보드에 바로 복사됩니다.
- 복사된 프롬프트를 NotebookLM 챗창에 붙여넣어 해당 30개의 노트를 분석시킵니다.
- NotebookLM이 마크다운 표(Table)로 추천 속성과 처리 제안을 답변하면, 그 텍스트를 그대로 복사하여 `response.md` 파일로 저장합니다. 
>💡 답변 형식이 표가 아닐 경우, 응답 텍스트를 파이썬 스크립트 등을 이용해 수동으로 CSV로 구축한 뒤 4단계로 바로 넘어갈 수 있습니다.

### 3단계: 응답 파싱 및 검증
NotebookLM이 출력한 제안 표가 규칙(v14)에 정확히 맞는지 검사하고 정제합니다.
```powershell
python orchestrator.py parse response.md
```
- 문법 오류나 축약된 경로가 없는지 검증 후 이상이 없으면 `response.csv` 파일로 자동 변환됩니다.

### 4단계: Vault 자동 반영 및 링크 일괄 수정 ✨
가장 강력한 기능입니다. 추천받은 CSV의 결과를 실제 옵시디언 볼트에 안전하게 반영합니다.
```powershell
python orchestrator.py apply "<볼트 경로>" response.csv
```
이 명령어 하나로 다음 작업이 한 번에 일어납니다:
1. **YAML 추가**: v14 기준 `domain`, `engine`, `topic`, `type` 속성을 추가합니다.
2. **폴더 이동**: `10_NOTE`, `20_THINKING`, `30_SYSTEM` 등 알맞은 폴더로 파일을 이동합니다.  
3. **제목 보존 및 우회**: AI가 억지로 제목을 짓지 못하게 `(유지)` 키워드를 강제하여 자동 이름 변경 체계를 비활성화함으로써 위키 링크 파괴를 방지합니다.
4. **링크 자동 업데이트 체인**: 폴더 계층이 바뀌거나 내부 위키링크가 얽혀있는 경우 볼트 전체(600여 개 파일)를 스캔하여 **기존 파일을 향해있던 `[[위키링크]]`를 새 경로로 남김없이 수정**합니다.

*(참고: 반영 전 `--dry-run` 옵션을 붙여 미리보기만 해볼 수 있습니다.)*

## 2. 수동 GUI 관리 도구 (pkm_manager.py)

자동화 대신, 소수의 노트를 직접 보면서 속성을 달거나 폴더 내용을 검수할 때 사용합니다.

```powershell
python pkm_manager.py
```
### 주요 기능
- **Vault 불러오기**: PC 내 옵시디언 Vault 선택
- **속성 덮어쓰기/추가**: v14 기준 `domain`, `engine`, `topic`, `type` 직접 선택 반영
- **선택 파일 path 갱신**: 현재 폴더 위치를 프론트매터 `path` 속성으로 기록

## 3. 안정성 원칙 (No Deletion)

시스템의 어떤 스크립트도 **결코 문서를 삭제하거나 파괴하지 않습니다.**

1. **안전한 외부 자동 백업 (`backupvault/`)**
   - 파일 이동, YAML 수정, 제목/링크를 변경하기 직전! 언제나 볼트 바깥쪽의 전용 백업 폴더인 **`내 문서/backupvault`** (예: `C:\Users\<user>\Documents\backupvault`)에 기존 원본이 즉시 복사됩니다.
   - 링크가 수정될 다른 문서들도 수정되기 전 모두 이곳에 안전하게 수정 내역 스냅샷이 기록됩니다.
2. **안전한 이동 로직**
   - 다른 폴더로 이관할 때, 만일 타겟 폴더에 이미 동일한 파일이 존재한다면 `conflict` 오류를 발생시키고 덮어쓰기를 방지합니다.

### ⚠️ AI 에이전트 직접 파일 조작 금지 규칙

> **볼트 내 파일을 이동하거나 이름을 바꿀 때 `write_to_file` + 원본 삭제 방식은 절대 사용하지 않는다.**
> 새 파일 생성 시 기존 `[[wikilink]]` 백링크가 전부 깨진다.

반드시 아래 우선순위로 처리한다:

| 상황 | 올바른 방법 |
|------|-------------|
| 소수 파일 이동 | `obsidian vault=<볼트 폴더 이름> move path="원본경로" to="대상경로"` |
| 파일명만 변경 | `obsidian vault=<볼트 폴더 이름> rename path="경로" name="새이름"` |
| 대량 배치 이동 | `python orchestrator.py apply "<볼트 경로>" response.csv` |
| YAML만 수정 | `obsidian vault=<볼트 폴더 이름> property:set path="..." name=필드 value=값` |

**Obsidian CLI는 볼트 폴더를 작업 위치(cwd)로 두고 실행한다** (`apply_gemini_recommendations.py`가 자동으로 그렇게 한다).  
(G: 드라이브 경로는 워크스페이스 미인식으로 오류 발생)

## 4. 2차 지식 베이스 추출 (LLM Wiki & Index)

현재 볼트 내의 문서 연결 상태(관계)나 메타데이터베이스를 **옵시디언 바깥 공간(`knowledge/` 등)으로 추출**하여 AI가 폴더 내부를 한눈에 스캔하게 합니다.
- **Index 스냅샷 생성**: 
  - Vault 안의 모든 프론트매터 스키마를 취합하여 요약본(`pkm_index.md`)으로 변환.
- **관계 위키(🕸) 생성 (예정/개선 중)**: 
  - 노트들 간의 촘촘한 연결망과 커뮤니티 구조를 읽어들여 2차 사료로 생성.

## 5. NotebookLM YAML 자동 분류 파이프라인 (추천)

최신 v14 지침에 맞춰 노트를 대량으로 정리할 때 가장 권장하는 **손실 없는(Non-destructive) 파이프라인**입니다. 기존 본문(`body`)을 통째로 덮어쓰지 않고 링크나 텍스트만 안전하게 파일 하단에 덧붙입니다.

### 1단계: 완벽한 YAML 전용 프롬프트 생성
Python 콘솔에서 아래 스크립트를 실행하거나 코드를 통해 `yaml_spec` 프롬프트를 복사합니다. 이 프롬프트는 AI에게 "절대 기존 본문을 훼손(body 덮어쓰기)하지 말고, `append_links`와 `append_body`만 쓰도록" 강제합니다.

```python
from notebooklm_prompts import select_prompt
print(select_prompt("yaml_spec"))
```

### 2단계: NotebookLM에 복붙하여 YAML 명세 얻기
번들링된 마크다운 문서들(또는 10~30여 개의 소스 노트)을 NotebookLM에 업로드한 뒤, 위에서 복사한 프롬프트를 입력합니다. NotebookLM이 아래와 같은 깔끔한 형태의 YAML 명세서를 반환합니다.

```yaml
vault: "<볼트 경로>"

notes:
  - stem: "원본 노트 제목"
    target_folder: "10_NOTE/자기"
    frontmatter:
      domain: 자기
      engine: principle
      topic: [성찰, 메타인지]
    append_links: ["연결할 관련 노트 1", "관련 노트 2"]
```

### 3단계: 안전한 일괄 반영 (Batch Apply)
반환된 YAML 텍스트를 복사해 `spec_업데이트.yaml` 같은 파일로 저장한 뒤, 아래 명령어로 볼트에 일괄 반영합니다.

```powershell
# 1. 먼저 오류가 없는지 미리보기(dry-run)
python -X utf8 pkm_batch_apply.py spec_업데이트.yaml --dry-run

# 2. 문제 없으면 실제 볼트에 적용 (링크 자동 추가, 폴더 자동 이동)
python -X utf8 pkm_batch_apply.py spec_업데이트.yaml
```

이 방식을 사용하면 옵시디언 내부 캐시망과 백링크 무결성이 100% 보존되며, 사용자 직접 수정 여부(해시 검사)까지 자동으로 체크되어 매우 안전하게 대량 정리가 가능합니다.
