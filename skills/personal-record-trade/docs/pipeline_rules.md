# 파이프라인 운영 규칙 (실수 방지용)

> 이 문서는 실제 작업 중 발생한 **모든** 실수들을 분류·기록하고, 동일한 실수가 반복되지 않도록 명문화한 규칙집입니다.
> **⚠️ 작업 전에 반드시 이 파일을 읽고 시작할 것.**

---

## A. 작업 후 반드시 검증 (가장 중요)

> 사용자가 가장 많이, 가장 강하게 지적한 문제.
> "테스트 좀 하라고", "작업 후 확인하는 습관을 들여라", "제대로 되어 있을 때까지 하라고"

### 규칙
1. **코드를 수정하면 반드시 실행하여 에러가 없는지 확인**한다
2. **구글 시트에 데이터를 넣으면 반드시 다시 읽어서 값이 맞는지 확인**한다
3. **대시보드를 수정하면 반드시 streamlit run으로 실행하여 화면이 뜨는지 확인**한다
4. "됐습니다"라고 말하기 전에 **실제로 작동하는지 증거(출력, 스크린샷)를 먼저 확보**한다
5. 한 곳을 고치면 **연관된 다른 곳이 깨지지 않았는지** 반드시 확인한다

### 구체적 체크 항목
- [ ] 코드 실행 후 에러 없음 확인
- [ ] 0원, NaN, 빈칸 등 이상값이 없는지 확인
- [ ] ZeroDivisionError 같은 엣지 케이스 점검
- [ ] 수식이 들어간 셀의 결과가 정상 범위인지 확인

## B. 데이터 정확성 — 복붙/추정 금지

> "ROIC가 왜 셋 다 똑같나", "EPS 0원????", "하이닉스가 75%라고? 뭔가 이상한데?"

### 규칙
1. **각 보고서/소스는 개별적으로 읽는다** — 하나의 값을 다른 소스에 복사하지 않는다
2. **해당 소스에 수치가 없으면 빈칸으로 남긴다** — 추정치를 만들어 넣지 않는다
3. 데이터 입력 후 **교차 검증**: 서로 다른 소스의 같은 지표가 동일하면 의심한다
4. **비정상적으로 보이는 값**(0, 음수, 100% 초과 등)은 반드시 원인을 찾고 확인한다
5. 보고서에서 **가능한 모든 지표**를 추출한다 — 목표가만 읽고 끝내지 않는다
   (EPS, PER, ROIC, ROE, OPM, PBR, EV/EBITDA, 매출, 영업이익 등)

## C. 구글 시트 입력 규칙

> "raw data에는 세 줄", "기업분석에는 종합 한 줄", "포지션 id는 비우고", "한 기업당 하나의 행인데 두 개가 들어가 있다"

### raw data 탭
- **소스 1개 = 행 1줄**. 보고서가 3개면 3줄, yahoo와 gurufocus가 있으면 2줄
- source 컬럼: `analyst_증권사명`, `yahoo`, `gurufocus` 등 출처 명시
- 한 종목당 한 줄 규칙이 아님 — 소스별로 나눈다

### 🔬 기업분석 탭
- **한 기업당 반드시 1줄** — 중복 행 금지
- 여러 소스의 데이터를 **종합/평균**하여 대표값으로 입력
- 기존 컬럼(ROIC%, 영업마진%, PER 등) **빠짐없이 매핑** — 누락 금지
- 포지션 ID는 **매수 시에만** 넣는다 (관심종목일 때는 비운다)
- 상태: '신규'가 아니라 적절한 상태값('관심종목' 등) 사용

### 🎯 비중조절신호 탭
- 포트폴리오 탭을 업데이트하면 **자동으로 업데이트되는 탭**이다
- ETF는 복잡한 밸류에이션 계산 없이 **모델비중 = 현재비중**으로 설정

### 데이터 저장 위치
- **마크다운 아티팩트에만 적고 끝내지 않는다** — 반드시 구글 시트에 기록
- 결과는 항상 구글 시트의 해당 탭에 파이프라인을 통해 저장

## D. 증권사 리서치 리포트 검색 파이프라인

> "pdf로 검색하는 게 아니라 다른 방법으로", "본문 텍스트만 추출하는 게 아니라 골라서", "네이버에서 검색하라고 한 적 없다"

### ❌ 하지 말 것
- `filetype:pdf`로 직접 PDF 검색하지 않는다
- 네이버 금융 스크래핑으로 대체하지 않는다
- 뉴스 기사 본문 텍스트만 긁어와서 끝내지 않는다
- 검색 방법을 사용자와 합의 없이 임의로 변경하지 않는다

### ✅ 올바른 순서 (투트랙)
1. **1단계 - 탐색**: `search_web`(구글 검색)으로 어떤 증권사가 어떤 리포트를 냈는지 리스트업
2. **2단계 - 선별**: 미래에셋, 신한, DS, IBK 등 신뢰할 수 있는 증권사의 리포트를 선택
3. **3단계 - 다운로드**: 선별된 리포트의 원문 PDF를 `data/report/{ticker}/`에 저장
4. **주의**: 신한투자증권 등 로그인 필요 사이트는 사용자에게 직접 다운로드 요청

### 저장 위치
- PDF: `data/report/{ticker}/증권사명_종목명_날짜.pdf`
- 웹 보충 텍스트: `data/report_web/{ticker}/`

## E. 이전 합의사항 존중

> "이전에 대화한 거 기억 안 나나?", "그때 로직 다 어디 갔나?", "밸류모델이 다르게 설정되게끔 만들어놨다. 이걸 왜 매번 알려줘야 하는지"

### 규칙
1. **사용자와 이전에 합의한 방법/로직이 있으면 그것을 따른다** — 임의로 변경하지 않는다
2. 합의한 내용이 기억나지 않으면 **이 문서와 SKILL.md를 먼저 확인**한다
3. 그래도 모르겠으면 **코드 파일(pipeline/)을 읽어서 기존 로직을 파악**한다
4. 확신이 없으면 **임의로 진행하지 말고 사용자에게 먼저 물어본다**

### 주요 합의 사항 기록
- 밸류에이션 모델: 성장주/가치주/ETF별로 다른 모델 적용 (시트에 이미 설정됨)
- 시총 계산: 구글파이낸스 함수 사용 (구글파이낸스는 망가지지 않는다)
- 데이터 소스 교차 검증: DART, Yahoo Finance, GuruFocus 세 가지를 병행
- 52주 신저가: yahoo에서 뽑아와서 성장주의 비중조절 하방열에 연결
- 성장 감쇄(fade): 사용자가 요청한 적 없음 — 임의 적용 금지

## F. 코드/대시보드 수정 원칙

> "대체 어떻게 확인하냐고. 직접 만들어보고 대시보드 실행해보고"
> "뜯어고쳐라 오류 나면 스스로 분석하고 고쳐가면서"

### 규칙
1. **Pydantic 모델(MetricObservation 등)에 필드를 추가/변경하면 관련 코드 전체 점검**
   - `source_method` enum에 없는 값 사용 금지 (dart_direct, rule, llm, calculated, market, manual만 허용)
   - extra 필드 금지 (Extra inputs are not permitted 에러 방지)
2. **변수 스코프 확인** — `ticker` 같은 변수가 정의 안 된 채 사용되지 않는지 확인
3. **ZeroDivisionError 방어** — 나눗셈 시 분모가 0일 수 있는 경우 반드시 방어 코드 추가
4. **타입 혼동 방지** — tuple과 str 비교 등 타입 불일치 에러 점검
5. 한 곳을 고치면 **연쇄적으로 깨질 수 있는 모든 곳을 확인**하고 고친다

## G. DART API 활용

> "dart는 왜 안 썼니?"

### 규칙
1. 한국 기업 분석 시 **DART API를 반드시 사용**한다 (dart-mcp 또는 dart_fetcher.py)
2. `.env`에 DART_API_KEY가 있다 — python-dotenv로 로드
3. DART에서 가져올 수 있는 데이터: 재무제표, 배당, 주요사항 등
4. DART와 Yahoo Finance와 GuruFocus — **세 가지를 교차 검증**한다

## H. LLM 판단 영역 vs API 데이터 영역

> "TAM을 40조로 잘못 설정한 것처럼", "LLM이 판단할 수 있게 계산식, 가정들이 모두 담겨야 한다"

### API로 가져오는 것 (확인 가능한 팩트)
- 매출, 영업이익, FCF, EBIT, NOPAT, 투자자본
- 현재가, 시총, PER
- 순부채, 자본총계

### LLM이 제공해야 하는 것 (판단 영역)
- TAM 크기와 정의, TAM 성장률 (CAGR)
- Peer 그룹 평균 PER
- 적정 WACC (산업별)
- 정상 PER (섹터 기준)
- 경쟁구도, 사이클 포지션 판단

### 규칙
- LLM 판단 영역의 값은 **근거(계산식, 가정)를 반드시 함께 기록**한다
- 임의의 숫자를 넣고 끝내지 않는다
