# AIEP 수업꾸러미 제작

교사가 정한 학년·교과·주제·차시·학습자 조건을 바탕으로 수업 내용과 자료를 설계하고, `templates/course-package.md` 표준에 맞춰 폴더에 정리한다. 마지막으로 AIEP 저작 도구의 성취기준, LCMS 콘텐츠, 파일/링크, 콘텐츠 속성, 공개 범위와 학습 순서에 맞춰 실제 입력 가능한 꾸러미로 변환한다.

이 스킬은 공통 수업 패키지 제작 체계의 AIEP 전용 어댑터다. 플랫폼 중립 설계와 응답 방식 구분은 [상위 학습 플랫폼 수업꾸러미 스킬](../teacherlesson-courseware-builder/SKILL.md)을 따른다.

## 시작할 때 확인할 것

- 필수 정보: 학년, 교과/과목, 주제 또는 단원, 수업 시간/차시, 원하는 결과물.
- 가능하면 확인: 학습자 선행 지식, 학급 특성, 수업 환경, 사용 가능한 자료, 평가 방식, 공개 범위.
- 일부 정보가 없어도 작업을 중단하지 않는다. 확인된 정보로 초안을 만들고, 가정과 미확인 항목을 표시한다. 정확한 교육과정 성취기준이 불명확하면 임의의 코드나 문구를 만들지 말고 후보/확인 필요로 남긴다.
- 개인정보가 포함된 명단, 학생 작품, 계정 정보는 사용자가 요청하지 않는 한 자료 폴더에 복사하거나 사이트에 올리지 않는다.

## 제작 절차

1. 요구 사항을 간단히 정리한다: 학년, 과목, 주제, 차시/시간, 학습자, 자료 조건, 결과물.
2. 성취기준을 확인한다. 공식 교육과정 자료 또는 AIEP의 성취기준 패널에서 과목·학년을 맞춰 찾는다. 사이트에서 확인한 기준은 코드와 원문을 그대로 기록하고, 수업 목표와 활동이 어떻게 이어지는지 설명한다.
3. 수업 흐름을 도입-탐구/학습-적용-정리/평가 순으로 설계한다. 차시, 예상 시간, 교사 행동, 학습자 행동, 확인할 증거를 적는다.
4. 필요한 학습 콘텐츠를 구분한다: LCMS 검색 콘텐츠, 직접 준비한 파일, 링크, 보충자료. 찾을 수 없는 LCMS 콘텐츠는 있는 것처럼 말하지 말고 교체 가능한 자료 조건이나 파일 대안을 제시한다.
5. 결과를 `templates/course-package.md`에 맞춰 구성하고, 자료 파일이 여러 개면 `자료/`, `출처/`, `미리보기/` 하위 폴더를 만들며 파일명과 출처를 기록한다. 원본 자료는 가급적 보존하고 새로 만든 자료만 패키지에 둔다.
6. 사이트 입력표를 만든다. 꾸러미명, 과목, 성취기준, 단원 행, 콘텐츠 배치 순서, 각 콘텐츠의 제목/설명/학습 유형/성취기준 연결/보충자료, 공개 여부, 순차학습 여부를 정리한다.
7. 검토한다: 목표-활동-평가의 연결, 연령 적합성, 사실 정확성, 저작권/출처, 접근성, 링크 작동, 파일 형식, 콘텐츠 순서.
8. 사용자가 사이트 제작을 요청하면 저장소의 `skills/ego-browser/SKILL.md`와 최신 `ego-browser skill` CLI 안내를 확인하고 Ego Lite `ego-browser`를 사용한다. 기존 TaskSpace와 사용자 페이지 상태를 먼저 확인하고, 제공된 경북 AIEP URL을 사용한다. 과목과 성취기준을 선택하고, 캔버스의 단원 행에 요소를 배치하며, 속성을 입력하고 미리보기에서 학습자 화면을 확인한다. 사이트 조작 전 현재 저장 상태를 확인하고 맞는 값을 보존한다.
9. 임시저장과 최종 등록은 구분한다. 사용자가 온라인 등록을 분명히 요청한 경우에만 등록하기를 누른다. 등록 전 꾸러미명, 공개 범위, 모든 배치, 출처/저작권, 목차와 플레이어 미리보기를 최종 확인한다. 전체 공개가 기본이라고 가정하지 않는다.
10. 작업을 마치면 생성한 폴더/파일, 사이트 반영 여부, 남은 미확인 사항과 문제 해결 내용을 짧게 보고한다.

## 사이트 운영 기준

- 경북 사이트 주소: <https://aiep-courseware.gbe.kr/course/new?snb=objective>
- 페이지에서 현재 확인된 요소와 문서로 확인된 기능은 `references/site-capabilities.md`를 따른다.
- 매뉴얼에 나오지 않거나 이번 화면에서 검증하지 않은 지원 형식/용량/브라우저 제한은 추측하지 않는다. 업로드 전에 화면의 현재 안내를 확인하고, 필요하면 교사에게 확인한다.
- 현재 학습자 미리보기에서 파일/PDF 열람은 확인할 수 있으나, 주관식 입력·학생별 제출함은 확인하지 않았다. 학생 답변 수집이 목표라면 별도 도구가 필요한지 확인한다.
- 드래그 앤 드롭이 불안정하거나 성취기준/LCMS 항목이 검색되지 않으면 무리하게 다른 요소를 등록하지 않는다. 화면 상태를 기록하고 파일/링크 대안을 마련한다.
- 콘텐츠를 등록한 뒤 목차 미리보기와 통합학습플레이어 미리보기에서 제목, 순서, 설명, 링크/자료 접근을 확인한다.

## 결과물 위치와 이름

사용자가 위치를 지정하지 않으면 현재 프로젝트 작업 폴더 아래에 과업별 폴더를 만든다.

```text
output/<YYYY-MM-DD>-<짧은-수업명>/
├── course-package.md
├── 자료/
├── 출처/
└── 미리보기/
```

다른 사용자가 찾기 쉽도록 파일명에 학년, 과목 또는 주제, 자료 유형을 넣는다. 사이트에 실제 올린 파일을 로컬 폴더에도 정리한다. 별도 요청이 없으면 사이트 계정 자격 증명이나 개인 학생 자료를 저장하지 않는다.

## 체크리스트

- [ ] 대상 학년, 교과, 주제, 시간과 결과물이 명확하거나 가정으로 표시됨
- [ ] 성취기준은 공식 출처에서 확인했거나 확인 필요로 표시됨
- [ ] 수업 목표, 활동, 평가 증거가 서로 연결됨
- [ ] 단원(캔버스 행)과 콘텐츠의 순서가 학습 흐름을 따름
- [ ] 콘텐츠 속성(제목, 설명, 성취기준 연결, 학습 유형, 보충자료)이 작성됨
- [ ] 파일/링크에는 출처와 사용 조건/저작권 정보가 기록됨
- [ ] 공개 범위와 순차학습 선택이 의도에 맞음
- [ ] 목차와 학습자 미리보기에서 최종 확인됨
- [ ] 온라인 등록 여부 및 미해결 이슈가 기록됨
