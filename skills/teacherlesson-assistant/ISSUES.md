### ISSUE-041: 수업 형태에 맞는 단계별 교사 안내 만들기 (2026-11-26)
- **상태**: 🔵 생성 틀·화면 구현, 다른 수업 형태와 교실 사용 확인 필요
- **요청**: 수업 흐름에 교사와 학생이 실제로 할 일을 쉽고 자세히 넣는다. 연극·모둠 발표라면 발표 안내, 듣는 방법, 모둠별 발표, 돌아보기처럼 필요한 단계를 나누고, 실험·탐구·토의·만들기·연습·감상은 각 수업 형태에 맞는 흐름을 만든다.
- **생성 방식**: Gemini 1차 요청이 지도서에서 수업 형태·목표·준비물·4~8개 단계·시간 배분을 잡고, 2차 요청이 그 뼈대를 유지하며 각 단계를 교사 행동·교사 발문·학생 행동·예상 반응·막힐 때 지원·확인할 점으로 채운다. 40분을 맞추고 차시 밖 내용을 섞지 않는다.
- **근거 구분**: 지도서에서 확인한 활동과 일반적인 운영 제안을 구별한다. 학생 반응은 예시로 표시한다. 지도서에 없는 모둠 수·발표 순서·정답·준비물은 만들어내지 않는다.
- **화면**: 수업 형태를 표시하고, 수업 진행 모드에서 현재 단계의 교사 안내·발문·학생 활동·예상 반응을 따로 보여 준다. 흐름 편집에서도 새 항목을 보존·수정하고, 옛 `do/say/tip` 흐름은 계속 읽는다.
- **확인**: 11/27 사회 차시를 새 틀로 생성해 7단계·40분 배분을 확인했다. 합쳐져 나온 단계명은 단계별 안내를 만들기 전에 나누고, 예상 반응에 실제 학생의 가족·여행 경험을 꾸며 쓴 경우에는 특정 교과 맥락을 넣지 않는 중립적인 예시로 바꾼다. 국어 PDF 2개는 각각 40MB(52쪽, 글자 약 6만 자)로 확인되어, 글자를 뽑아 쪽 표시가 있는 텍스트로 Gemini에 보내도록 바꿨다. 사회 PDF는 약 3MB다. 11/26 자동 준비에서 국어 두 차시가 Gemini 모델 혼잡 시간 초과·CLI 오류로 실패했으나, 한 차시는 재시도로 생성했고 다른 차시는 NotebookLM에서 정확한 국어 지도서 소스 하나를 선택해 5단계·40분 흐름으로 준비했다. 결과는 로컬 데이터 폴더에만 저장했다.
- **오류 처리**: `gemini_ask()`가 여러 대체 모델까지 시도한 뒤 실패를 알리면 같은 요청을 바로 다시 보내지 않는다. JSON 형식 오류만 수정 요청으로 한 번 더 생성한다.
- **다음 확인**: Gemini 연결 실패 때 스킬의 NotebookLM 수동 대체 절차를 사용한다. 탐구·실험·연극·발표 등 다른 형태의 단계 구성도 교사가 확인한다. 직접 고친 기존 흐름은 자동으로 다시 만들지 않는다.
- **관련 파일**: `prepare_lessons.py`, `assistant_server.py`, `web/index.html`
