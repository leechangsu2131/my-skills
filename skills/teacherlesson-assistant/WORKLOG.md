### 지도서에서 수업 흐름 만들기

1. `notebook_sources.py`가 지도서 PDF에서 글자를 뽑아 `notebooklm/<과목>/<단원>.md`에 차시별 구간을 만든다.
2. `prepare_lessons.py`는 해당 차시 구간을 우선 가져와 Gemini CLI로 수업흐름 JSON을 만든다. 구간이 없으면 Supabase 차시의 PDF 경로에서 쪽을 발췌한다.
3. 결과는 `flows/<lesson_id>.json`에 저장하고 수업 비서가 읽는다.

NotebookLM 단추는 과목 노트북을 열고 질문을 준비하는 별도 기능이다. 자동 수업 준비 단추는 NotebookLM에 직접 질문하지 않고, NotebookLM에 올릴 때 쓰는 같은 `.md` 소스를 Gemini에 전달한다.

### 고친 문제

- 시간표가 가리키던 옛 `pdf_splits` 경로가 새 PC에 없었다. 같은 단원 폴더의 전체 지도서 PDF를 찾고 진도표 쪽수로 자르도록 경로 해석을 보강했다.
- 실제 차시 선택 목록은 첫 미완료 차시 뒤 80개까지만 내려줬다. 수학 6단원은 113번째부터라 목록에 나타나지 않았다. 이후 차시는 모두 표시하고 단원·차시·제목 검색을 추가했다.
- 같은 날짜·교시에 완료 수업이 여러 개 남아 있으면 Supabase 응답의 첫 행(이 사례는 수학 1차시)을 화면이 선택했다. 예정 차시를 우선하고, 전부 완료라면 교육과정 순서상 가장 뒤 차시를 보여주도록 고쳤다. 11월 23일 4교시 수학은 1차시와 4차시가 모두 `done`으로 있어 1차시가 4차시를 가리고 있었다.
- `실제로 할 차시 고르기`는 화면에서 선택한 차시를 오늘부터 다시 배치한다고 안내했지만, 서버는 `target_date`를 무시하고 과목 전체에서 가장 이른 달력 슬롯과 비교했다. 11월 24일 국어에서 교사가 고른 `lesson-0410`이 4월 21일에 그대로 남는 사례를 확인했다. 선택한 차시를 요청 날짜·현재 교시의 과목 슬롯으로 옮기고, 앞 차시는 교육과정 순서로 완료 처리하도록 고쳤다. 진도 API가 오류를 돌려줄 때 화면이 조용히 실패하던 부분도 오류 메시지를 표시하도록 보강했다. 기존 선택 기록에 맞춰 `lesson-0410`을 11월 24일 3교시로 옮겼고, 오늘 수업 API에서 해당 차시가 보이는 것을 확인했다.
- Supabase 이관 전 검토가 필요하다는 교사 확인을 받은 뒤, 먼저 들어갔던 2학기 복사본을 되돌리고 검토표를 만들었다. 확인 후 다시 이관했다. 검토표는 `reports/semester2_progress_review_2026.csv`다.
