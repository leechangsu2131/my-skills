# T52 — 🌙 자동 준비 질문문(PROMPT) 개선안

작성: claude-web-162 · 2026-11-26 · 대상: `prepare_lessons.py` 의 `PLAN_PROMPT`·`DETAIL_PROMPT`
**이 문서는 안(案)이다. 코드는 고치지 않았다.** 교사가 고르면 아래 두 블록을 그대로 코드에 붙여 넣으면 된다.

> 참고: 일을 맡길 때는 `PROMPT` 하나였지만, 지금 코드는 질문이 둘이다 — ① `PLAN_PROMPT`(수업 형태·단계 뼈대·분 배분) → ② `DETAIL_PROMPT`(단계마다 교사 행동·발문·학생 활동·예상 반응). 둘 다 다룬다.

## 한눈에

| 넣어 달라던 것 | 어디에 넣었나 | 한 줄 |
|---|---|---|
| 시간 배분 원칙 | `PLAN_PROMPT` | 합계 정확히 40분, 도입·마무리 3~5분, 한 단계 12분 이하, 교사 설명만 하는 단계 5분 이하, 학생 활동 절반 이상 |
| 좋은 발문 기준(열린 질문) | `DETAIL_PROMPT` | 단계마다 열린 질문 1개 이상, "맞나요?"처럼 예·아니요로 끝나는 질문만 두지 않기, 한 번에 하나만 묻기 |
| 학생 경험 연결 | `DETAIL_PROMPT` | 도입·첫 활동에 경험을 묻는 **발문**을 넣되, 예상 반응에는 학생의 이야기를 지어내지 않음 |
| 3학년 수준 말 | `DETAIL_PROMPT` | 학생에게 하는 말은 한 문장 30자 안팎·한 문장에 한 가지·어려운 한자어 풀기·"~해 볼까요?" |

지금 문안에는 이미 있는 것(근거 없는 내용 지어내지 않기, 발표 단계 나누기, 운영 제안 표시, 개인 일화 금지)을 **그대로 두었다.** 새로 더한 것만 아래 표에 이유와 함께 적었다.

## 새 문안 (코드에 붙여 넣는 형태 그대로)

`{{ }}` 는 파이썬 `.format` 에서 중괄호 글자를 뜻하니 **그대로** 둔다. 자리표시자는 지금과 같다: `{file} {subject} {publisher} {unit} {lesson} {title} {plan} {correction} {cautions}`.

```python
PLAN_PROMPT = """@{file} 이 자료는 초등학교 3학년 {subject} 교사용 지도서({publisher}) 가운데 「{unit}」 {lesson}차시 「{title}」 부분입니다.
지도서에서 이 한 차시의 학습 목표·준비물·수업 형태·실제 활동을 읽고, 40분 수업의 단계 뼈대만 JSON 하나로 답하세요. 설명 문장이나 ``` 표시는 쓰지 마세요.

{{"lesson_type":"예: 실험·탐구, 토의, 만들기, 연극·발표, 기능 연습, 읽기·감상",
 "goal":"학습 목표 한 문장", "materials":["지도서에 나온 준비물"],
 "steps":[{{"name":"단계 이름", "minutes":5, "purpose":"이 단계에서 하는 일", "flag":"keep 또는 cut 또는 빈 문자열"}}],
 "homework":"숙제·다음 시간 준비물(없으면 빈 문자열)",
 "pages":"근거 쪽수"}}

규칙
[단계 나누기]
- 단계는 4~8개. 도입·전개·정리만 기계적으로 나누지 말고 이 차시의 실제 활동이 드러나게 쪼갭니다.
- 단계 이름은 학생이 하는 일로 짧게 짓습니다(예: "자석에 붙는 물건 찾아보기"). 이름에 "및"이나 "과/와"로 서로 다른 활동을 묶지 않습니다.
- 서로 다른 일을 한 단계에 묶지 않습니다(예: "활동지 작성 및 발표"는 작성·발표 안내·발표·듣고 반응하기를 나눔). 발표가 지도서 활동에 있으면 최소한 "발표 방법과 듣는 약속 안내"와 "발표·듣는 학생의 반응"을 따로 둡니다. 모둠별 차례가 필요하면 발표 단계를 더 나누되 모둠 수·순서는 지어내지 않습니다.
- 탐구·실험은 질문·예상·준비·실행·관찰·설명 중 필요한 흐름을, 토의는 쟁점·생각·근거·공유·정리 중 필요한 흐름을, 만들기는 계획·제작·공유·돌아보기 중 필요한 흐름을 씁니다. 이는 참고이며 모든 형태에 억지로 맞추지 않습니다.
- 지도서에 없는 모둠 수·발표 순서·도구·평가 기준을 지어내지 않습니다. 정해져 있지 않으면 일반적인 운영 단계만 둡니다.
[시간 배분: 합계는 정확히 40분]
- minutes 는 1 이상의 정수입니다. 답하기 전에 모든 단계의 분을 더해 정확히 40인지 한 번 더 확인합니다.
- 지도서에 활동별 시간이 적혀 있으면 그 비율을 우선하고 합이 40분이 되게 맞춥니다. 적혀 있지 않으면 아래를 기본으로 합니다.
  · 도입(지난 시간·경험 떠올리기, 목표 알기) 3~5분, 마무리(배운 것 말하고 돌아보기) 3~5분, 나머지는 학생이 직접 해 보는 활동에 씁니다.
  · 3학년은 한 가지에 오래 집중하기 어렵습니다. 한 단계는 길어도 12분을 넘기지 말고, 교사가 설명만 하는 단계는 5분 이하로 합니다. 더 긴 활동은 안내·해 보기·나누기로 나눕니다.
  · 학생이 직접 말하거나 손을 움직이는 시간이 40분의 절반 이상이 되게 합니다.
- flag: 이 차시의 학습 목표를 이루는 활동과 마무리는 "keep", 시간이 모자라면 줄여도 목표를 이루는 보충·심화 활동은 "cut", 나머지는 "". 줄일 만한 활동이 없으면 cut 이 없어도 됩니다. 마무리 단계는 cut 으로 하지 않습니다.
[근거]
- 반드시 「{title}」 이번 차시만 씁니다. 묶음 차시면 한 시간 분량을 골라 구성합니다.
- 이 차시의 지도서 근거가 부족하면 없는 내용을 채우지 말고 목적에 "지도서에 안내 없음"을 적습니다.
{correction}{cautions}"""

   "student_actions":["학생이 할 말이나 행동"], "expected_responses":["예상 학생 반응 예시"],
   "teacher_support":"반응이 없거나 어려워할 때 이어갈 안내", "check":"교사가 확인할 점",

규칙
[뼈대 지키기]
- 단계 수·순서·이름·분은 뼈대와 정확히 같게 둡니다.
- 이름에 서로 다른 활동이 "및"으로 묶여 있더라도 안내·수행·공유처럼 교사 안내가 달라지는 일은 한 단계씩 나누어야 합니다. 발표는 발표자 안내·발표·듣는 학생의 반응이 각각 보이게 합니다.
[교사 안내]
- teacher_actions 와 student_actions 는 단계마다 2~4개를 짧은 순서 목록으로 씁니다. 막연한 "활동한다" 대신 무엇을 펼치고, 말하고, 보여 주고, 만들고, 기록하고, 발표하는지 씁니다. 질문을 한 뒤에는 "잠깐 생각할 시간을 줍니다"처럼 기다리는 일도 적습니다.

[학생 반응]

[분량]
- 목록 칸(teacher_actions·teacher_prompts·student_actions·expected_responses)은 단계마다 항목 4개 이하, 각 항목은 한두 문장으로 씁니다. teacher_support 는 두 문장 이하, check·tip 은 한 문장으로 씁니다.
{correction}{cautions}"""

## 무엇을 왜 바꿨나

| 바꾼 곳 | 이유 (코드·지금 문안 근거) |
|---|---|
| PLAN: 합계 "정확히 40분" + 답하기 전 한 번 더 더해 보기 | `parse_plan` 이 합계 ≠ 40 이면 실패시키고 1번 다시 묻는다. 처음부터 맞추게 해 재시도·실패를 줄인다. |
| PLAN: 단계 이름에 "및"·"과/와" 금지, 학생이 하는 일로 짓기 | 코드가 "및" 이름을 반으로 기계적으로 쪼갠다(`parse_plan`). 모델이 미리 나누면 억지 쪼개기("운영 제안: …에 집중합니다.")가 줄고, 화면의 단계 이름도 읽기 쉽다. 세부 단계가 12개를 넘으면 실패하는 점도 피한다. |
| PLAN: 도입·마무리 3~5분, 한 단계 12분 이하, 교사 설명만 5분 이하, 학생 활동 절반 이상 | 3학년이 한 가지에 오래 집중하기 어렵다는 교육 상식에 근거한 **기본값**(교사가 정한 기준이 저장소에 없음 → 아래 "교사가 정해 줄 것"). 지도서에 시간이 적혀 있으면 그것을 우선하게 해 지도서 근거를 해치지 않는다. 4단계라면 12분 한도로도 40분이 가능하다(예: 4+12+12+12). |
| PLAN: flag — 마무리는 cut 금지, 줄일 활동이 없으면 cut 없어도 됨 | '지금 할 일' 화면에서 시간이 모자랄 때 cut 단계를 줄이는데, 마무리가 줄어드는 일을 막는다. cut 을 억지로 만들지도 않게 한다. |
| DETAIL: 열린 질문 1개 이상·예/아니요 질문만 금지·한 번에 하나만 | 지금은 "실제로 쓸 수 있는 발문 1~3개"뿐이라 닫힌 확인 질문만 나올 수 있다. |
| DETAIL: 경험 연결은 **발문**으로, 예상 반응은 **관찰·생각 문장**으로 | `PERSONAL_STORY`(저는·나는·가족·친구랑·어제 …)에 걸린 예상 반응은 코드가 모두 "학생마다 경험과 생각이 다를 수 있어요…"로 바꿔 버린다. 경험을 묻는 발문을 넣으라고만 하면 예상 반응이 필터에 걸려 같은 문장으로 뭉개진다. 그래서 어떤 말투를 쓰면 걸리는지 알려 준다. |
| DETAIL: 3학년 수준 말(30자 안팎·한 문장에 한 가지·한자어 풀기·한 번에 한 동작) | 지금은 "쉽게 씁니다"뿐이다. 학생에게 하는 말(발문·학생 행동·예상 반응)과 교사만 읽는 칸(교사 행동·확인점)을 나눠, 어른 말투를 그대로 읽게 되는 일을 줄인다. |
| DETAIL: 분량 상한(목록 4개·문장 수) | `parse_flow` 는 목록을 5개·항목 500자, support 600자·check/tip 400자에서 **말없이 자른다**. 상한을 알려 주어 뒤쪽 내용이 잘려 나가지 않게 한다. |
| DETAIL: 규칙을 `[소제목]`으로 묶음 | 규칙이 많아져 읽기 어려워지는 것을 막는다(모델과 사람 모두). |
| 그대로 둔 것 | JSON 모양·키 이름, 근거 없는 내용 금지, "운영 제안:" 표시, 개인 일화 금지, 발표 단계 나누기, 이번 차시만 쓰기, `{correction}{cautions}` 자리. |

## 코드와 맞는지 (이 작업에서 확인한 것)

작업 환경에서 Gemini 는 부를 수 없어, **문안의 형식**만 확인했다.

- 위 두 블록을 이 문서에서 읽어 실제 `prepare_lessons.py` 가 쓰는 값과 같은 모양으로 `.format` 했다 → 오류 없음, 자리표시자 집합이 지금 문안과 같다.
- 문안 속 JSON 예시를 `json.loads` 했다 → 읽힌다. 키 이름이 지금과 같다(`PLAN`: lesson_type·goal·materials·steps[name·minutes·purpose·flag]·homework·pages, `DETAIL`: 위 키 + teacher_actions·teacher_prompts·student_actions·expected_responses·teacher_support·check·tip·flag).
- 새 규칙을 따랐다고 가정한 **손으로 만든** 답(6단계·합계 40분·한 단계 12분 이하·열린 질문·일반 문장 예상 반응)을 `parse_plan`·`parse_flow` 에 넣었다 → 통과, 예상 반응이 필터 문장으로 바뀌지 않음. 문안이 권하는 예상 반응 예시("모양이 둥글어요." 등)는 `PERSONAL_STORY` 에 걸리지 않고, 금지한 말투("저는 어제 …", "우리 가족은 …")는 걸린다는 것도 확인했다.
- 이 확인은 임시 스크립트로 했고 저장소에 넣지 않았다(문안을 바꾸는 사람이 같은 방법으로 다시 확인하면 된다: 이 문서의 `python` 블록을 읽어 실행 → `.format` → `json.loads` → `parse_plan`·`parse_flow`).
- 못 확인: **실제 Gemini 가 이 문안을 얼마나 잘 따르는지**(확인 필요 — 아래 비교).

## 교사 PC 에서 해 볼 것 (적용 순서)

1. **옛 결과 백업**: 데이터 폴더의 `flows` 에서 비교할 차시 2~4개(탐구·토의·만들기·연극/발표 각 1개)의 `*.json` 을 다른 이름으로 복사해 둔다.
2. **문안 바꾸기**: `prepare_lessons.py` 의 `PLAN_PROMPT`·`DETAIL_PROMPT` 를 위 블록으로 바꾼다(교사 PC 의 Claude Code 에게 "T52 문안 적용"). 바꾼 뒤 `python -m pytest tests/test_prepare_lessons.py` 통과 확인.
3. **다시 만들기**: `python prepare_lessons.py --date <날짜> --redo` (자동으로 만든 흐름만 덮어씀. 사람이 고친 흐름은 안 건드림).
4. **옛/새 비교**(아래 표). 새 쪽이 더 나쁘면 옛 문안으로 되돌린다(코드가 아니라 문안 두 개뿐이라 쉽다).

| 볼 것 | 좋은 모습 | 나쁜 모습(문안이 안 먹힘) |
|---|---|---|
| 시간 합계 | 40분, 결과 줄에 "시간 합계 … 확인 필요"가 안 뜸 | 실패("단계 시간 합계가 40분이 아님")가 늘어남 |
| 한 단계 길이 | 12분 이하, 교사 설명만 하는 단계 5분 이하 | 15~20분짜리 단계 |
| 발문 | 단계마다 "왜/어떻게/무엇이 달라졌나요"가 1개 이상, 도입에 경험 발문, 마무리에 돌아보기 | "맞나요?", "알겠죠?"만 있음 |
| 예상 반응 | 관찰·생각 문장("모양이 둥글어요.") | "학생마다 경험과 생각이 다를 수 있어요…"가 거의 모든 단계에 똑같이 나옴(필터가 대신 쓴 것 = 말투 지시가 안 먹음) |
| 말 | 한 문장이 짧고 쉬움 | 길고 어려운 한자어 |
| 실패 | 실패 줄이 늘지 않음(`prepare_status.json` 의 fail 수) | 형식 오류 재시도·실패 증가(문안이 길어져 모델이 놓침) |

## 교사가 정해 줄 것 (제가 정한 기본값 — 바꾸고 싶으면 알려 주세요)

1. 도입·마무리 각 **3~5분**, 한 단계 **12분 이하**, 교사 설명만 하는 단계 **5분 이하**가 맞는지(과목에 따라 다를 수 있음: 체육·음악은 연습이 길 수 있음).
2. 열린 질문을 **단계마다 1개 이상** 요구하는 것이 과한지(도입·정리 정도로 줄일 수도 있음).
3. "경험 연결 발문"을 모든 과목 도입에 넣어도 되는지(기능 연습 수업에는 어색할 수 있어 "수업 형태에 맞으면"으로 약하게 썼음).

## 한계

- 문안 길이가 늘어난다(글자 수: `PLAN_PROMPT` 1,055 → 1,630자 약 1.55배, `DETAIL_PROMPT` 1,446 → 2,499자 약 1.73배, 자리표시자를 예시 값으로 채웠을 때 기준). 무료 flash 모델이 규칙을 놓칠 수 있어(위 비교표의 '실패' 줄) 실제 차시로 확인이 필요하다.
- 기본값(3~5분·12분·5분·절반)은 일반적인 교육 상식에서 가져온 것이고 이 교사·학교 기준이 아니다.
- 코드의 필터(`PERSONAL_STORY`)와 "및" 쪼개기는 그대로다. 문안이 먹히면 이 코드의 개입이 줄어들 것으로 **추정**한다.
