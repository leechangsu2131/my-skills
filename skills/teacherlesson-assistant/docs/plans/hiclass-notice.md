# 설계 메모: 하이클래스 알림장 올리기 (T85, ISSUE-008 첫째)

2026-11-27, claude-web-소연. **설계만** 했다. 코드는 바꾸지 않았고 하이클래스에 접속하지 않았다.

## 지금 상태

- 화면의 `📢 알림장·숙제` 칸 → `복사하고 하이클래스 열기`. 글은 클립보드로만 가고, 붙여 넣기와 게시는 교사가 한다.
- 글은 차시 기록의 `notice` 칸에 저장된다(`/api/session` → `data_dir()` 의 `sessions/`).
- 하이클래스 주소는 설정 `hiclass_url`. `open_window` 로 열기만 한다.
- `admin-hitalk-sender/hitalk_sender.py` 는 **Selenium + 원격 디버깅 9223**, 전용 프로필(`launch_chrome_hiclass.bat`, `%TEMP%\hiclass_chrome_profile`), 교사가 직접 로그인. ISSUE-008 에 적힌 9222 와 다르다.

## 제안: "채우기까지만" 먼저

게시하면 학부모에게 알림이 갈 수 있어 되돌리기 어렵다(추정). 그래서 **1단계는 쓰기 칸을 채우기만 하고, 게시 단추는 교사가 하이클래스에서 직접 누른다.** 붙여 넣기 수고는 없어지고, 잘못 게시될 길은 코드에 없다.

2단계(자동 게시)는 1단계를 몇 주 써 본 뒤 교사가 원할 때만 한다.

## 흐름

1. 교사가 알림장 칸에 글을 쓴다.
2. `미리보기` → 서버가 올라갈 글, 대상 반, 연결 상태를 돌려준다. 하이클래스에는 아무것도 쓰지 않는다.
3. 교사가 확인하고 `하이클래스에 채우기` 를 누른다.
4. 서버가 알림장 쓰기 화면을 열고 반을 확인한 뒤 제목·본문을 넣는다.
5. 다시 읽어 넣은 글이 같은지 확인하고, "하이클래스에서 확인 후 게시를 누르세요" 를 보여 준다.

어느 단계든 실패하면 지금 방식(복사하고 열기)으로 돌아간다.

## API 모양 (초안)

`POST /api/notice/preview`

```json
{"date": "2026-11-27", "title": "11월 27일 알림장", "body": "1. 수학익힘 40쪽"}
```

```json
{"status": "success", "target": "○학년 ○반", "title": "…", "body": "…",
 "warnings": ["본문에 이름처럼 보이는 낱말이 있어요"], "preview_id": "…"}
```

`POST /api/notice/fill`

```json
{"preview_id": "…"}
```

- 글을 다시 받지 않고 `preview_id` 로 미리 본 글만 넣는다. 한 번 쓰면 없어지고 10분 뒤 만료.
- 2단계의 `/api/notice/post` 는 같은 방식에 `"confirm": true` 를 더하고, 설정에서 따로 켜야만 동작한다(기본 꺼짐).

## 안전 장치

- 지금의 `_trusted()`(Host·Origin 검사)를 그대로 쓴다. 이 PC 의 다른 프로그램은 막지 못하므로 `preview_id` 를 거치게 한다.
- 설정 `TEACHERLESSON_ASSISTANT__NOTICE_DRY_RUN=true` 면 쓰기 화면까지만 가고 글을 넣지 않는다.
- 반 이름이 설정과 다르거나 확인할 수 없으면 멈춘다.
- 쓰기 칸에 이미 글이 있으면 덮어쓰지 않고 멈춘다.
- 같은 날 이미 채운 기록이 있으면 한 번 더 묻는다.
- 알림장 글은 `data_dir()` 밖에 남기지 않는다. 로그에는 길이와 성공 여부만, 화면 캡처는 저장하지 않는다(2026-11-27 캡처에 학생 정보가 올라간 일이 있었다).
- 비밀번호 자동 입력은 하지 않는다.

## 구현할 때

- 크롬 연결은 하이톡과 **같은 프로필·포트(9223)** 를 쓰면 로그인을 한 번만 해도 된다. 하이톡 발송 중에는 탭이 섞이지 않게 알림장 전용 탭을 새로 연다. `ensure_single_hitalk_tab` 은 주소에 `hitalk` 이 든 탭을 세므로 알림장 주소에 그 말이 있는지 확인한다.
- 연결 도구: `_shared/cdp_tab.py` 는 9222 고정이라 그대로는 못 쓴다. 포트를 인자로 받게 하거나 하이톡처럼 Selenium 을 쓴다.
- 새 파일 `hiclass_notice.py` 에 화면 조작을 모으고, 서버는 부르기만 한다.
- 시험은 가짜 화면 객체로: 미리보기 없이 채우기 거절, 만료, 반 불일치, 칸에 글 있음, DRY_RUN.

## 확인 필요 (교사 PC, 코드를 짜기 전에)

1. 알림장 쓰기 화면의 주소와 들어가는 순서.
2. 제목·본문 칸의 모양(일반 입력칸인지 편집기인지), 선택자.
3. 대상 반을 고르는 방식, 임시 저장 기능이 있는지.
4. 게시하면 학부모에게 알림이 바로 가는지, 고치거나 지울 수 있는지.
5. 자동 입력이 하이클래스 이용약관에 어긋나지 않는지.
6. 평소 알림장을 교시별로 쓰는지 하루에 하나로 모아 쓰는지. 하나라면 그날 차시의 `notice` 를 모아 미리보기에 채운다.
