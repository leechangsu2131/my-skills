### ISSUE-006: 저장 결재선 역할·순번 검증 강화 (2026-11-25)
- **상태**: 🔵 진행 중

- **확인**: `admin-neis-bot/ISSUES.md`의 검증된 흐름은 결재자 지정 창에서 구분을 먼저 고르고 `selectRows([행])`와 `btn1.click()`으로 한 명씩 넣은 뒤 `atrzScNm` 및 순서를 확인하는 방식이다.

- **다음 단계**: 확장 v1.7.2를 재로드한 뒤 교사가 선택한 미상신 건으로 추가·저장 결과를 확인한다. 최종 상신은 별도 사용자 확인 없이 자동 진행하지 않는다.
- **관련 파일**: `extension/absence-workflow.js`, `SKILL.md`, `../admin-neis-bot/ISSUES.md`

### ISSUE-007: 결석신고 첨부 확인·다운로드 (2026-11-25)
- **상태**: 🟢 해결 (2026-11-25)
- **증상**: 결석신고 상세에 증빙 파일이 표시되지만 파일 행 선택이 반영되지 않거나, 다운로드 버튼이 “선택한 파일이 없습니다”라고 안내했다.
- **원인**: NEIS 첨부는 상세창 안의 RAONK 업로더 iframe에서 관리한다. 다른 상세창이 중복으로 열리거나 현재 상세와 다른 iframe을 고르면 화면의 체크 상태와 업로더가 인식하는 선택 파일이 달라질 수 있다.
- **해결/조치**: v1.7.2 팝업에 결석신고별 **첨부 확인 · 다운로드** 버튼을 추가했다. 버튼을 누르면 신청 ID를 목록에서 다시 하나로 확인하고 상세창을 연다. 첨부 데이터셋 행 수와 모든 RAONK 업로더의 파일 수를 비교하고, 업로더별 `getSelectedFileCount()`가 맞을 때만 내려받는다. 상세창이 이미 열렸거나 값이 다르면 중단한다. 상세창은 자동으로 닫지 않아 교사가 내용을 확인한 뒤 직접 닫는다. 파일명·내용은 로그나 확장 저장소에 넣지 않는다.
- **실측**: 9222의 로그인된 NEIS 탭에서 첨부 1개를 선택하고 NEIS의 단일 파일 다운로드를 실행했다. Chrome 다운로드 이벤트가 발생했고 JPEG 파일이 저장되어 이미지로 열리는 것을 확인했다. 파일 내용은 저장소에 기록하지 않았다.
- **관련 파일**: `extension/popup.js`, `extension/popup.css`, `extension/manifest.json`, `SKILL.md`
