# 자동 주차 동기화

## 동작 흐름

1. 사용자가 `주간학습안내작성`에서 정상적으로 주간 조회를 합니다.
2. `neis-reader.js`가 `/els_edc_tm06_003.do` 조회 완료를 감지하고 `dsWikLrn`에서 현재 주 자료를 읽습니다.
3. `dsWeekList`의 주차를 확장 서비스 워커에 전달해 최근 12시간 안에 가져온 주를 확인합니다.
4. 아직 저장되지 않았거나 12시간이 지난 주차마다 `cmbWeek`, `dmSearch`, `subSelectWikInfo.send()`를 이용해 같은 NEIS 화면에서 읽기 조회를 순차 실행합니다.
5. 각 주 결과를 필요한 수업 필드만 남겨 `chrome.storage.local`과 로컬 뷰어에 저장하고, 끝나면 원래 보고 있던 주를 다시 조회합니다.

사용자가 매 주마다 조회 버튼을 누르거나 확장 팝업을 실행할 필요는 없습니다. 이후 NEIS에서 정상 조회하면 현재 주는 즉시 다시 저장하고, `dsWeekList`의 다른 주는 12시간 캐시 만료 후 다시 동기화합니다. 주차별 결과를 저장하므로 도중에 실패해도 다음 정상 조회 때 아직 가져오지 못한 주부터 다시 시도합니다. `dsWeekList`는 당시 NEIS 화면이 제공한 기간만 포함하므로 목록 밖의 과거 기간은 해당 기간이 포함되도록 화면 조건을 먼저 바꿔야 합니다.

## 안전 조건과 한계

- `dsWikLrn.isModified()`가 참이거나 수정 상태를 확인할 수 없으면 주차 조회를 시작하거나 계속하지 않습니다.
- 조회 중 화면에서 주차 선택이 바뀌면 중단하고, 사용자 선택으로 보이는 화면 상태는 덮어쓰지 않습니다.
- 자동 조회는 `dsWeekList`가 제공하는 목록을 대상으로 하며 한 번에 40주까지 처리합니다. 40주 초과는 팝업의 선택한 달 가져오기를 사용합니다.
- 내부 요청은 Cpr 앱의 기존 제출 객체로 보냅니다. 쿠키, 인증 토큰, `_AUTHDATA`, 원본 요청 본문은 읽거나 저장하지 않습니다.
- 주차 조회는 읽기만 수행합니다. NEIS의 저장, 수정, 결재 제출은 호출하지 않습니다.
- 캐시는 Chrome 프로필의 `storage.local`에 저장됩니다. 로컬 뷰어 서버는 실행 중인 동안 메모리에 레코드를 보관합니다.

## 문제 해결

- **첫 조회 뒤 진행이 시작되지 않음**: 확장 관리 화면에서 확장 프로그램을 새로고침한 뒤 NEIS 탭도 새로고침하고, `주간학습안내작성` 화면에서 다시 조회합니다.
- **현재 주만 보이고 나머지 주가 비어 있음**: 플로팅 패널의 상태 문구를 확인합니다. 미저장 수정, 조회 구조를 찾지 못함, 40주 초과는 자동 조회를 중단하는 사유입니다. 필요하면 팝업에서 선택한 달 가져오기를 실행합니다.
- **뷰어에 저장되지만 페이지를 다시 열면 자료가 없어짐**: Chrome 확장 저장소에는 유지됩니다. 별도 뷰어는 `실행_나이스수업뷰어.bat`을 다시 실행해야 서버에서 조회할 수 있습니다.

## 구현 위치

- `extension/neis-reader.js`: 조회 감지, 주차 목록/수업 레코드 읽기, 캐시 확인, 자동 조회와 원래 주 복원
- `extension/content.js`: 페이지 위젯과 서비스 워커 메시지 중계
- `extension/background.js`: 주별 완료 시각 저장, 12시간 만료 판단, 로컬 뷰어 전송
- `extension/popup.js`: 사용자가 요청한 주/월 수동 조회
- `docs/data-contract.md`: 원본 NEIS 컬럼과 정규 레코드 매핑
