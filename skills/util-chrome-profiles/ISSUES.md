### ISSUE-004: 창에 특정 글자가 뜨면 알림 (2026-11-28)
- **상태**: 📌 백로그 — 기본은 됨(2026-11-28): 미리보기 오른쪽 클릭 → 글자 감시(쉼표로 여러 개, 20초마다, 새로 나타날 때 알림). UIA 로 본문 글이 잘 읽힘(창당 수십 ms). 남은 것: 정규식·'사라지면 알림'·설정 저장(지금은 창을 닫으면 사라짐), OCR 보조
- **하고 싶은 것**: 창(또는 고른 창들) 어딘가에 "접수 완료", "대기 0명", "오류" 같은 글자가 나타나면 트레이 알림·소리·빨간 표시. 반대로 "글자가 사라지면 알림"도.
- **방법 후보** (위가 우선):
  1. **UI 자동화(UIA)로 화면 글 읽기** — Chrome·Edge 는 접근성 트리로 웹 페이지 글을 내준다. `uiautomation`/`pywinauto` 로 창의 글을 모아 찾는다. OCR 보다 정확하고 가려진 창·작은 글씨도 되며, 원격 디버깅(CDP)이 막힌 기본 프로필에서도 된다. 먼저 이 PC 의 Chrome 창에서 UIA 로 본문 글이 나오는지, 창 20개를 몇 초 간격으로 읽을 때 부담이 얼마인지 시험.
  2. **OCR** — UIA 로 안 읽히는 곳(그림 속 글, 캔버스)용. Windows 내장 OCR(`Windows.Media.Ocr`, `winsdk` 패키지, 한국어 언어팩 필요)이 설치 없이 가볍다. 이미 찍는 캡처(`capture_bits`)를 그대로 쓴다.
- **화면 생각**: 미리보기 오른쪽 클릭 → "글자 감시…" → 찾을 글(여러 개, 정규식 선택) + 나타날 때/사라질 때 + 확인 간격. 감시 중인 창은 미리보기 글에 "글자 감시: 접수 완료" 표시. 설정은 앱 ID(프로필) 기준으로 저장해 창을 다시 열어도 이어지게.
- **주의**: 찾은 글을 로그·파일로 남기지 않는다(학생 정보가 화면에 있을 수 있음). 알림에는 찾은 낱말만 보인다.

### ISSUE-003: 특정 이미지와 비슷한 화면이 뜨면 알림 (2026-11-28)
- **상태**: 📌 백로그
- **하고 싶은 것**: "이 버튼/이 팝업/이 화면이 뜨면 알려 줘". 예: 대기열 끝난 화면, 로그인 만료 창, 특정 아이콘.
- **방법 후보**:
  1. **본보기 이미지 고르기**: 미리보기 오른쪽 클릭 → "이 부분을 본보기로" → 창 큰 캡처 위에서 마우스로 네모를 그려 잘라 `data_dir()/templates/` 에 저장(파일로 가져오기도). 
  2. **찾기**: OpenCV `matchTemplate`(정규화 상관) 으로 창 캡처 안에서 찾고, 점수가 기준(기본 0.85, 조절 가능)을 넘으면 알림. 창 크기·배율이 달라질 수 있으니 몇 가지 배율로 찾는다. 위치를 아는 경우는 그 영역만 비교해 가볍게.
  3. **화면 전체가 비슷한지**: 지금 쓰는 32×32 흑백 서명을 본보기와 비교하는 간단한 방식도 둔다("이 화면과 거의 같아지면").
- **부담**: 캡처는 이미 1초마다 돌아가며 찍으니 그 그림을 다시 쓴다. 감시 켠 창만 원본 크기로 찍고, OpenCV(`opencv-python-headless`) 는 이 기능을 켤 때만 불러온다.
- **함께 할 것**: 알림을 한곳에 모으기 — 변화 없음·타이머·글자·이미지 알림을 같은 방식(트레이, 소리, 빨간 표시, 선택적으로 카톡/디스코드 메모 스킬로 보내기)으로.

### ISSUE-008: 다른 PC 에서 같은 설정 쓰기 — 계정 기준 저장 (2026-11-28)
- **증상**: 설정(그룹·시작 URL·작업 시간·다시 쓸 시각)이 'Profile 4' 같은 폴더 이름으로 저장돼, PC 가 바뀌면 다른 계정에 붙거나(설정 파일을 함께 쓸 때) 한쪽 저장이 다른 PC 프로필을 지웠다.
- **해결**: 프로필마다 저장용 이름 `sid` = `acct:이메일`(Edge `edge:acct:이메일`, 로그인 안 했으면 폴더 키). 화면 안에서는 여전히 폴더 키를 쓰고, 읽을 때 `cfg_from_file`·쓸 때 `cfg_to_file` 에서만 바꾼다. 이 PC 에 없는 계정 설정은 `self.foreign` 에 두었다 그대로 다시 적는다(그룹 이름 바꾸기·삭제도 따라감). 예전 폴더 이름 설정은 처음 켤 때 자동으로 옮김(`id_version: 2`). `pauses.json`·`pause_done` 도 sid.
- **시험**: 설정 사본으로 옮기기 → 다시 켜도 트리 같음, 다른 PC 계정 끼워 넣기 → 화면엔 안 보이고 저장 때 남음·이름 바꾸기/삭제 따라감, Profile 4↔5 폴더를 바꾼 '다른 PC' 흉내에서도 그룹이 계정을 따라감.
- **남은 것**: 로그인 안 한 프로필(예: Edge 애플 학생·네이버 공문서)은 PC 가 다르면 맞지 않을 수 있음.
- **관련 파일**: `chrome_profiles.py` (`load_profiles` sid, `Manager.sid/local_key/cfg_from_file/cfg_to_file`)

### ISSUE-000: 창 ↔ 프로필 짝짓기 방식 (2026-11-27)
- **증상**: 처음 설계(다른 AI 답변)는 "실행 직후 새로 생긴 창 = 이 프로필"로 짝지어, 매니저를 다시 켜면 열린 창을 못 잡고 동시에 창을 열면 짝이 틀릴 수 있었다.
- **원인**: 같은 User Data 의 프로필은 한 chrome.exe 프로세스를 함께 써서 프로세스로는 구분이 안 된다.
- **해결**: Chrome 이 창마다 붙이는 AppUserModelID(`SHGetPropertyStoreForWindow` → `PKEY_AppUserModel_ID`)로 짝짓는다. 기본 프로필 `Chrome`, 나머지 `Chrome.UserData.<폴더명에서 영문·숫자·점만>`.
- **관련 파일**: `chrome_profiles.py` (`aumid_table`, `window_aumid`)
