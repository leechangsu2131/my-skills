### ISSUE-007: Discord 전송이 실패해도 "완료"라고 하고 종료 코드 0 이다 (2026-11-25)
- **상태**: 📌 백로그 (확인 필요 — 의도인지 모름)
- **증상**: `send_chapter` 는 덩어리 전송이 실패해도 `❌` 만 찍고 끝까지 간 뒤 "Discord 전송 완료!" 를 출력한다. `send_to_discord` 의 반환값(True/False)을 쓰지 않아서 `03_send_discord.py` 는 늘 종료 코드 0 → `run_daily.py` 도 "🎉 완료" 로 끝난다. HTTP 429(너무 자주 보냄)도 다시 시도하지 않는다.
- **원인**: 실패 횟수를 세거나 종료 코드로 알리는 부분이 없다.
- **해결/조치**: (미적용) 실패가 하나라도 있으면 종료 코드 1, 429 는 `Retry-After` 만큼 기다렸다 한 번 더. 현재 동작은 시험(`test_send_chapter_일부_전송이_실패해도_나머지를_계속_보낸다`)에 적혀 있다.
- **관련 파일**: `scripts/03_send_discord.py`, `scripts/run_daily.py`

### ISSUE-006: 책 본문 일부가 저장소에 올라가 있다 — 교사 결정 필요 (2026-11-25)
- **상태**: 📌 백로그 (**교사 결정 필요**, 저작물)
- **증상**: `scripts/output/chapter_01.txt`(약 4KB)에 출판된 책의 본문(머리말)이 들어 있고, 공개 저장소에 추적되고 있다. `scripts/toc.json`(챕터 149개 목차)도 특정 책의 목차로 보인다.
- **원인**: `.gitignore` 가 `skills/output/` 만 막고 `scripts/output/` 은 막지 않는다. 작업자 안내(WORKER_GUIDE)는 지도서·교과서 같은 저작물을 저장소에 올리지 않게 한다.
- **해결/조치**: (미적용 — 교사 결정 전에는 지우지 않음) 추적에서 빼기(`git rm --cached`), `.gitignore` 에 `scripts/output/` 추가, 결과물은 `data_dir()` 로 옮기기. 이미 올라간 기록(히스토리)까지 지울지도 결정 필요. T24(결과물이 추적되면 경고)와 함께 보면 좋다.
- **관련 파일**: `scripts/output/chapter_01.txt`, `scripts/toc.json`, `/.gitignore`

### ISSUE-005: Gems 로 보내는 글이 챕터 앞 8000자뿐이다 (2026-11-25)
- **상태**: 📌 백로그 (확인 필요 — 의도인지 모름)
- **증상**: `02_gems_translate.js` 가 `chapterText.slice(0, 8000)` 만 입력창에 넣는다("Gems 입력 한도 고려"). 챕터가 8000자보다 길면 나머지는 번역되지 않는데 경고도 없다.
- **원인**: 긴 챕터를 나눠 보내는 부분이 없다.
- **해결/조치**: (미적용) 8000자를 넘으면 경고를 내거나, 문단 단위로 나눠 여러 번 보내고 이어 붙이기. 이 일(T08)은 Python 쪽만 시험했고 JS 는 시험하지 않았다.
- **관련 파일**: `scripts/02_gems_translate.js`

### ISSUE-004: 목차 보기에서 끝쪽이 비어 있으면 `?` 가 아니라 `None` 으로 보인다 (2026-11-25)
- **상태**: 📌 백로그 (겉모양만의 문제)
- **증상**: `show_toc()` 가 `ch.get("end_page", "?")` 를 쓰는데, 수동 입력에서 끝쪽을 비우면 `end_page: null` 로 저장되어 `?` 대신 `None` 이 찍힌다.
- **원인**: `get` 의 기본값은 키가 아예 없을 때만 쓰인다.
- **해결/조치**: (미적용) `ch.get("end_page") or "?"`. 시험은 xfail.
- **관련 파일**: `scripts/01_setup_toc.py`(`show_toc`)

### ISSUE-003: 한도보다 긴 한 줄은 나뉘지 않아 Discord 가 거절한다 (2026-11-25)
- **상태**: 📌 백로그
- **증상**: `split_message` 는 줄바꿈(`\n`) 기준으로만 나눈다. 한 문단이 줄바꿈 없이 1900자를 넘으면 그 줄이 통째로 한 메시지가 되어 Discord 한도(2000자)를 넘기면 HTTP 400 으로 전송이 실패한다.
- **원인**: 줄 하나가 `max_len` 보다 긴 경우의 처리가 없다.
- **해결/조치**: (미적용) 긴 줄은 문장 끝(`. `·`다. `)이나 글자 수로 다시 자르기. 시험은 xfail.
- **관련 파일**: `scripts/03_send_discord.py`(`split_message`)

### ISSUE-002: 수동 목차 입력(`--manual`)에서 새로 입력한 챕터가 저장되지 않는 경우가 있다 (2026-11-25)
- **상태**: 📌 백로그 (입력이 사라지므로 우선순위 높음)
- **증상**: ① 기존 목차가 있을 때 "이어서 추가하겠습니까?" 에 `y` 를 하고 챕터를 입력해도 "변경사항이 없습니다" 로 끝나 저장되지 않는다. ② `n`(처음부터 다시)을 고르고 입력한 챕터 수가 기존 챕터 수 이하여도 같은 결과로 사라진다. (기존보다 많이 입력하면 저장됨.)
- **원인**: 저장 조건이 `len(chapters) > len(existing)` 인데, `y` 일 때 `chapters = existing` 이라 같은 리스트라서 새 챕터를 넣으면 두 길이가 함께 늘어 늘 같다. `n` 일 때는 비교 대상이 "처음부터 다시"와 맞지 않는다.
- **해결/조치**: (미적용) 입력 시작 전에 `existing_count = len(existing)` 를 따로 저장하고(또는 `chapters = list(existing)`), "새로 입력한 챕터가 1개 이상인가" 로 판단. 시험 2개는 xfail.
- **관련 파일**: `scripts/01_setup_toc.py`(`manual_mode`)

### ISSUE-001: 자동 감지(`--auto`)에서 범위 밖 번호만 고르면 기존 toc.json 이 빈 목록으로 덮인다 (2026-11-25)
- **상태**: 📌 백로그
- **증상**: 후보가 3개인데 `9` 처럼 없는 번호만 입력하면 `selected` 가 비어 `save_toc([])` 가 불려 기존 `toc.json` 이 `[]` 로 덮인다.

- **해결/조치**: (미적용) `selected` 가 비면 "선택된 항목이 없습니다" 를 알리고 저장하지 않기. 시험은 xfail.
- **관련 파일**: `scripts/01_setup_toc.py`(`auto_mode`)
