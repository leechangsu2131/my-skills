## 🟢 해결됨

### ISSUE-001: ODT 의 제목(text:h) 글자가 인덱싱에서 빠짐 (2026-11-26, 같은 날 해결)
- **상태**: 🟢 해결됨 (T69)
- **증상**: 제목 서식(`text:h`)으로 쓴 글이 검색 대상에 들어가지 않았다(문단 `text:p`·표만 읽음). 실제 odfpy 로 제목+본문 ODT 를 만들어 재현: 읽힌 글은 `['본문']` 뿐
- **원인**: `parse_odt_elements` 의 `walk` 가 `p`·`table` 만 글로 뽑고 `h` 는 자식으로 내려가기만 했다.
- **해결**: `walk` 가 `text:h` 도 `text:p` 처럼 `paragraph` 요소로 뽑는다(빈 제목은 뺌, 문서 안 순서 유지). 시험의 xfail 표시를 지우고 제목·본문 순서·빈 제목 시험 추가. 변이 확인 통과
- **남은 것**: 실제 공문 ODT 가 제목 서식을 쓰는지는 확인 필요(교사 PC). 이미 인덱싱한 문서는 다시 인덱싱해야 제목이 들어감
- **관련 파일**: `projects/school-agent/skills/doc-indexer/scripts/indexer.py`, `…/tests/test_doc_indexer.py`

### ISSUE-003: 연도·부서를 못 찾으면 프롬프트에 'None' 글자가 들어감 (2026-11-26, 같은 날 해결)
- **상태**: 🟢 해결됨 (T69, 프롬프트 쪽만)
- **증상**: 인덱서가 연도·부서를 못 찾으면 `None` 으로 저장하고, `ask.py` 는 `meta.get('year', '')` 라서 값이 `None` 이면 `(연도: None, 부서: None)` 이 프롬프트에 그대로 들어갔다.
- **해결**: `ask.py` 가 `meta.get('year') or ''`·`meta.get('dept') or ''` 로 읽는다. xfail 표시를 지우고 연도만 있고 부서가 없는 경우 시험 추가. 변이 확인 통과
- **남은 것(확인 필요)**: 실제 ChromaDB 가 `None` 메타데이터를 받는지는 교사 PC 에서 확인 — 받지 않으면 인덱싱 자체가 실패하므로 그때는 인덱서가 값을 빈 글(`''`)로 저장하게 바꿔야 함(이 PC 에는 chromadb 가 없어 못 확인)
- **관련 파일**: `…/scripts/ask.py`, `…/scripts/indexer.py` `index_file`

### ISSUE-004(연도 부분): 연도를 긴 숫자 안에서 읽음 (2026-11-26, 같은 날 해결)
- **상태**: 🟢 해결됨 (T69) — 부서 부분은 위 📌 ISSUE-004
- **증상**: 경로 어디서든 `20` 으로 시작하는 숫자 4개를 연도로 읽었다(`교무-12023456.pdf` → 2023, 저장 폴더 이름의 숫자도 해당).
- **해결**: `extract_year_from_path` 가 경로를 숫자 덩어리로 나눠, 4자리 `20xx` 이거나 날짜로 시작하는 6·8·12·14자리(`202503`·`20250304`…, 달 1~12·일 1~31 검사)일 때만 연도로 인정하고 앞에서부터 처음 나오는 것을 쓴다. 이미 쓰이고 있을 `20250304_공문.pdf` 같은 날짜 붙임 파일 이름은 그대로 2025 로 읽힌다. xfail 표시를 지우고 사례 시험 14개 추가. 연도 쪽 변이 5가지(달·일·20 시작·길이 검사 빼기, 옛 방식으로 되돌리기)를 모두 시험이 잡음
- **남은 것**: 이미 인덱싱한 문서의 연도 메타데이터는 다시 인덱싱해야 바뀜. `--year` 필터가 실제 폴더에서 얼마나 맞는지는 확인 필요(교사 PC)
- **관련 파일**: `…/scripts/indexer.py` `extract_year_from_path`, `_year_from_digit_run`
